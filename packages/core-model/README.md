# `@vpe/core-model`

**Ответственность (карта ADR-0009):** сущности ADR-0001, типы времени, лексер/линт/span-map,
ledger якорей.

**Импортирует:** `@vpe/schema`.
**НЕ импортирует:** `node:fs`/`fs`/`fs/promises` — модель не умеет читать диск (**M3**);
сеть (**M4**); `hyperframes`/`@hyperframes/*` (**M1**); `gsap` (**M6**);
`react`/`react-dom` (**M2**); `media`, `voice`, `templates-spec`, `compile`, `renderer-hyperframes`, `cli`.

---

## Модель времени: что здесь, чего здесь нет

Задача `C-01` (roadmap §4.3). Исполнимая форма правил **T1, T2, T4** ADR-0003 и типов времени
авторского слоя ADR-0001.

### Что здесь

| модуль | что даёт |
|---|---|
| `src/time/integer.ts` | `floorDiv`, `ceilDiv` (точные, знак любой), `mulExact`, `addExact`, `assertSafeInteger` |
| `src/time/rational.ts` | `Rational {num, den}` — сокращённая дробь, `den > 0` |
| `src/time/grid.ts` | `Fps {num, den}`, `TimeGrid {sampleRate, fps}`, `timeGrid()`, `assertTimeGrid()` |
| `src/time/ms.ts` | `msToSamples(ms, sampleRate)` — **единственная** функция перевода (T1) |
| `src/time/frames.ts` | `samplesPerFrame`, `frameStartSample`, `frameLengthInSamples`, `frameOfSample`, `clipDurationInFrames` (T2, T3) |
| `src/time/interval.ts` | `SampleInterval`/`FrameInterval` как `[start, end)`, `assertClipWithinSegment`, `assertT4` (T4) |
| `src/time/timepoint.ts` | `TimePoint` (три варианта), `Duration`, `assertRealizable` (ADR-0001) |
| `src/time/errors.ts` | `TimeModelError` — ошибка называет ПРАВИЛО, а не следствие |

Три вещи, которые стоит знать до чтения кода:

* **Секунд в API нет.** Ни на входе, ни на выходе, ни в имени. Миллисекунды — сахар авторского
  слоя и живут ровно в `msToSamples`; всё остальное — сэмплы и кадры, оба брендированы.
* **Умножение — вызов, а не оператор.** T2 требует проверять `Number.isSafeInteger` на каждом
  промежуточном произведении, а у оператора `*` нет места, куда встроить проверку. Поэтому
  `mulExact(a, b, 'f · sampleRate')`, и поэтому в сообщении об ошибке стоит **имя величины**.
* **Умолчаний нет.** `fps = {30, 1}` и `sampleRate = 24000` — поля `compileProfile`, то есть
  часть произведения (ADR-0003, «fps = 30 — решение, а не умолчание»). Ни одна функция их
  не подставляет: сетка передаётся целиком.

## Лексер: что есть, чего нет

Задача `C-02` (roadmap §4.3). Исполнимая форма **нормативной таблицы ADR-0002 §2** и правил
ADR-0002 §1/§5/§8. Вход — **текст**, а не путь: модель не умеет читать диск (**M3**), файл
читает вызывающий.

```ts
import { parseSource, dumpAst } from '@vpe/core-model';

const ast = parseSource(text, { file: 'source/01-intro.md', sampleRate: 24000 });
console.log(dumpAst(ast)); // канонический JSON — только для отладки
```

### Что здесь

| модуль | что даёт |
|---|---|
| `src/source/text.ts` | NFC + `\r\n`/`\r` → `\n` **первым шагом**; `SourceText`, `Span`, `строка:колонка` — всё в **code points** |
| `src/source/errors.ts` | `SourceParseError`: `location {file, line, column}`, сообщение начинается с `файл:строка:колонка` и называет ПРАВИЛО |
| `src/source/lexer.ts` | семь позиций таблицы ADR-0002 §2 и ничего больше; имена якорей проверяет `publicAnchor()` из `@vpe/schema` |
| `src/source/parse.ts` | AST: глава → сцена → абзац → чанк → токены и маркеры; правила МЕСТА (`[img:]`, `[pause:]`, заголовки) |
| `src/source/spanmap.ts` | `spokenToSource` / `sourceToSpoken` / `runAtSpoken` — прямое и обратное направление карты |
| `src/source/dump.ts` | `dumpAst` через `canonicalJson`; AST **не персистируется** (ADR-0002 §5) |

Четыре вещи, которые стоит знать до чтения кода:

* **Список маркеров закрыт.** `[beat: name]`, `[pause: Nms]`, `[say: display | spoken]`,
  `[img: alias]`, `[emph]`, `# chapter: id`, `## scene: id` — и всё. Неизвестный `[...]` и `#`
  в середине строки — **ошибка**, а не пропуск: расширение списка требует нового ADR
  (ADR-0002 §1), и лексер не имеет права решить это за него.
* **`[pause:]` живёт в трёх положениях.** На границе абзаца — узел `silence` (тишина, разреза
  нет, денег не стоит). Внутри абзаца на границе предложения — узел `chunk-break` (режет чанк
  и несёт ту же тишину; это единственное платное положение, ADR-0002 §2 + ADR-0010 §3).
  Внутри абзаца не на границе предложения — **ошибка компиляции с местом**.
* **Пробельные схлопываются.** Ряд пробелов/табов/мягких переносов внутри абзаца даёт один
  `U+0020`, span — на первый символ ряда (решение владельца `C-02`, пометка у **D8**). Поэтому
  снятый `[beat:]` или `[emph]` не меняет **ни одного байта** spoken-текста, то есть не меняет
  `voiceKey` — как и обещает колонка «Текст идёт в TTS: нет».
* **Токен — это токен ИСХОДНИКА** (ADR-0004 §5), а не слово нормализованного текста:
  максимальный ряд непробельных символов, а `[say: d | s]` — **один** токен целиком.
  Следствие, видное в фикстуре: `[say: “waiting” | waiting].` даёт отдельный токен `.`.

### Чего здесь нет — и где это будет

| чего нет | почему | где |
|---|---|---|
| ~~**ledger якорей**, минт `w:` и `b:img-<alias>-<n>`, `boundTo`, word-diff~~ — **сделано в `C-04`**, раздел ниже | ADR-0002 §4: разворот `[img:]` — работа **компилятора**; минт — CSPRNG, а не разбор | `C-04` — сделано |
| ~~**ordinal у `[img:]`**~~ — **решено в `C-04`**: счёт по alias, область — файл, 1-based | ADR-0004 §2a не различал «n-й `[img:]` в сцене» и «n-й с этим alias». Уточнение к записи `C-02`: фикстура «что считается» РАЗЛИЧАЕТ (в сцене `turn` две картинки), не различала она только область | `C-04` — решение владельца |
| **Timeline, дефолтные gap'ы T8** (`defaultParagraphGapSamples` и соседи) | восьмая строка таблицы: тишина без маркера берётся из `compileProfile`, а не из исходника | `C-05` |
| **деление слишком длинного абзаца** на части (`splitIndex` от длины) | ADR-0010 §3: структурное деление — часть плана речи | `V-03` |
| **`chunkKey` / `voiceKey`** | здесь нет ни провайдера, ни голоса, ни `roleDigest`; из формулы ADR-0010 §3a лексеру принадлежит только `spokenChunkText` | `V-03` |
| **scope у `[emph]`** | дрейф roadmap §11.2 строка 16 — правка **нормативной** таблицы, решение владельца | `CP-05` |

## Линт и трансдьюсер: что есть, чего нет

Задача `C-03` (roadmap §4.3). Исполнимая форма **ADR-0002 §3** («линт вместо нормализатора») и
**ADR-0010 §10** (трансдьюсер, три property-свойства, таблица ловушек F1–F16). Обе стадии —
**над AST**, парсер их не зовёт: парсер принимает текст, линт отвергает.

```ts
import { parseSource, lintProse, assertProse, transduceDocument, reconstructDisplay } from '@vpe/core-model';

const ast = parseSource(text, { file: 'source/01-intro.md', sampleRate: 24000 });
assertProse(ast);                       // бросит SourceParseError с `файл:строка:колонка`
for (const chunk of transduceDocument(ast)) {
  chunk.spoken;                         // уйдёт провайдеру
  chunk.display;                        // уйдёт в субтитр
  reconstructDisplay(chunk.spoken, chunk.runs) === chunk.display;  // побайтово
}
```

### Что здесь

| модуль | что даёт |
|---|---|
| `src/source/lint.ts` | десять запретов ADR-0002 §3 (`digit`, `percent`, `dollar`, `numero`, `roman`, `abbreviation`, `url`, `bold`, `list`, `inline-code`); `lintProse` — **все** находки файла, `assertProse` — отказ первой; `lintShare` — доля токенов под `[say:]` |
| `src/source/transduce.ts` | `transduceChunk`/`transduceDocument` — `spoken` + `display` + карта; `reconstructDisplay` (round-trip); `spokenOrigin` (тотальность); `runAtSpokenIndex` |
| `src/source/ast.ts` | `chunksIn`/`tokensIn` — обход дерева в порядке исходника, один на обе стадии |
| `tests/fixtures/v13-content-language.test.ts` | **V13** — корневой охранник: кириллицы нет ни в прозе фикстур, ни в `title`/`descriptionTemplate` |

Четыре вещи, которые стоит знать до чтения кода:

* **Область запрета получается из структуры, а не из списка исключений.** Линт смотрит только
  на токены `origin: 'prose'`. Внутри `[say: d | s]` в `d` может стоять что угодно, а `s` —
  это и есть «словами»; имена якорей стережёт `publicAnchor()` из `@vpe/schema`. Поэтому URL
  остаётся законным в `publish.yaml` (`sources[]`, вход PG-A1) и в `direction/*.yaml` (C7) без
  единой оговорки в коде.
* **Линт возвращает СПИСОК, парсер бросает на первой ошибке.** Осознанное расхождение (`C-02`,
  огр. 2): у линта нарушений в одном файле бывает много, и «покажи все» — единственная полезная
  форма. Одна находка на пару (токен, код), в позиции **первого** нарушающего символа.
* **Карта со вставками, а не только с удалениями.** Три вида прогона: `copy` (тождество),
  `space` (схлопнутый ряд пробельных, длина 1) и `say` — единственный, у которого длины
  spoken- и display-сторон **не равны**. Без третьего вида субтитр `twenty-three percent`
  вместо `23%` неизбежен (ADR-0010 §10).
* **Индексация — только code points, во всём модуле.** Ни `str[i]`, ни `.length` по строке:
  `[...text]` и `pointLength`. `FACT` (SP-2): длина `alignment.characters` совпала с числом
  code points на 28/28 строк двух голосов; реализация в UTF-16 units разъедется с `alignment`
  на первом эмодзи, и разъедется **молча**. `Intl.Segmenter` не используется — он дал бы
  графемы, то есть **неверную** единицу, и запрещён Charter V8.

### Три правила, выбранные решением владельца (а не выведенные)

* **Римские цифры** — отдельное слово из **≥ 2** символов, все из `IVXLCDM`, все в верхнем
  регистре. `I` пропускается по длине (местоимение частотнее любого римского числа); одиночные
  `V`/`X`/`C` — тоже. Капсовые аббревиатуры из тех же букв (`DVD`, `MIX`) краснеют — принятая цена.
* **Сокращения с точкой** — закрытый список из восьми слов: `Dr.`, `St.`, `Mr.`, `Mrs.`, `Ms.`,
  `Prof.`, `e.g.`, `i.e.` Обещание ADR-0002 §3 «точка больше не встречается в сокращениях» верно
  ровно на длину этого списка (`docs/DEBTS.md` №14).
* **Запретов десять**, а не девять: ADR-0002 §3 и roadmap §4.3 перечисляют десять позиций.

### Чего здесь нет — и где это будет

| чего нет | почему | где |
|---|---|---|
| **обратное направление карты** (display-текст → исходник) | у прогона есть `displaySource`, но потребителя ещё нет: субтитры собирает не эта стадия | `CP-*` (AC5), `docs/DEBTS.md` №17 |
| **токенизация под `w:`** провайдера | единица провайдера (ADR-0010 §6) — не токен исходника; минт якорей — уже здесь (`C-04`), а привязка ко ВРЕМЕНИ появится с дублем | `V-0x` |
| **`apply_text_normalization`** и всё про провайдера | здесь нет ни провайдера, ни ключа, ни сети | `V-01` |
| **порог доли токенов под линтом** | `lintShare` МЕРИТ, но не судит: порог (~2 %) живёт в Charter V5 и roadmap §7.3 №7 | пересмотр — решение владельца |
| **URL без схемы** (`example.org`) | «точка между буквами» неотличима от сокращения; эвристику запрещает Charter §7 | `docs/DEBTS.md` №16 |

## Ledger якорей: что есть, чего нет

Задача `C-04` (roadmap §4.3). Исполнимая форма **ADR-0004 §1/§2a/§4/§6** и **ADR-0002 §4**.
Вход — разобранный AST и **текст** прежнего ledger'а: модель не умеет читать диск (**M3**),
файл читает вызывающий.

```ts
import { parseSource, syncLedger, parseLedger, renderLedger, expandImg, boundToOf } from '@vpe/core-model';

const ast = parseSource(text, { file: 'source/01-intro.md', sampleRate: 24000 });
const before = parseLedger(ledgerText);          // строка = запись, шапка первой строкой
const { text: after, minted, died, bindings } = syncLedger(ast, before);
// after — канонический файл целиком; записать его обязан вызывающий
expandImg(ast);                                   // порождённые direction-записи (ЗНАЧЕНИЯ, не файл)
```

### Что здесь

| модуль | что даёт |
|---|---|
| `src/anchors/mint.ts` | `mintAnchorId(random?)` — `w:<base32(csprng(128 бит))[:16]>`; порт `RandomBytes`; **единственный** импорт `node:crypto` в пакете |
| `src/anchors/ledger.ts` | `parseLedger`/`renderLedger`, `liveAnchors`/`latestById` (свёртка), `assertUniqueLive` (**A3**), `assertAddOnly` (**A8**), `nextRev` |
| `src/anchors/boundto.ts` | `boundTo` от **канонического JSON** четырёх величин, `boundToOf`, `assertBoundTo` — отказ, а не WARN (**§6**) |
| `src/anchors/diff.ts` | `diffTokens` — LCS по поверхностным формам, с отрезанием общих концов и жёстким пределом матрицы |
| `src/anchors/slots.ts` | `anchorSlots` — что вообще попадает в ledger и в каком порядке; `implicitBitId` |
| `src/anchors/img.ts` | `expandImg` — форма порождённой direction-записи (ADR-0002 §4), `at`/`until` типа `PublicAnchorId` |
| `src/anchors/sync.ts` | `syncLedger` — дифф, наследование id, минт нового, пометка `dead`, канонический текст |
| `src/anchors/errors.ts` | `AnchorLedgerError`: правило (`A3`, `A8`, `ADR-0004 §6`, …) и номер строки файла |

Пять вещей, которые стоит знать до чтения кода:

* **Минт случаен, а `parse` детерминирован — и это не противоречие.** Минт зовётся ТОЛЬКО для
  якорей, которых нет в ledger'е; результат немедленно фиксируется. Прогон на неизменном тексте
  не дописывает ни строки, поэтому файл совпадает побайтово. Детерминированный минт от
  `ledgerRev` отвергнут ревизией M3: две ветки от одной ревизии выдали бы одинаковые id разным
  словам, и merge (объединение множеств строк) свёл бы их молча.
* **Запись описывает якорь на момент своей ревизии; текущее состояние — последняя запись id.**
  Единственная форма, при которой add-only и word-diff совместимы: диффу нужен упорядоченный
  список токенов прошлого разбора, а под add-only порядок нельзя ни переписать, ни вывести из
  порядка строк. Поэтому у якоря, сдвинувшегося в тексте, появляется НОВАЯ строка, а старая не
  трогается. Цена — рост файла; она записана в `docs/DEBTS.md` №24.
* **«Живой» — это свёртка, а не фильтр по строкам.** Строка со `status: 'live'` остаётся в файле
  навсегда; живым считается id, у которого ПОСЛЕДНЯЯ запись `live`.
* **`boundTo` — функция, а не поле.** В схеме `anchors/1` его нет; ADR-0004 §7 перечисляет его
  среди полей записи OVERRIDE. Здесь — вычисление и сверка; хранение — `O-01`.
* **A1 держится типом.** `at`/`until` порождённой записи объявлены `PublicAnchorId`, а его
  конструктор отвергает `w:`. Ссылку на `w:` в direction-записи нельзя построить — это ловит
  компилятор, а не только тест.

### Ordinal у `[img:]` — решение владельца (`C-04`)

`b:img-<alias>-<n>`, где `n` — номер этого `[img:]` **среди `[img:]` с этим же alias**, счёт
**по файлу**, 1-based. Обе «сценные» трактовки дают одну и ту же строку для одного alias в двух
сценах, то есть ломают **A3** на законном «одно фото в двух сценах»; счёт по всем `[img:]`
вдобавок переименовывает чужие биты при вставке картинки выше. Буква ADR («`ordinalВСцене`»)
правится владельцем — `docs/DEBTS.md` №18.

### Чего здесь нет — и где это будет

| чего нет | почему | где |
|---|---|---|
| **overrides**: `override/1`, `vpe nudge`/`inspect`/`override rm`, хранение `boundTo`, статус `applied` | ADR-0004 §7–§8 описывает журнал, писателем которого является CLI; здесь нет ни CLI, ни первого override | `O-01` |
| **ненулевой exit code** и `vpe fmt --check`/`vpe check` | это поведение процесса, а не модели: модель бросает `AnchorLedgerError` | `L-03` |
| **`recordId` порождённой `[img:]`-записи** | ADR-0002 §4 его не называет, `direction/1` требует, случайный сломал бы D1/AC4 — правило вывода не изобретается (Charter §7) | `C-05`, `docs/DEBTS.md` №21 |
| **`ch:` в ledger** | `anchors/1` требует непустой `sceneId`, а у главы сцены нет; врать в машинном файле нельзя | `O-01`/`L-03`, `docs/DEBTS.md` №22 |
| **удаление мёртвых записей** («хранятся N ревизий») | `N` в ADR не задано, а удаление противоречит add-only | владелец, `docs/DEBTS.md` №23 |
| **измерение частоты ТИХОГО перенацеливания (A9)** | это спайк с корпусом правок, а не тест | **SP-4** (`X-01`) |
| **время якоря** (сэмпл, `TokenBinding`) | ledger даёт имена и порядок; время появляется после приёмки дубля | `V-0x` |
