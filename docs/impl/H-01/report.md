# `H-01` — адаптер-подпроцесс рендерера HyperFrames

**Дата:** 2026-08-28. **Оценка:** 2. **Вход:** `CP-04`, `TS-01`, `M-01` + фактически `CP-07`
(IR несёт `assets`/`fonts` по sha — кандидат в правку roadmap, см. §10).
**Выход:** пакет `renderer-hyperframes` — первый код; аддитивная функция в `media`.

---

## 1. Что сделано — одним абзацем

Адаптер границы рендерера: `renderSegment(request, options)` проверяет запрос по формам
ADR-0008 **без единого изменения поля**, материализует каталог композиции в `tmpDir` строго из
полей `assets`/`fonts` этого же запроса, считает `compositionHash` по готовому каталогу и
сверяет его с `bundle.hash`, запускает HyperFrames с `--format png-sequence` и возвращает
**кадры**; `SegmentArtifact` собирает `media` новой функцией `buildSegmentArtifact`. Точка
входа подпроцесса `bin/render-segment.ts` — stdin JSON → stdout JSON → код выхода. Один
синтетический шаблон `solid@1` живёт **только в тестах** и доказывает сквозной путь.

**Числа:** 78 тестов в пакете (5 файлов без браузера, 2 с браузером) + 9 в двух новых линтах;
полный прогон репозитория — **121 файл, 1986 тестов, зелено**.

## 5. Три находки окружения, каждая стоила прогона

**(1) `pnpm add` оставил дерево частично материализованным.** Первый `hyperframes browser
ensure` упал `ERR_MODULE_NOT_FOUND: tslib` — `@swc/helpers@0.5.23` объявляет `tslib: ^2.8.0`,
лок его знает, а линка в `.pnpm` не было. Лечится `pnpm install --force` (37 с). Свойство
pnpm 11.9.0, не пакета; записано, чтобы следующая сессия не искала это в коде.

**(2) `HYPERFRAMES_FFMPEG_PATH` — путь, а не имя.** CLI проверяет обе `*_PATH` как **путь к
существующему файлу** и на `"ffmpeg"` падает *до* браузера («Configured path does not exist»).
Поэтому в `run.ts` появился `resolveOnPath` — обход `PATH` руками (не `which`: внешняя команда
— ещё один подпроцесс со своим поведением). `media` зовёт ffmpeg просто по имени и потому с
этим не сталкивался.

**(3) ГЛАВНАЯ — компилятор HyperFrames читает композицию СТАТИЧЕСКИ.** Первая версия runtime
выставляла `data-composition-id`/`data-width`/`data-height`/`data-duration` скриптом и
регистрировала таймлайн из отдельного `<script src="./runtime.js">`. Рендер при этом **не
падал**: за 13 минут дал 0–2 PNG из 30. Причина видна только без `--quiet`:

```
✗ root_missing_composition_id [root]: Root composition is missing `data-composition-id`.
✗ root_missing_dimensions [root]: Root composition is missing `data-width` or `data-height`.
✗ missing_timeline_registry: Missing `window.__timelines` registration.
  Continuing render despite lint issues. Use --strict to block errors.
[INFO] Compiled composition metadata {"staticDuration":0,"width":1080,"height":1920}
[INFO] Launching browser for composition probe... {"reasons":["root duration unknown"]}
```

То есть компилятор не нашёл в **разметке** ни id, ни геометрии, ни длительности, ни
регистрации таймлайна, **предупредил и пошёл дальше** — калибровать длительность браузером,
в `forceScreenshot`. Правка: `data-*` пишет материализация прямо в `index.html`, а runtime
**встраивается** в страницу (отдельный `<script src>` компилятор не разворачивает). После
правки те же 30 кадров рендерятся за ~4–5 с.

**Два следствия, оба важнее самой правки.** Первое: перевод `кадр n → t = n/fps` теперь
существует **по обе стороны границы** — на Node при материализации (`durationSeconds`) и в
браузере (`toSeconds`); runtime их **сверяет** и падает при расхождении, чтобы две геометрии
времени не разошлись молча. Второе: `--strict` у рендерера существует и превращает эти
предупреждения в отказ — кандидат в `H-05`/`H-04`, здесь не включён (менять поведение рендерера
на этапе, где ещё нет ни одного настоящего шаблона, значило бы получить красный гейт на пустом
месте). Записано долгом №157.

## 8. Инварианты: что переведено и с какими оговорками

Roadmap обещал этой задаче **R2, R3, R4**.

* **R4 — `named → guarded`, целиком.** Строка требовала «проверки КОНКРЕТНОГО типа
  `SegmentRenderRequest`, а его не существует до `H-01`». Тип теперь существует
  (`src/contract.ts`), и охранник стоит на нём: `canonicalJson(request)` → `JSON.parse` →
  `canonicalJson` даёт **тот же текст**, а разобранный обратно объект **проходит валидатор**;
  `Map`, `Set`, `bigint` в запросе отвергаются **с путём к месту**.
* **R3 — `named → guarded` с двумя оговорками.** Исполнено: `ir.assets`/`ir.fonts` ⊆
  `request.*` по sha (отказ на **значениях**, до диска); sha **каждого** файла запроса
  сверяется с байтами; перехват `fs` в процессе адаптера даёт список ⊆ белого; каталог
  композиции наполняется только из запроса (лишний файл рядом в него не попадает).
  **Оговорка 1:** белый список включает собственный код рендерера (`node_modules/gsap`,
  `src/composition/runtime.js`) — правило говорит про файлы **вне `assets`/`fonts` запроса**,
  то есть про входы сегмента; собственный код входом сегмента не является. **Оговорка 2:**
  перехват видит только процесс адаптера; открытия процесса рендерера ограничены тем, что
  `file_server` раздаёт каталог композиции, — механически это закроет `H-05`.
* **R2 — `named → guarded` с оговоркой.** Каталог вокруг `tmpDir`/`outputPath` — `chmod 0555`,
  адаптер проходит; негативный контроль: запись мимо в тот же каталог падает `EACCES` (без
  него тест был бы зелёным и в мире, где `chmod` ни на что не влияет). **Оговорка:** `chmod`
  ловит запись своим же пользователем и не ловит запись от root; полный ro-namespace — `H-05`.

**Счёт `guarded`: 56 → 59.**

Помечены **без смены статуса**: **R1** (четыре `HYPERFRAMES_NO_*` стоят и проверены, но это
не изоляция), **R10** (`--format mp4` у рендерера невозможен по построению — единственное
место, где формат называется, отдаёт `png-sequence`; вторая половина R10 уже `guarded` с
`M-04`), **R13** (формула `n/fps` появилась в коде по обе стороны границы; тест — `H-02`),
**D4** (греп-охранник композиции появился; заморозка глобалей — `H-05`), **K6** (версия Chrome
измерена и в профиль не попала), **R14** (обоснование строки устарело — см. §10).

строковых литералов, которые ESLint не разбирает как код. То есть инвариант **D4** не
действовал бы ровно в том месте, ради которого написан, — рендер-путь в браузере. Отсюда
новый греп-охранник `tests/lints/d4-composition.test.ts`; он слабее ESLint и это сказано
вслух, но покрывает область, которую ESLint не покрывает вовсе.

**Н6 нашёл ложно-зелёный тест — мой собственный.** Проверка «`workers` приходит из профиля»
стояла на единственном значении `4` — том самом, что в `render.final.yaml`, — и осталась
**зелёной** при подставленном литерале `'4'`: она стерегла совпадение, а не источник. Тест
усилен тремя значениями (1, 2, 7); после усиления нарушение краснит два теста вместо одного.
Это единственная правка теста по итогам протокола, и она записана, а не спрятана в диффе.

## 10. Кандидаты в правку документов (сам не правил)

**ADR-0008.**
1. **Расширение файла ассета выводится из магических байтов.** В запросе `{sha256, path, role}`
   расширения нет ни одним полем, а браузеру нужен MIME. Добавить поле — изменить контракт;
   поэтому реализовано выведение по сигнатуре (PNG/JPEG/WebP/TTF/OTF/WOFF/WOFF2), неизвестный
   формат — **отказ**, а не `.bin`. WAV отвергается отдельным сообщением со ссылкой на **R5**.
2. **`RenderResponse` как форма ответа подпроцесса.** ADR называет «JSON-ответ на stdout», но
   форму ответа не описывает. После решения A её стоит записать явно, вместе с кодами выхода
   (`0` ok, `1` договорный отказ, `2` stdin не разобрался).
3. **`SegmentArtifact` живёт в `media`, а `SegmentRenderRequest` — в рендерере.** Правка DOC-04
   развела ответственности, но не сказала, где живут типы. Теперь сказано кодом.
4. **`--strict` у рендерера существует** и превращает предупреждения компилятора композиции в
   отказ. См. §5 находку (3): без него неверная разметка даёт не падение, а неограниченно
   долгий рендер. Кандидат в «Гарантии рендерера».
5. **`pixelProfile.imageFormat: jpeg` рендерером не выражается.** У `hyperframes@0.8.5` форматы
   вывода — `mp4|webm|mov|png-sequence|gif`; JPEG-последовательности нет, mp4 запрещён **R10**.
   `render.final.yaml` несёт `imageFormat: jpeg` ⇒ **на профиле `final` адаптер сегодня падает**
   с правилом «ADR-0008 профиль». Это отказ, а не подстановка png: молчаливая подмена формата
   передачи кадров сменила бы пиксели, не сменив ключа кэша. Долг №154.

**ADR-0006 §2.** Какая из двух величин входит в `segmentKey` — наш `bundle.hash` (sha256
перечня каталога) или `engineCompositionHash` рендерера? SP-3c мерил на воспроизводимость
**вторую** («за 134 прогона ровно один»), а в ключ по форме контракта попадает **первая**.
Обе годятся, но выбор обязан быть записан. Долг №155.

**Roadmap §3/§4.9 `H-01`.** Фактический вход — ещё и `CP-07`: адаптер требует, чтобы
`RenderIrSegment` нёс `assets`/`fonts` по sha, а это появилось там.

**Roadmap §4.9 `H-03` / invariants **R14**.** Обоснование строки — «версия Chrome не пришпилена
самим пакетом — её выбирает `puppeteer`» — **устарело**: `hyperframes@0.8.5` пришпиливает её
сам литералом `CHROME_VERSION`. Правило от этого не отменяется (сверять фактическое с
отпечатком по-прежнему надо), но его «почему» другое. Долг №156.
