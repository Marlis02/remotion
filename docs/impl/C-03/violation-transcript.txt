ПРОТОКОЛ НАРУШЕНИЙ — `C-03` (линт прозы, трансдьюсер `[say:]`, охранник V13)
==============================================================================
Каждое нарушение вносится заменой полной строки кода, после чего файл восстанавливается
ИЗ БЭКАПА (не обратной заменой). `fixtures/` не изменяется ни в одном нарушении: там, где
нужен изменённый исходник, правится КОПИЯ во временном каталоге ВНЕ репозитория
(нарушения 21–23 работают на `mkdtemp`, а не на `fixtures/`).
Классы: (а) ломается реализация; (б) ломается сам охранник; (в) нарушение в настоящем коде.

ПОКРЫТИЕ. 23 нарушения:
  1–10  — каждый из ДЕСЯТИ запретов ADR-0002 §3 по отдельности (снят один — красный его кейс);
  11–13 — свойства самого линта: область (только проза), точность позиции, «все нарушения»;
  14–15 — подстановка `[say:]` в трансдьюсере;
  16–18 — по одному на каждое из ТРЁХ property-свойств ADR-0010 §10
          (16 — тотальность, 17 — монотонность, 18 — round-trip);
  19–20 — два правила `C-02`, на которых стоит `C-03`: единица индексации и состав пробельных;
  21–23 — сам охранник V13.

ЧТО ПРОТОКОЛ НАШЁЛ В САМИХ ОХРАННИКАХ. Нарушение 19 (индексация в UTF-16 units вместо code
points — ровно тот МОЛЧАЛИВЫЙ дефект, о котором предупреждает ADR-0010 §10) в первом прогоне
уронило РОВНО ОДИН тест — property-свойство тотальности; ни один тест `C-02`, включая golden,
его не увидел, потому что в фикстуре нет ни одного астрального символа. Кейс F13 при этом
оставался зелёным: длины и монотонность после подмены единицы выглядели правдоподобно. F13
усилен (добавлена сверка прообраза каждого символа с нормализованным потоком исходника), после
чего нарушение 19 роняет два теста. Строка в прогоне ниже — уже после усиления.
Ни один охранник не удалён и не ослаблен.
