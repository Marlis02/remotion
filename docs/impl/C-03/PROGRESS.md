## Что уже есть от `C-02` и переиспользуется без единой новой строки

Трансдьюсер здесь — **не второй парсер**, а стадия над готовым AST. Из `C-02` берётся целиком:

| что | откуда | как используется в `C-03` |
|---|---|---|
| `Chunk.spoken` — spoken-текст чанка | `parse.ts` | это и есть выход трансдьюсера по речи; **identity уже исполнена** |
| `Chunk.spanMap` — прогоны `copy`/`space`, монотонные, в code points | `parse.ts` | **основа** карты `C-03`: прогоны берутся как есть, к ним добавляется display-сторона |
| `TokenNode {origin: 'say', surface, spoken, displaySpan, spokenSpan, spokenStart}` | `ast.ts` | `[say:]` уже разобран в **один** токен: `surface` = `d`, `spoken` = `s`, оба span'а есть |
| `spokenToSource` / `sourceToSpoken` / `runAtSpoken` | `spanmap.ts` | тотальность и монотонность проверяются через них, второй карты нет |
| `Span {start, end, line, column}` в code points, `positionAt`, `pointLength` | `text.ts` | `строка:колонка` линта — отсюда; `Intl.Segmenter` не нужен и запрещён (Charter V8) |
| `SourceParseError` с правилом `'ADR-0002 §3'` (уже в union `SourceRule`) | `errors.ts` | линт отказывает **этим** классом: один класс ошибок на весь диалект |
| NFC + `\n` первым шагом; NBSP **не** пробельный (`WHITESPACE = {' ', '\t', '\n'}`) | `text.ts` | F15 и F16 работают без правок `C-02` — см. п. «F15» ниже |

**Что добавляется:** два модуля (`lint.ts`, `transduce.ts`), display-сторона у прогонов
(`C-02` знает только spoken↔исходник) и третий вид прогона — `say` (вставка/замена).

## План (6 шагов)

### 1. Линт прозы — `packages/core-model/src/source/lint.ts`

Отдельная функция **над AST**, не внутри парсера: `parseSource` принимает текст, `lintProse`
отвергает. Область — **только прозаические токены** (`TokenNode.origin === 'prose'`). Всё
остальное вне области по построению: `[say: d | s]` — токен с `origin: 'say'` (в `d` можно
что угодно, `s` — это и есть «словами»); имена в `[beat:]`/`[img:]` и id заголовков — якоря,
их алфавит стережёт `publicAnchor()` из `@vpe/schema`; `[pause: 400ms]` — параметр маркера.

```ts
export type ProseRuleCode =
  | 'digit' | 'percent' | 'dollar' | 'numero' | 'roman'
  | 'abbreviation' | 'url' | 'bold' | 'list' | 'inline-code';

export interface ProseFinding {
  readonly code: ProseRuleCode;
  readonly location: SourceLocation;   // файл:строка:колонка — числа, не строка
  readonly excerpt: string;            // сам токен
  readonly message: string;            // «<что> — напиши словами или используй [say:]. Например: …»
}

export function lintProse(doc: SourceDocument): ProseFinding[];   // ВСЕ нарушения файла
export function assertProse(doc: SourceDocument): void;           // бросает SourceParseError на первом
```

* **Возвращает список, а не бросает на первом.** Это осознанное расхождение с парсером
  (`C-02`, огр. 2: разбор — один проход без восстановления). Причина: у линта нарушений в
  одном файле бывает много, и «покажи все» — единственная полезная форма. Бросает отдельная
  функция `assertProse`, и бросает `SourceParseError` с правилом `ADR-0002 §3`.
* **Позиция — точная, до символа.** Прозаический токен по построению не содержит пробельных,
  значит не содержит `\n`: `{line: token.span.line, column: token.span.column + i}` — точное
  место `i`-го code point внутри токена. Никакого повторного разбора текста.
* **Формат сообщения — по ADR-0002 §3** дословно: `файл:строка:колонка: <что> — напиши словами
  или используй [say:]`, плюс пример escape-hatch из того же §3 —
  `[say: 23% | twenty-three percent]`. (В задании «запиши словами», в ADR «напиши»; беру
  формулировку ADR как нормативную — если нужно наоборот, это одно слово.)

Определения девяти/десяти запретов — **не эвристики, а закрытые правила** (Charter §7).
Три из них выношу в вопросы (1 и 2 ниже), остальные фиксирую здесь:

| код | правило (буквально) |
|---|---|
| `digit` | любой code point с `Nd`-свойством в пределах ASCII `0`–`9`; шире не беру — не-ASCII цифры в английской прозе недостижимы, а `\p{Nd}` затащил бы деванагари ради нуля случаев |
| `percent` | `%` |
| `dollar` | `$` |
| `numero` | `№` (U+2116) |
| `url` | токен содержит `://` **или** начинается с `www.` **или** начинается с `mailto:`. Голый `example.org` **не** ловится: правило «точка между буквами» неотличимо от сокращения и было бы эвристикой |
| `bold` | токен содержит `**`. Позиция — первая `*` пары. Ловится и разорванный по токенам `**two words**` (краснеет `**two`) |
| `list` | токен стоит в **колонке 1** и равен `-`, `*` или `+`, **либо** совпадает с `<цифры>.`/`<цифры>)`. Только начало строки — по ADR-0002 §3 «списки» |
| `inline-code` | токен содержит `` ` `` |

Один токен может дать несколько находок (`1.` в колонке 1 — `list` и `digit`); находки
дедуплицируются по паре (код, смещение), порядок — по смещению, затем по коду.

### 2. Трансдьюсер — `packages/core-model/src/source/transduce.ts`

Стадия над AST: чанк → `{spoken, display, runs}`. **Identity + подстановка `[say:]`**, ровно
как в ADR-0002 §3 и ADR-0010 §10.

```ts
export type TextRunKind = 'copy' | 'space' | 'say';

export interface TextRun {
  readonly kind: TextRunKind;
  readonly spokenStart: number;   readonly spokenLength: number;
  readonly displayStart: number;  readonly displayLength: number;
  readonly spokenSource: number;  // смещение исходника для spoken-стороны
  readonly displaySource: number; // смещение исходника для display-стороны
  readonly display?: string;      // литерал `d` — ТОЛЬКО у `say`; без него round-trip невозможен
}

export interface ChunkText {
  readonly spoken: string; readonly display: string; readonly runs: readonly TextRun[];
}

export function transduceChunk(chunk: Chunk): ChunkText;
export function reconstructDisplay(spoken: string, runs: readonly TextRun[]): string;
export function spokenOrigin(text: ChunkText, spokenIndex: number): SpokenOrigin;
export function transduceDocument(doc: SourceDocument): ChunkText[];
```

* **Три вида прогона.** `copy` — символ spoken = символ display = символ исходника.
  `space` — схлопнутый ряд пробельных: длина 1 с обеих сторон, оба смещения — на **первый**
  символ ряда. `say` — единственный вид со **вставкой**: `spokenLength = |s|`,
  `displayLength = |d|`, они не равны, `spokenSource` указывает внутрь `s`, `displaySource` —
  внутрь `d`. Это и есть «карта со вставками, а не только с удалениями» (ADR-0010 §10).
* **Как строится — без второго парсера.** Берутся прогоны `chunk.spanMap` **как есть**;
  прогон, чей `spokenStart` совпадает с `spokenStart` какого-то токена `origin: 'say'` и чья
  длина равна `pointLength(token.spoken)`, становится прогоном `say`; остальные — `copy`/`space`
  один в один. Если совпадения нет — это дефект `C-02`, и трансдьюсер падает, а не молчит.
* **Индексация — только code points.** Ни `str[i]`, ни `str.length` по всему модулю:
  `[...text]` и `pointLength`. `Intl.Segmenter` не используется — он дал бы **неверную**
  единицу (ADR-0010 §10: 45/45/44 на `café` в NFD), и он же запрещён Charter V8.
* **Тотальность в формулировке задания:** `spokenOrigin(text, i)` для каждого `i` из
  `[0, |spoken|)` возвращает либо `{kind: 'copy'|'space', sourceOffset, displayOffset}` —
  прообраз есть и в исходнике, и в display, — либо `{kind: 'say', sourceOffset, inserted: true}`
  — символ пришёл из `s`, в display прообраза **нет**, и он помечен вставленным. Третьего
  ответа нет: `undefined` невозможен, потому что прогоны покрывают spoken без дыр и нахлёстов
  (проверяется утверждением при построении).

  на реализации, индексирующей через `str[i]`.
* **F14** URL: в **прозе** `https://example.org/a?b=c` линт отвергает кодом `url`;

  которого нет ни в одном ADR»), а NFC компатибилити-разложение U+00A0 **не** применяет

  U+00A0. Вопроса владельцу нет.

**Property-тесты** — три свойства ADR-0010 §10, генератор `splitmix32` из `test/etalon.ts`,

1. **тотальность** — `spokenOrigin` определён для каждого `i`, прогоны покрывают spoken без

2. **монотонность** — `spokenStart`, `displayStart`, `spokenSource`, `displaySource` строго

Алфавит генератора — ловушки F1–F16 (апострофы обоих видов, em-dash, `…`, curly quotes,

## Вопросы владельцу (три; ответы нужны до первой строки кода)

### Вопрос 1. Римские цифры — где граница

`I` — местоимение, и оно частотнее любого римского числа. Эвристику не изобретаю (Charter §7),
поэтому три варианта с ценой:

* **(а) — рекомендую.** Отдельное слово из **≥ 2** символов, все из `IVXLCDM`, все **в верхнем
  регистре**. Цена: 4 строки. Ловит `II`, `XIV`, `MMXXVI`. Пропускает `I` — и это правильно.
  Ложные срабатывания: аббревиатуры из тех же букв — `MIX`, `CIVIC`, `DVD`, `LID`. В английской
  прозе все они пишутся не капсом, а если капс нужен — escape-hatch тот же `[say:]`.
* **(б)** То же плюс проверка **каноничности** записи регуляркой
  `^M{0,3}(CM|CD|D?C{0,3})(XC|XL|L?X{0,3})(IX|IV|V?I{0,3})$`. Цена: 8 строк. `MIX` и `DVD`
  проходят как проза (они не римские числа), но `IIII` (некононическая, но читаемая как 4)
  тоже проходит — то есть правило становится **слабее** там, где важно.
* **(в)** Не линтовать римские вовсе, записать `UNKNOWN` в `DEBTS.md`. Цена: 0 строк, но
  строка ADR-0002 §3 остаётся без охранника, и V10/V13 это не мешает, а вот «девять/десять
  запретов» становится девятью/восемью.

### Вопрос 2. Сокращения с точкой — какой именно закрытый список

`St.` — и «улица», и «святой»; общего правила нет. Беру **закрытый список и только его**:

* **(а) — рекомендую.** `Dr.`, `St.`, `Mr.`, `Mrs.`, `Ms.`, `Prof.`, `e.g.`, `i.e.` — то есть
  F1 из таблицы ADR-0010 §10 (`Dr.`/`St.`/`Mr.`) + F6 (`e.g.`/`i.e.`) + три ближайших соседа
  той же формы. Сравнение **регистрозависимое**, слово целиком. Цена: одна константа-массив,
  ~6 строк. Честное следствие, которое запишу в отчёт: `etc.`, `vs.`, `Jr.`, `Ph.D.` проходят
  как проза, и обещание ADR-0002 §3 «точка больше не встречается в сокращениях» верно **ровно
  на длину списка**, а не вообще.
* **(б)** Ровно пять из таблицы: `Dr.`, `St.`, `Mr.`, `e.g.`, `i.e.` — буквально «F1 + `e.g.`/`i.e.`
  и только они», как сформулировано в задании. Цена та же; `Mrs.`/`Ms.`/`Prof.` проходят.
* **(в)** Список + правило «любое слово из ≤ 4 букв, оканчивающееся точкой, за которым на той

### Вопрос 3. «Девять запретов» — их десять

В задании трижды сказано «девять запретов», а ADR-0002 §3 и roadmap §4.3 перечисляют **десять**:
цифры, `%`, `$`, `№`, римские цифры, сокращения с точкой, URL, `**жирный**`, списки, инлайн-код.
Считаю это опиской в задании, а не сокращением списка.

* **(а) — рекомендую.** Десять кодов, десять красных кейсов, десять нарушений в протоколе.
  Покрывает «девять» с запасом и совпадает с ADR буквально.
* **(б)** Девять — если `%`, `$`, `№` считать одним правилом «непроизносимые знаки». Тогда в
  протоколе девять нарушений, но код внутри всё равно различает три символа.

Если ответ на вопрос 1 — вариант **(в)**, запретов остаётся девять, и вопрос 3 снимается сам.
