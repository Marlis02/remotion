## 2. Контракт: `guidance` стало обязательным полем

`TemplateSpec` получил обязательное строковое поле — 2–4 предложения «что делает / когда
уместен / чего не делать». Все семь спеков заполнены в этом же коммите; **три** синтетических
спека тестов (`cli/test/template-gate-render.test.ts`, `templates-spec/test/gates-file.test.ts`,
`compile/test/template-contract.test.ts`) правки не потребовали — все три строятся спредом
`...still1` и наследуют поле само. Это и есть измерение того, насколько расширение контракта
дёшево: обязательное поле не потребовало ни одной правки за пределами семи спеков.

**Обязательность — это вся его ценность.** Восьмой шаблон без описания не соберётся вовсе
(ошибка `tsc`), а шаблон с ПУСТЫМ описанием краснеет юнитом поимённо — проба Н1 показала
именно это: в тексте отказа стоит `flash@1`, а не «один из семи».

Что в `guidance` НЕ пишется — ни диапазонов, ни enum'ов, ни умолчаний: их выгружает
интроспекция. Текст, повторяющий схему словами, разошёлся бы с ней при первой правке. Пример
того, что там пишется вместо: у `parallax25@1` — измерение `E-02` §7 («на толпе без одного
выделенного объекта три модели класса u2net дали 0.1–0.2 % кадра, на фигуре — 27–47 %»), то
есть условие применимости, которого в схеме нет и быть не может.

## 3. Интроспекция: `z.toJSONSchema` плюс то, чего она не умеет

Первая половина — штатная: `z.toJSONSchema(paramsSchema, { io: 'input' })`. Вход, а не выход,
потому что автор пишет ВХОД.

**Вторая половина появилась из измерения, а не из осторожности.** `.refine`-проверки в JSON
Schema не попадают, и это проверено на живых схемах: `drift` у `parallax25@1` с диапазоном
`[0, 0.2]` выгружался голым `{"type":"number"}`. То есть выгрузка недоговаривала бы ровно про
то число, в которое ИИ упрётся первым отказом. **Решение владельца (вопрос В1): блок границ
в выгрузку, текст — интроспекцией `error`-функции чека.** Второго источника истины при этом
не появляется: печатается та самая строка, которую вернёт схема, а не её пересказ.

Измерено, что вынимается:

| шаблон | адресов с проверками | что именно |
|---|---|---|
| `kenburns@1` | 6 (`from.*`, `to.*`) | конечность числа и запрет `-0` (ADR-0007 §3) |
| `bed@1` | 2 поля + **`params` целиком** | децибелы; плюс перекрёстная проверка `inPoint.asset == asset` |
| `parallax25@1` | 3 (`drift`, `depthSpread`, `scale`) | те же два плюс СОБСТВЕННЫЕ границы: `[0, 0.2]`, `>= 1`, `> 0` |

**Отдельная находка — `bed@1`.** Его перекрёстная проверка задана `superRefine`, а такой чек
строит текст ВНУТРИ себя, через `ctx.addIssue`; снаружи текста не существует. Выдумать его
было нельзя, промолчать — тоже: молчание ИИ прочёл бы как разрешение. Поэтому в структуре два
поля — `messages` (что назвало себя) и `checks` (сколько проверок есть всего), а выгрузка
печатает честное «ещё 1 перекрёстная проверка, чей текст строится внутри неё самой; его
печатает отказ компилятора».

## 4. Команда и выгрузка

`vpe spec export [--json] [--out <файл>]`. По умолчанию markdown в stdout — выгрузку вставляют
в чат, а не скармливают программе. `--gates-dir` у неё нет намеренно: она отвечает на вопрос
«что умеет ДВИЖОК», а не «что снято на этой машине».

Пять разделов: грамматика прозы и якорей (ADR-0002 §1–§4, ADR-0004 §1/§2/§5a) → каталог семи
шаблонов → числа канала → форма ответа → запреты. Порядок — порядок чтения; запреты стоят
последними намеренно: их читают, уже зная предмет.

**Что в выгрузке ЧИТАЕТСЯ ИЗ КОДА, а не написано:** имена и версии шаблонов, `guidance`, роли
ассетов и шрифтов, объявляет ли шаблон длительность сам, кривые, бюджет мс/кадр, `purposes`,
статус гейта (тем же загрузчиком, что у `vpe template list` — «манифест из двух мест» обязано
означать ОДНО чтение), JSON Schema параметров и границы `.refine`.

**Что авторское — и у каждого утверждения назван источник:** грамматика (ADR), числа канала
(профиль проекта и отчёты `H-07`/`E-07`/`E-02`), форма ответа.

**Вычитка выгрузки глазами дала три недостающих правила** — те, на которых ИИ споткнулся бы
первым же отказом, а раздел о них молчал: грамматика ИМЕНИ якоря (первый символ — буква или
цифра, дальше буквы, цифры, `-` и `_`), `N ≥ 1` у `[pause: Nms]` и разделитель `|` у `[say:]`.
Первое проверено делом, а не переписано из ADR: `publicAnchor()` отвергает `b:the turn`,
`b:-turn` и `b:the.turn`, принимает `b:the-turn`, `b:the_turn` и `b:2turn` — пример в выгрузке
взят из этого прогона.

**Примеры вызовов — из живых файлов, по решению владельца (В2) с указанием источника у
каждого.** Их семь, по одному на шаблон:

| шаблон | источник | почему так |
|---|---|---|
| `kenburns@1`, `parallax25@1`, `captionEmphasis@1`, `flash@1` | `examples/vertical-v1/direction/01-archive.yaml` | живой демо-ролик |
| `still@1`, `bed@1` | `fixtures/minimal/direction/01-intro.yaml` | демо их не зовёт: `still@1` там ПОРОЖДЁННЫЙ, `bed@1` не зовётся вовсе |
| `grade@1` | тот же файл на коммите `0e509d4` (`E-07`), запись `7e21c40a` | вызов снят решением владельца `ENV-01`; форма приведена, чтобы была известна, а не чтобы его звали |

**YAML печатает канонический писатель `@vpe/schema` (`renderFamily`), а не мои руки.** Он «не
создаёт файлов, которые читатель отвергнет» — значит форма примера проверена схемой
`direction/1` по построению, а не глазами. Сверх того юнит прогоняет `params` КАЖДОГО примера
схемой его шаблона: проба Н4 (`drift: 0.35` при потолке 0.2) краснеет.

**Одно расхождение названо, а не спрятано.** В рабочем дереве владельца запись `4d8ea15b`
несёт `drift: 0.09` и `depthSpread: 3.2`; в выгрузку взяты значения КОММИТА (`0.045` / `2.6`)
— некоммитнутая правка не воспроизводима у читателя выгрузки. Односторонность связи
«пример ↔ живой файл» заведена долгом **№234**.

Что проверяет владелец:

1. `vpe spec export` — прочитать выгрузку глазами как ИНСТРУКЦИЮ: можно ли по ней написать

2. `vpe spec export --json | python3 -m json.tool` — парсится (проверено: `schema`

полученные файлы в проект → `vpe build`. Его результат (принял / отказал и как) — вход `F-01`
