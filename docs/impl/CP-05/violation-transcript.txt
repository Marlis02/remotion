НАРУШЕНИЕ 1 — `δ_i` вставлен в НАЧАЛО сегмента вместо конца хвостового gap'а (против T6)

  packages/compile/src/audio/plan.ts, `segmentElements`:

-   return out;
+   return [correctionElement(row, row.firstSample, finalPadding, grid), ...out];

  Красное: ВСЕ 28 тестов файла.

  Сообщение:
    CompileAudioError: ADR-0003 T5: элемент `speech:72xh5eni6aev6aqz` стоит на 0, а предыдущий
    кончился на 240. Перекрытие в 240 сэмплов: аудио-дорожка непрерывна и никогда не режется

  ЧТО ЭТО ЗНАЧИТ. Ассерт непрерывности ловит перестановку МГНОВЕННО и называет её физически:

  его нашли бы позже всех прочих дефектов.

НАРУШЕНИЕ 2 — `boundary-correction` учтён в `L_i` (против определения T6: «δ не входит ни в
один L̃»)

  packages/compile/src/audio/plan.ts, `segmentElements`, сверка суммы сегмента:
+   nominal += row.correctionSamples;
    if (nominal !== row.nominalSamples) {

  Красное: ВСЕ 28 тестов файла.

  Сообщение:
    CompileAudioError: ADR-0003 T5: сегмент `seg:intro`: сумма длин его клипов 552000 ≠
    L_i = 551760. Клип, не попавший ни в один сегмент, означает разрез посреди клипа, а

  ЧТО ЭТО ЗНАЧИТ. Числа в сообщении — это ровно `A_1` против `L_1`: 552000 = 551760 + 240.
  То есть охранник показывает, что поправка ушла внутрь `L`, а не просто «сумма не сошлась».
  Именно эта ошибка делает определение T6 ЦИКЛИЧНЫМ (C3): `L` начинает зависеть от `δ`,
  который зависит от `d`, который зависит от `L`.

НАРУШЕНИЕ 3 — добивка до `Σ A_i` вместо `frameStartSample(F)` (против T5)

  packages/compile/src/audio/plan.ts, `compileAudio`:
-   const finalPadding = index === last ? manifest.trackTailSamples : 0;
+   const finalPadding = index === last ? 0 : 0;

  Красное: ДВА теста, и ОБА — на дробной сетке:
    × дробное `S` (24000 при 30000/1001, `S = 800.8`): добивка НЕНУЛЕВАЯ и лежит в конце
    × дорожка на дробной сетке материализуется и её длина равна плану

  Сообщение:
    CompileAudioError: ADR-0003 T5: сумма длин элементов 460457 ≠ длине дорожки 460460 =
    frameStartSample(F). «Дорожка дополняется тишиной до frameStartSample(F) в самом конце
    ролика» (T5) — добивка приезжает полем `finalPaddingSamples` поправки последнего сегмента
    (решение владельца 5, вариант «а»), и её потеря видна ровно здесь

  ЧТО ЭТО ЗНАЧИТ — И ЭТО ГЛАВНОЕ ИЗМЕРЕНИЕ ПРОТОКОЛА. На фикстуре `minimal` и на синтетике из
  восьми сцен при 24000/30 это нарушение НЕ КРАСНЕЕТ НИ ОДНИМ ТЕСТОМ: при целом `S`
  добивка тождественно равна нулю (`frameStartSample` аддитивна, `Σ A_i` уже равно
  `frameStartSample(F)`), и убрать её — значит не изменить ничего. Ветку T5 держит РОВНО тест
  на дробной сетке, написанный ради неё. Без него строка T5 была бы «guarded» по имени: три
  сэмпла разницы 460457 против 460460 — это ровно тот дефект, который в готовом ролике
  выглядит как последний кадр без звука.

НАРУШЕНИЕ 4 — окно дубля `[0, numSamples)` без вычета краёв (против T7)

  packages/compile/src/audio/render.ts, `renderAudioTrack`:
-   track.samples.set(pcm.samples.subarray(element.fromSample, element.toSample), element.atSample);
+   track.samples.set(pcm.samples.subarray(0, element.lengthSamples), element.atSample);

  Красное: ОДИН тест — «длина в сэмплах равна плану, а окно первого дубля совпадает ПОБАЙТОВО».

  Сообщение:
    AssertionError: expected Int16Array[ 0, 0, 0, 0, 0, 0, 0, …(84481) ] to deeply equal
    Int16Array[ 0, -150, -300, -451, …(85081) ]

  ЧТО ЭТО ЗНАЧИТ. Полученное начинается СЕМЬЮ НУЛЯМИ, ожидаемое — сразу волной. Эти нули и

  класть на дорожку. Дефект не даёт ни ошибки длины, ни расхождения сумм — дорожка остаётся

  (`p95 ≤ 80 мс`) он стоит всей величины лид-ина на каждом чанке.

  ЧЕСТНО О ГРАНИЦЕ ОХРАННИКА: длина дорожки, `sha256` и детерминизм остаются зелёными. Один
  тест — это минимум, при котором правило проверяемо, и он написан не «на всякий случай».

НАРУШЕНИЕ 5 — T9 понижен до WARN (против «компилятор ПАДАЕТ», ADR-0003 T9 = PG-E1)

  packages/compile/src/audio/plan.ts, `assertMaxDuration`:
    if (manifest.totalFrames <= profile.maxDurationFrames) return;
+   if (manifest.totalFrames > 0) return;
    throw new CompileAudioError(

  Красное: ОДИН тест — «`maxDurationFrames = 1472` ⇒ падение с раскладкой в кадрах и секундах».

  Сообщение:
    AssertionError: expected Error: ожидался отказ T9 to be an instance of CompileAudioError

  ЧТО ЭТО ЗНАЧИТ. Тест написан так, что молчание — тоже ответ: если стадия НЕ бросила, тест
  бросает сам («ожидался отказ T9») и падает на проверке класса. Это отличает его от
  `expect(...).toThrow()`, который на понижении до WARN дал бы менее внятную диагностику.
  Смысл правила — `FACT` (r3 §3.3): Short длиннее минуты с claimed-музыкой теряет
  монетизацию, и величина, которую движок добавляет САМ (`Σ δ` T6 и `Σ gap` T8), обязана
  иметь охранника, а не предупреждение.
