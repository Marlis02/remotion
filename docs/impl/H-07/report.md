## 2. Развязка: кто чем владеет теперь

Решение владельца дословно: «Базовая раскладка полосы — свойство ТРЕКА субтитров, живёт в
`runtime.js`; `captionEmphasis@1` оставляет за собой ТОЛЬКО эмфазу активного слова».
Исполнено так:

| | ТРЕК (`composition/runtime.js`) | ШАБЛОН (`captionEmphasis@1`) |
|---|---|---|
| **что** | позиция, ширина, кегль, межстрочный, цвет, мягкая тень, НЕПРОЗРАЧНАЯ плашка; пословная разметка; **какое слово активно и когда** | **как выглядит** эмфаза: `bold` по оси `wght` + тёплый акцент `#ffb347`; плюс `font-family` — вынужденно (долг **№207**) |
| **чем** | правило `#captions .caption-group` / `.caption-plate` / `.caption-word` + два `tl.set` на слово | два `ctx.timeline.set(document.documentElement, …)` на своё окно — **механизм не менялся** |

**Сцепка — наследование, и общего у сторон ровно ДВА ИМЕНИ.** Правило трека ставит каждому
слову `--vpe-caption-weight: normal` и `--vpe-caption-color: #ffffff`, то есть ЗАКРЫВАЕТ его
от наследования. На окне `token.highlight` таймлайн подменяет обе переменные на `inherit` —
слово открывается и начинает брать значение с корня документа, куда его на СВОЁМ окне кладёт
шаблон. Красится ровно пересечение двух окон: активное слово в кадре, где клип эмфазы жив.
Чисел эмфазы в треке нет, чисел раскладки в шаблоне нет — оба факта под охранником
(`templates.test.ts`).

**Почему пословная разметка вообще понадобилась.** До `H-07` `runtime.js` клал текст группы
ОДНИМ текстовым узлом, а `span.caption-token` создавал **пустыми** — красить в строке было
нечего. Теперь каждый токен становится `span.caption-word`, и вход это позволяет буквально:
`text` группы есть `tokens.join(' ')` по построению компилятора
([`captions.ts`](../../../packages/compile/src/timeline/captions.ts), `textOf`). Рантайм это
**проверяет, а не предполагает**, и проверка сразу окупилась: тестовая фикстура рендерера
правило НАРУШАЛА (группа `and the sea` при одном токене `sea`) и была зелёной, потому что
мерить его было нечем. Фикстура исправлена; долг **№208** — о том, что сверка живёт в
браузере, а не в компиляторе, где величина рождается.

**Слово-`span` НЕ несёт `data-start`, и это решение, а не забывчивость** (утверждение стоит в
юните по прямому указанию владельца). Измерено по коду вендора `hyperframes@0.8.5`: клипы он
собирает из `[data-start]` и ставит такому элементу `style.visibility = 'hidden'` вне окна —
слово с собственным окном **исчезало бы** из строки, а не выделялось в ней. Поэтому время
слова едет таймлайном, а `data-frame-*` слова остаются справочными.

## 3. Долг №207: почему `font-family` осталась у шаблона

Семейство знает только тот, у кого есть ссылка на шрифт (`ctx.fonts` + `ctx.fontOf`). У ТРЕКА
`IR.captions` поля шрифта нет ни в IR, ни в профиле, а завести его — правка `compile`,
задачей запрещённая. Следствие названо вслух: **сегмент без клипа эмфазы получает полосу на
месте, в нужном кегле и на плашке, но СИСТЕМНЫМ шрифтом.**

Демо обходит это авторски — по одному `captionEmphasis@1` на сцену (решение владельца), — то
есть обход стоит записи в режиссуре на каждую сцену. Адрес долга подсказал сам компилятор:
текст его отказа уже содержит «Укажите шрифт роли (поле профиля — долг с адресом `H-07`/№13)».

## 4. Числа полосы: предложение с кадрами (№188, №125 — статус НЕ меняется)

Выбраны по глазу под 9:16 и безопасные зоны Shorts (нижние ~15 % и правые ~12 % кадра заняты
интерфейсом), живут константой `BAND` в `runtime.js`:

| величина | значение | почему так |
|---|---|---|
| ширина полосы / отступ слева | **920 / 80** | поля по 80 px с обеих сторон при кадре 1080 |
| низ полосы над краем кадра | **500** | ставит строку в 68–74 % высоты — вне зоны интерфейса |
| кегль | **68** | величина №125, пересмотрена по глазу под вариативный шрифт |
| межстрочный | **1.22** | две строки умещаются в плашку без слипания |
| плашка | `#05070c`, **непрозрачная**, радиус 28, растушёвка `0 0 36px 18px` тем же цветом | решение владельца, вариант «б»: условие применимости **R13** остаётся в силе, мягкость края даётся скруглением и тенью, а не прозрачностью |
| цвет текста / тень | `#ffffff`, `0 2px 10px rgba(0,0,0,0.55)` | читается и на светлом кадре |
| акцент активного слова | `bold` + `#ffb347` | перенос из `sp3f` `.cw .hot`; `H-06` его НЕ переносил с формулировкой «решение, которого никто не принимал» — в `H-07` оно принято |

**ИЗМЕРЕНО НА ГОТОВОМ РОЛИКЕ, а не на макете** (кадр 15.6 с, поиск по точному цвету плашки
±3 на кодек): плашка `y 1297…1430` (высота 134), `x 225…854` (ширина 630), низ на **489 px**
над краем кадра, центр строки — **71.0 %** высоты, центр по X — **540** при кадре 540. То
есть попадание в названную владельцем зону 68–74 % проверено числом.

**Плашка ОБНИМАЕТ текст, а не занимает всю полосу** — отдельный узел `span.caption-plate`
внутри группы. Ширина её поэтому переменная (630 px на трёх словах, 494 на трёх коротких), и
это **добавляет требование прибору `H-02`**: кроп полосы для **R13** обязан быть по ВЫСОТЕ, а
не прямоугольником фиксированной ширины.

Потолок символов (`maxGroupChars: 21`) в профиле демо оставлен фикстурным и НЕ
пересматривался: при полосе 920 и кегле 68 он заведомо не тесен, а его пересмотр есть предмет
того же №188. **Статусы №125 и №188 не меняются — буква за владельцем, по кадрам.**

## 5. Шрифт (№13): два кандидата, и одно измерение по дороге

**Механика ingest'а исполнена на настоящем файле.** Демо несёт ОДНУ запись
`fonts/records/<sha>.json` на ВАРИАТИВНЫЙ шрифт — то есть правило v1 «ровно один font-record»
([`contract.ts:116`](../../../packages/compile/src/timeline/contract.ts)) выполняется без
всякого смягчения: начертания живут осью `wght`, а не вторым файлом. Правило предъявлено
делом — нарушение Н2 (§6).

| | **Inter** (в коммите) | **Montserrat** (кадрами) |
|---|---|---|
| версия | 4.001 (`git-66647c0bb`) | 9.000 |
| оси `fvar` | `opsz` 14…32 (умолч. 14), `wght` 100…900 (умолч. **400**) | `wght` 100…900 (умолч. **100**) |
| `name` 1 / 2 | `Inter` / `Regular` | `Montserrat Thin` / `Regular` (типографическое семейство — nameID 16 `Montserrat`) |
| `fsType` (OS/2) | **0** — встраивание разрешено без ограничений | **0** |
| лицензия | **SIL Open Font License 1.1** | **SIL Open Font License 1.1** |
| sha256 | `29160a80…9031` | `0f7b311b…82f7` |

Оба прогона — на одном тексте, одних фотографиях и одном `now`; отличие прогонов **ровно одно
— запись шрифта**. Кадры: [`frames/`](frames), по три полных кадра и три кропа полосы 1:1 на
прогон (см. §8).

**ПРОБА П1 — ОСЬ ИЛИ СИНТЕТИКА.** По букве CSS Fonts 4 дескриптор `font-weight` у `@font-face`
по умолчанию равен `normal`, ось должна быть прижата к 400, а `font-weight: bold` — уйти в
синтетическое утолщение. Измерено, что на этом браузере это НЕ так, и измерено тремя пробами
подряд, как требует протокол:

1. у `Montserrat[wght]` умолчание оси — **100 (Thin)**, а кадр НЕ волосяной ⇒ ось выставлена
   в 400 по `font-weight: normal`, дефолтный инстанс файла не взят;
2. добавление `font-weight: 100 900` в `@font-face` **доезжает** до композиции:
   `bundle.hash` сегмента 3 сменился `2a8af058fbdd…` → `f4d47c7909fd…`;
3. кадр 15.6 с при этом — **побайтово тот же**, md5 `a14aa37313841b2c76b7f64b5d630f56`.

Значит диапазон браузер берёт из `fvar` сам, и решение владельца «вес по оси вариативного
шрифта» **исполняется** — но исполняет его ВЕНДОР, а не наш код, и охранника у этого нет:
долг **№209**, адрес `H-02`.

**ПОБОЧНОЕ, НО ВАЖНОЕ.** Тест-на-факте `H-06` («на шрифте проекта эмфаза пикселей не меняет»)
покраснел и перевёрнут на «различаются» — как и было предписано прежней сессией. Но красное
дала **не жирность, а ЦВЕТ**: гарнитура прибора всё ещё `DejaVuSans-Bold.ttf` с машины (долг
**№187**), оси весов у неё нет, и эмфаза «только весом» не изменила бы там ни одного пикселя.
Это предельный случай в пользу второй половины решения владельца: «на телефоне жирность одна
не читается».
