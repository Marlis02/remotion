# `CAPTION-01` — субтитры настраиваемые: тринадцать ручек, четыре пресета, прежний вид байт в байт

**Дата:** 2026-09-11. **Машина:** комп владельца (`ct`), образ `vpe-env:env-02`,
отпечаток `3217a4cf…3cb95c`. **Вход:** `H-07` (раскладка полосы — свойство трека), `TPL-01b`
(пресеты), `TPL-01c` (демо). **Основание:** задание владельца и его же **разрешение на
закрытую зону `composition/runtime.js`** от 2026-09-11.

## 1. Что было и что стало

**Было.** Субтитр = одно поле `style: "bold"`, и вид полосы жил в ДВУХ местах кода движка:
акцентный цвет `#ffb347` — в реализации шаблона, а плашка, кегль, положение и ширина —
константами `BAND` в `composition/runtime.js`. Автор не мог поменять вид субтитров, не правя
движок.

**Стало.** Тринадцать ручек у `captionEmphasis@1` и четыре пресета. Вид полосы по-прежнему
строит ТРЕК (решение `H-07` не отменено ни в одну сторону), но **значения ему подаёт клип**:
`mount` кладёт набор в `window.__VPE_CAPTION_BAND`, `runtime.js` накладывает его поверх
умолчания канала по ЗАКРЫТОМУ СПИСКУ ИМЁН. Сегмент без клипа получает ровно то, что получал
до задачи.

| ручка | что | границы |
| --- | --- | --- |
| `font` | роль шрифта проекта | `^[a-z][a-z0-9-]*$`, умолчание — `caption` |
| `sizePx` | кегль | 40…120, целое |
| `weight` | начертание АКТИВНОГО слова (ось `wght`) | `regular` \| `bold` |
| `textColor` | цвет текста полосы | `#rrggbb`, строчные |
| `activeColor` | цвет активного слова | `#rrggbb` |
| `bg` | фон под текстом | `plate` \| `translucent` \| `none` |
| `plateColor` | цвет плашки | `#rrggbb`; запрещён при `bg: none` |
| `plateOpacity` | прозрачность плашки | 0…1; ТОЛЬКО при `bg: translucent` |
| `outline` | обводка `{widthPx 0…8, color}` | читаемость без плашки |
| `shadow` | тень `{dxPx, dyPx, blurPx, color, opacity}` | выключается нулями |
| `position` | положение по вертикали | `bottom` \| `center` \| `top` |
| `marginPx` | отступ от края по `position` | 0…600; запрещён при `position: center` |
| `widthPct` | ширина блока, доля кадра | 40…95 |

**Три `.refine`, и все три — про ПОЛЕ БЕЗ АДРЕСАТА.** Написанное и не действующее хуже
ненаписанного: автор поправит `plateColor`, посмотрит кадр и не увидит разницы, а причина
(«у вас `bg: none`») не напечатана нигде. Поэтому — отказ с адресом поля, а не молчание.

**НИ ОДНА РУЧКА НЕ ИМЕЕТ `.default()` В СХЕМЕ, И ЭТО РЕШЕНИЕ.** IR несёт `params` как их
написал автор (компилятор кладёт в клип СЫРОЙ merge пресета и записи, а не `parsed.data`),
поэтому `.default()` в zod завёл бы ВТОРОЙ комплект тех же чисел рядом с `BAND` — и разъехался
бы с первым в день первой правки. Не названная ручка берётся из умолчания канала.

**Две ручки, названные в задании, получили по дополнительному полю, и обе — ради байт в байт.**
`shadow.opacity` отдельным полем: прежняя тень канала — `rgba(0, 0, 0, 0.55)`, шестицифровой
hex её невыразим, а `#rrggbbaa` дал бы альфу 140/255 = 0.549, то есть ДРУГОЙ пиксель.
`widthPct` вместо `widthPx`: 85.185185 % от 1080 — это ровно 920, а абсолютное число сломалось
бы на кадре другой ширины.

## 2. Разрешение владельца: дифф `composition/runtime.js`

Правка по разрешению от 2026-09-11, ровно в объявленных границах: зашитые числа стали
читаемыми из данных клипа. **НЕ ТРОНУТО:** механика монтирования `#captions`, порядок кадров,
атрибуты `data-*`, которые компилятор читает статически, вычисление групп. Форма, которую
читает компилятор, не изменилась ни одним полем — значит условие «СТОП по задаче» не наступило.

### БЫЛО (объект `BAND`, строки ~245–312)

```js
  var BAND = {

    widthPx: 920,
    leftPx: 80,
```

### СТАЛО (те же числа до единицы + наложение поданного клипом)

```js
  var BAND = {
    /** Доля ШИРИНЫ кадра под блок субтитров: 85.185185 % от 1080 ⇒ 920 px, поля по 80. */
    widthPct: 85.185185,
    /** Низ полосы над краем кадра: 500 при 1920 ⇒ строка в 68–74 % высоты. */
    position: 'bottom',
    marginPx: 500,
    sizePx: 68,
    lineHeight: 1.22,
    /** Базовое начертание слова. КЛЮЧЕВЫМ СЛОВОМ: числу gsap дописал бы единицу (`H-06`). */
    wordWeight: 'normal',
    textColor: '#ffffff',
    /** Мягкая тень под текстом: полоса читается и на светлом кадре. */
    shadow: { dxPx: 0, dyPx: 2, blurPx: 10, color: '#000000', opacity: 0.55 },
    /** Обводки у канального умолчания нет: под непрозрачной плашкой она — лишние пиксели. */
    outline: { widthPx: 0, color: '#000000' },
    bg: 'plate',
    plateColor: '#05070c',
    plateOpacity: 1,
    plateRadiusPx: 28,
    platePadding: '14px 32px',
    plateFeatherPx: 36,
    plateSpreadPx: 18,
  };

  var overlay = window.__VPE_CAPTION_BAND;
  if (overlay) {
    var KEYS = [
      'widthPct', 'position', 'marginPx', 'sizePx', 'textColor',
      'shadow', 'outline', 'bg', 'plateColor', 'plateOpacity',
    ];
    for (var k = 0; k < KEYS.length; k++) {
      if (overlay[KEYS[k]] !== undefined) BAND[KEYS[k]] = overlay[KEYS[k]];
    }
  }

  var bandWidthPx = Math.round((MANIFEST.baseWidth * BAND.widthPct) / 100);
  var bandLeftPx = Math.round((MANIFEST.baseWidth - bandWidthPx) / 2);
```

Ниже по файлу текст правил собирается из этих величин: вертикаль (`bottom`/`top`/`center`),
`text-shadow` из `shadow`, `-webkit-text-stroke` + `paint-order: stroke fill` из `outline`,
три ветви плашки (`plate` — непрозрачная с растушёвкой, `translucent` — `rgba()` без
растушёвки, `none` — только `display: inline-block`).

**НАЛОЖЕНИЕ ИДЁТ ПО ЗАКРЫТОМУ СПИСКУ ИМЁН, А НЕ КОПИРОВАНИЕМ КЛЮЧЕЙ.** Копирование пустило
бы в раскладку любое поле, которое шаблон когда-нибудь положит рядом, и опечатка в его коде
молча завела бы неизвестное рантайму поле. Список — ДОГОВОР между двумя сторонами ГРАНИЦЫ
ПРОЦЕССА (браузер против Node, общего модуля нет), и его совпадение стоит охранником-грепом по
обоим файлам.

**ЧЕГО НЕ СТАЛО РУЧКАМИ И ЭТО НАЗВАНО:** `plateRadiusPx`, `platePadding`, `plateFeatherPx`,
`plateSpreadPx`. Владелец их не называл, а каждая ручка стоит строки в `vpe spec export`, то
есть места в задании для ИИ. Долг, а не умолчание.

## 4. ГЛАВНОЕ ЧИСЛО: прежний вид сохранён ПОБАЙТОВО, и это измерено дважды

### 4.1 Четырнадцать записей гейта: `sha256` не сдвинулся НИ У ОДНОЙ

Правка `runtime.js` двигает `bundle.hash` у ВСЕХ шаблонов — рантайм встраивается в
`index.html`, а он входит в перечень каталога композиции. Поэтому пересняты **все семь
шаблонов на обоих профилях**, а не один, как предполагало задание.

| шаблон | профиль | `sha256` до | `sha256` после | `bundleHash` |
| --- | --- | --- | --- | --- |
| `captionEmphasis@1` | `final` N=10 | `541b7a170fbcfa9d` | `541b7a170fbcfa9d` **равен** | `58e06db5d8c2` → `ba583b7536e7` |
| `captionEmphasis@1` | `draftHalf` N=3 | `70e3f6dbdad1822f` | `70e3f6dbdad1822f` **равен** | `3a571505bc7d` → `aca62cd30c46` |
| `still@1` | оба | `3f97e47aea65900a` / `d21d011019c63736` | **равны** | сдвинулся |
| `kenburns@1` | оба | `3dc745097a66e2b2` / `6c5be6fe9c40dcd0` | **равны** | сдвинулся |
| `flash@1` | оба | `813e0295c20eb5d1` / `efeecc768abe5dd7` | **равны** | сдвинулся |
| `grade@1` | оба | `8fe4418dc9f89a9d` / `f65fc4431b8b9478` | **равны** | сдвинулся |
| `parallax25@1` | оба | `894886fb5fdd62bb` / `7b8aa4ced5a5c75a` | **равны** | сдвинулся |
| `video@1` | оба | `939e9eb75b0ca3b1` / `ab90e9b7dc4b2940` | **равны** | сдвинулся |

**Все четырнадцать — класс `PASS`, `sha256` и `framemd5` совпали с прежними записями.** То
есть перепись раскладки не сдвинула НИ ОДНОГО ПИКСЕЛЯ ни на одном шаблоне — ни там, где
субтитры есть (`captionEmphasis@1`, `params` = `bottom-warm`), ни там, где их нет.
Это и есть ответ «пиксельно — ДА» на вопрос задания.

### 4.2 Живой проект `work/ct-test-1`: тот же `sha256` финала

Три записи мигрированы `params: {style: bold}` → `preset: "bottom-warm"`, сборка `draftHalf`
штатной командой через образ:

| прогон | `sha256` `final.mp4` |
| --- | --- |
| до миграции (тот же код, `CACHE-02`) | `8daa9ef2c0c048c98421a82b38806c7f3ea08edc24ef64853a2b0dbfee2ae45d` |
| **после миграции** | `8daa9ef2c0c048c98421a82b38806c7f3ea08edc24ef64853a2b0dbfee2ae45d` **равен** |

**ОГОВОРКА, КОТОРУЮ ОБЯЗАНО ПРОЧИТАТЬ ЗАДАНИЕ.** §2.4 говорит: «Промах на субтитровом сегменте
= пресет разошёлся с константами → СТОП». В таком виде критерий неисполним, и вот почему:
`params` клипа входят в `segmentIrHash`, а они СМЕНИЛИСЬ (одно поле → тринадцать), и
`bundle.hash` сменился тоже (правили `runtime.js`) — значит промах структурно неизбежен на
всех трёх сегментах, независимо от того, совпал вид или нет. Промах здесь не признак ошибки.
Признак — РАВЕНСТВО `sha256` финала, и оно выполнено. **Решение сессии, пересмотреть.**

### 4.3 Юнит вместо «дампа IR старого кода»

§2.4 просил юнит «дамп IR записи `style:bold` старого кода == дамп записи `preset:bottom-warm`
нового». Буквально он невыполним: дампы РАЗНЫЕ по построению (одно поле против тринадцати), и
тест, сравнивающий их, был бы красным при любом правильном исходе. Вместо него —
[`captions-preset.test.ts`](../../../packages/renderer-hyperframes/test/captions-preset.test.ts),
и он утверждает то, что задание имело в виду, двумя независимыми способами:
`bottom-warm` == ЗАМОРОЖЕННЫЙ СНИМОК прежних констант (историческая запись, меняться не
может) и `bottom-warm` == НЫНЕШНЕЕ умолчание канала в `runtime.js` (то есть сегмент без клипа
выглядит так же, как сегмент с этим пресетом). **Решение сессии, пересмотреть.**

## 7. Найдено по дороге — ЧУЖОЙ ЛАТЕНТНЫЙ ДЕФЕКТ (новый долг)

Первая редакция демо **не собиралась**:

```
CompileAudioError: ADR-0003 T5: элемент `correction:seg:warm` длиной 0.
Интервалы модели полуоткрыты (**T4**), пустых среди них нет: элемент нулевой длины —
это не тишина, а забытая ветка
```

Причина найдена чтением: `correctionElement`
([`compile/src/audio/plan.ts`](../../../packages/compile/src/audio/plan.ts)) кладёт элемент
поправки **ВСЕГДА**, даже когда `δ_i = 0` и добивки нет, — а `assertContinuous` в том же файле
такой элемент законно отвергает. То есть **любой проект, у которого речь сегмента случайно
легла ровно на сетку кадров, сегодня не собирается**, и виноват в этом не автор.

Дефект НЕ ЧИНИЛСЯ: аудио-тракт эта задача не трогает и разрешения на него не имела.
Обойдён редакцией текста демо (одно предложение длиннее), заведён долгом **№274** с точной
воспроизводящей строкой. **Решение сессии, пересмотреть.**

## 8. Чего НЕ сделано

* `plateRadiusPx`, `platePadding`, `plateFeatherPx`, `plateSpreadPx` ручками не стали — долг;
* **вид полосы — свойство СЕГМЕНТА, а не окна клипа.** Правило `<style>` у трека одно, и
  менять кегль в середине сегмента нечем. Первый клип эмфазы в сегменте побеждает (тем же
  правилом идемпотентности, что у инъекции `<style>`) — долг;
* «авто-плашка по яркости кадра» — новый долг, как и просило задание;
* долг **№207** (сегмент без клипа эмфазы рисуется системным шрифтом) НЕ закрыт и не сузился:
  `font` называет РОЛЬ, а ссылку на шрифт по-прежнему имеет только клип.
