## 2. Развилка §2.3 — **ДЫРА**, и это измерение, а не выбор

Задание оставляло два пути: пробить сквозь нижние слои прозрачное окно либо рендерить сегмент
браузером ДВАЖДЫ. Ответ дан пробой на одном кадре 1080×1920 (`still@1` под слоем, который
пытается пробить дыру):

| чем пробуем | пиксель ВНУТРИ прямоугольника | снаружи |
|---|---|---|
| `backdrop-filter: opacity(0)` | `156,156,156,255` | `161,161,161,255` |
| то же + `blur(0px)` | `156,156,156,255` | не тронут |
| контроль (дыры нет) | `156,156,156,255` | `161,161,161,255` |
| **`clip-path: path(evenodd, …)` на слоях ниже** | **`0,0,0,0`** | **не тронут** |

`backdrop-filter` дыры не даёт ВООБЩЕ — кадр неотличим от контроля: фильтр рисует
отфильтрованную копию ПОВЕРХ фона, а не заменяет его, и `opacity(0)` означает «не рисуй
ничего». `clip-path` с правилом чётности даёт ровно дыру. На готовой композиции гейта доля
прозрачных пикселей — **11.51 %** при расчётных 11.53 % (367×652 из 1080×1920).

**Второй проход браузера поэтому НЕ ДЕЛАЕТСЯ, и цена, которую мы не платим, названа:** второй
рендер каждого сегмента с видео, две композиции на сегмент, два `bundle.hash`, пересъёмка
гейтов и правка ключа кэша.

**Цена, которую дыра БЕРЁТ**, названа тоже: правило CSS ставится один раз на монтировании и
СТАТИЧНО. Отсюда отсутствие ручки `move` — едущее окно требовало бы пересчёта `clip-path` на
каждом кадре, то есть колбэка в композиции, чей детерминизм не измерен (**D4**).

**Как это выражено, чтобы не нарушить границу шаблона:** инъекцией `<style>` в документ — тот
же приём, которым `captionEmphasis@1` инъектирует правила полосы субтитров (`H-06`/`H-07`), и
тот же класс действия, каким `grade@1` красит лежащее ниже `backdrop-filter`'ом. Свой `z`
шаблон берёт с `data-z` собственного узла, чужие — из `window.__VPE_IR.clips`; `runtime.js` не
тронут ни строкой.

**СЛОЙ НА ТОМ ЖЕ `z` ЗАКРОЕТ ВИДЕО**, и это видно с первого прогона: дыра пробивает слои
СТРОГО ниже. Найдено живой сборкой (в проекте владельца уже лежало полноэкранное фото на `z:
20`), исправлено записью на `z: 25` и сказано в `guidance` шаблона вслух.

## 3. Архитектура: стадия между рендером и энкодом

`рендерер → PNG(rgba) → compositeVideoUnderlay → PNG(rgba) → encodeSegment → .mts`

[`media/src/assemble/video-underlay.ts`](../../../packages/media/src/assemble/video-underlay.ts).
Граф одной командой ffmpeg:

```
[1:v] trim=start_frame=<inPoint>, setpts=PTS-STARTPTS,
      fps=fps=30/1:round=down,               ← 24 → 30 повтором кадров, округление ВНИЗ
      loop=…:size=1:start=…,                 ← пауза (по одному фильтру на паузу)
      setpts=N/(30/1)/TB,                    ← перенумерация времён после loop
      tpad=stop=-1:stop_mode=clone,          ← держать последний кадр
      trim=end_frame=<frameCount>,           ← длина — величина ПЛАНА
      scale+crop | scale+pad,                ← cover | contain
      scale(eval=frame)+crop,                ← наезд, суперсэмплинг ×2 (вариант «d»)
      format=rgba,
      pad=<W>:<H>:<x>:<y>:color=0x00000000   ← нижний слой на полный кадр
[vid]; [vid][0:v] overlay=x=0:y=0:shortest=1 [out]
```

**`R10` ОСТАЛСЯ ВЕРЕН БУКВАЛЬНО, И №255 ЗАКРЫВАЕТСЯ ФАКТОМ.** Спайк ставил вопрос так: «видео
кодируется один раз» перестаёт быть верным, потому что нижний слой приходит уже кодированным и
пересобирается вместе с графикой; правило придётся либо сузить, либо переформулировать. Ни то
ни другое не понадобилось: промежуток между стадиями — **PNG без потерь**, кодирование
по-прежнему ровно одно (`encodeSegment`), `segmentEncodeArgs` и `FORBIDDEN_CONCAT_ARGS` не
тронуты ни строкой.

**ЧТО ПРИШПИЛЕНО** (каждое — там, где у ffmpeg умолчание зависит от сборки): `-sws_flags
lanczos+accurate_rnd+full_chroma_int`, `format=rgba` ДО наложения, `-fps_mode passthrough`,
`fps=…:round=down` (та же формула `floor`, что у `videoFrameOf`), `-c:v png`, `-pix_fmt rgba`.
**Сика по времени нет ни одного** — точка входа берётся `trim=start_frame`, то есть по кадрам.

**`-threads 1` НЕ СТАВИТСЯ, И ЭТО ИЗМЕРЕНИЕ:** восемь прогонов БЕЗ него дают один sha (§4).

### Две ошибки графа, найденные измерением

1. **Размер выхода `overlay` равен размеру ГЛАВНОГО входа.** Первая живая сборка упала на
   `width not divisible by 2 (367x652)`: врезка стала главным входом и задала размер кадра.
   Лечение — `pad` нижнего слоя до полного кадра ДО наложения; смещение врезки живёт ровно в
   одном месте.
2. **`loop` повторяет кадр, не трогая PTS**, и `overlay` теряет синхронизацию: выход выходил
   на кадр короче плана (`R8`: «заказано 113, измерено 112»), а та же цепочка без `loop` —
   верной длины. Лечение — `setpts=N/fps/TB` после пауз плюс `trim=end_frame` по числу плана.
   **Поймал это `R8`, а не глаз** — то есть охранник сработал по назначению.

## 8. Чего НЕ сделано — списком, с ценой

* **`move`** (переезд прямоугольника между `full` и `corner`) — дыра статична, едущее окно
  требует пересчёта `clip-path` на каждом кадре. Долг.
* **`radius`** (скругление окна) — скругление обязано совпасть ПО ОБЕ стороны границы: в дыре
  (`clip-path` с дугами) и в маске видео у ffmpeg. Две независимые реализации одной кривой —
  ровно тот класс расхождения, который проект себе запрещает. Долг.
* **`loop`, `speed`, `audio: full|duck`** — «показать ещё раз», «показать медленнее» и звук
  суть другие намерения; звук адресован `VID-02b`. Долги.
* **Окно клипа и дыра**: правило CSS живёт весь сегмент, а не только окно `video@1`. Сегодня
  ненаблюдаемо (вне окна в дыре чёрный фон), на сегменте с движущимся фоном будет видно. Долг.
* **Видео копируется в каталог композиции** материализацией (она копирует все `request.assets`),
  хотя браузер его не открывает. Цена — копия файла на сегмент. Долг.
* **Кэш-охранник «правка `zoom.to` промахивается ровно этим сегментом»** (§3 п. 6 задания) не
  написан: `segmentIrHash` несёт `params` целиком, то есть свойство следует из уже
  доказанного (**K9**, golden blast radius), а прибор на видео потребовал бы браузерного
  прогона. Долг.
