# `TS-01` — `templates-spec`: контракт шаблона, манифест с записью гейта, реестр

**Задача:** [roadmap](../../roadmap.md) §3 строка `TS-01`, §4.8 подраздел `TS-01`.
**Вход:** `C-05` (закрыт). **Оценка roadmap:** 1; фактическая — см. §11.
**Первый код пакета `@vpe/templates-spec`.** До этой сессии `src/index.ts` содержал `export {}`.

## 1. Что сделано

Пакет получил контракт шаблона: **грамматику имени вызова**, **схемы `params` пяти шаблонов
фикстуры**, **чистые `declareAssets`/`declareFonts`**, **манифест с записями гейта**, **реестр**
и **два входа инвариантов** — `requestFiles` (**R3**) и `assertBuildMayStart` (**R12**).

Компилятор не тронут ни одной строкой: `compile` продолжает нести `params` данными. Всё, что
требует ВЫЗОВА контракта из `compose`/`compileIr`, адресовано новой задаче `CP-06` (§9).

**Числа:** 15 модулей `src/` (1 532 строки), 7 файлов тестов пакета (931 строка, 152 теста),
один охранник границы (97 строк, 5 тестов). `pnpm test` — **110 файлов / 1869 тестов / 99.64 с**
(было 103 / 1712); `pnpm typecheck` и `pnpm lint` зелёные.

### Источник каждого числа `msPerFrameBudget`

**Ни одно не измерено, и ни одно не помечено `FACT`.** Спайки мерили другие композиции:
`FACT` (SP-3f §2) — шейдерный фон **13.5 мс/кадр**, частицы **≈ 37 мс** на каждый из своих 95
кадров, стеклянная карточка **+0.9 мс/кадр при разбросе серии ±4.7 %** («ниже шума»). Ни
`kenburns`, ни `still`, ни `flash`, ни `captionEmphasis`, ни `bed` не участвовали ни в одном
из пяти спайков SP-3.

* `kenburns@1` — **2**, `INFERENCE`: ближайшее измеренное — стеклянная карточка («ниже шума»);
  Ken Burns дешевле по эффектам, но масштабирует полноэкранное фото ⇒ взято вдвое больше;
* `still@1`, `flash@1`, `captionEmphasis@1` — **1**, `INFERENCE`: статичная картинка, твин
  прозрачности, смена начертания в уже рисуемой полосе;
* `bed@1` — **0**, и это **не оценка, а свойство**: шаблон аудио-домена кадров не рисует.

Числа заменяются **измерением при прохождении гейта** (`E-00`). Долг №146.

### Находка 9 — строка в отчёт по требованию владельца

**При `CP-06` тест `D1` из `CP-04`, считающий четыре seed'а, обязан быть ПЕРЕЧИТАН, а не
подогнан.** Сегодня `CP-04` кладёт один seed на клип с ключом `purpose = templateId`
(долг №135). Контракт говорит другое: `purposes` пуст у всех пяти шаблонов фикстуры, потому
что случайности не требует ни один. Значит при подключении контракта карта `seeds` станет
**пустой** у всех клипов — то есть D1 будет считать НОЛЬ seed'ов, а не четыре и не другие
четыре. Это не «поправить число в тесте»: это вопрос «а что D1 вообще охраняет, если ни один
шаблон v1 случайности не просит». Ответ принадлежит `CP-06`, и он обязан быть решением, а не
правкой ожидания.

## 4. Входы R3 и R12: что охраняется, а что — нет

Roadmap обещал `TS-01` два перехода: **R3 (вход)** и **R12 (вход)**. Переходов в `guarded`
**нет ни одного, и это ожидалось заданием**: обе строки говорят о поведении сборки и адаптера,
которых ещё не существует.

### R12 — «сборка не стартует без записи гейта для пары»

Написано и покрыто: `assertBuildMayStart(registry, usedTemplates, {profileId, engineFingerprint})`.
**Вызывающего нет** — сборку запускает `vpe build` (`L-01`), а `L-01` ждёт `H-01`.

Матрица (16 тестов, `test/gate.test.ts`):

| вход | результат |
|---|---|
| пять шаблонов фикстуры, `gates: []` | **падает** — это критерий |
| синтетический спек с полной записью на той же паре | проходит |
| запись на другом `engineFingerprint` | падает |
| запись на другом профиле | падает, называя, какие записи есть |
| класс `FAIL` | падает |
| класс `FLAKY-по-контейнеру` | падает — нормализация ещё не применена |
| `PASS` на `final`, сборка на `draftHalf` | падает — проверяется ПАРА, а не профиль |
| две полные записи | пускают обе сборки |
| шаблона нет в реестре / имя не разбирается | падает с той же `R12` |
| восемь вызовов `still@1` | одна строка отказа |

**Результат на фикстуре — дословно** (полный текст — в
[`violation-transcript.txt`](violation-transcript.txt)):

```
R12: сборка не стартует: 5 шаблон(ов) без пройденной записи гейта для пары
(профиль `final`, отпечаток `0000…0000`).
  • kenburns@1 — записи гейта для профиля `final` нет (записей нет ни одной).
    Снимите гейт: `vpe template gate kenburns@1 --profile final`
  • flash@1 — … • bed@1 — … • still@1 — … • captionEmphasis@1 — …
Правило — Charter V13: «шаблон, не прошедший гейт, не версионируется и не используется;
сборка ролика с таким шаблоном не стартует». Запись ставит АВТОР командой
`vpe template gate` (решение владельца 5, RM1) — ночного CI в v1 нет
```

Падение — **ожидаемый результат, а не сбой**: рендерера нет, прогонов не было, `gates: []` —
честное состояние. Именно на нуле записей R12 обязана не пустить сборку.

### R3 — «адаптер не открывает файлов вне `assets`/`fonts` запроса»

Написан **единственный источник списка** — `requestFiles(spec, params) = declareAssets ∪
declareFonts`. Без него «вне запроса» нечем определить. `params` прогоняются схемой ДО
деклараций: декларация на невалидных `params` вернула бы список, которого никто не объявлял.

**Вызывающего нет** — запрос собирает адаптер (`H-01`), список в него кладёт компилятор
(`CP-06`). Что охраняется здесь: чистота деклараций (греп на диск/сеть) и то, что список —
функция только `params`.

На фикстуре `requestFiles` даёт **три ссылки**: `pad-loop` (`bed@1`), `ledger` (`still@1`) и
шрифт роли `caption` (`captionEmphasis@1`).

## 5. Что измерено этой сессией

1. **`still@1` обязан принимать ДВЕ формы своих `params`.** `expandImg`
   ([`core-model/src/anchors/img.ts`](../../../packages/core-model/src/anchors/img.ts)) строит
   порождённую `[img:]`-запись как `params: { asset: slot.alias }` — **без `fit`**, а фикстура
   несёт `{ asset, fit }`. Сделай `fit` обязательным — и **восемь записей из восьми** на ролике
   AC1 (ADR-0002 §4: `[img:]` разворачивается в `still@1`) не прошли бы собственный контракт.
   Поэтому `fit` необязателен, а умолчание принадлежит коду шаблона, не схеме.
2. **Ни один из пяти шаблонов фикстуры не требует случайности.** `purposes: []` у всех пяти —
   это измерение, а не заглушка. Следствие для `CP-06` — §3, находка 9.
3. **`bed@1` кадров не рисует.** Шаблон аудио-домена в библиотеке, где гейт сравнивает `sha256`
   готового mp4 и `framemd5`. Что означает «гейт шаблона `bed@1`» — вопрос без ответа в
   документах; долг №147.
4. **Первый эшелон отказа «манифеста нет» стережёт ТЕКСТ отказа, а не отказ.** Снятие
   рантаймовой проверки шаблон всё равно не пропускает: его ловит `safeParse(undefined)`.
   Показано (Н1/Н1b): чтобы спек без манифеста действительно зарегистрировался, пришлось снять
   ОБА эшелона — тогда краснеют 5 тестов.
5. **Чистоту деклараций стережёт греп, а не равенство результатов.** `declareAssets` с
   `fs.existsSync` оставляет тест «два вызова дают равный результат» **зелёным** (24/24) —
   чтение одного файла дважды и даёт равные результаты. Красным становится только
   греп-охранник границы (Н5).
6. **`zod` остался в одной версии.** `pnpm why zod` → `4.4.3`, владельцы `@vpe/schema` и
   `@vpe/templates-spec`; лок вырос ровно на 3 строки (`importers`), новых пакетов ноль.
7. **Линт поймал своё:** `JSON.stringify` в `gate.ts` (ADR-0007 §3 / `S-01`). Заменён сборкой
   имени из полей.

## 7. Правки реестра инвариантов

**Счёт `guarded` не меняется: 56.** Переходов нет.

* **R3** — пометка: «вход написан и покрыт (`requestFiles`, `templates-spec`), вызывающего нет
  (`H-01`/`CP-06`)»;
* **R12** — пометка: «вход написан и покрыт (`assertBuildMayStart`, `templates-spec`),
  вызывающего нет (`L-01`)»; названо, что проверяется ПАРА, что `FLAKY-по-контейнеру` не
  пропускается и что на фикстуре функция ПАДАЕТ;
* **K6** — пометка без смены статуса: за именем `templateRegistryVersion` в allowlist впервые
  стоит реестр, и строка сверяется с фикстурой тестом (поправка владельца П2). Статус не
  меняется: вторая половина K6 по-прежнему требует самого отпечатка (`H-03`);
* **D5** — пометка без смены статуса: `easingIds` манифеста несёт идентификаторы кривых, но
  проверяется только форма; членство — `TS-02`.

Ни один охранник не удалён и не ослаблен.

## 9. Кандидаты в правку документов (сами документы не правились)

### roadmap §3 — новая строка `CP-06`

Решение владельца 2. Форма строки:

```
| `CP-06` | compile | t | `TS-01`, `CP-05` | компилятор потребляет контракт шаблона:
валидация `params` схемой в `readDirection`/`compose`, `declareAssets` → sha в IR,
`declareFonts` → `fonts` в IR, длительность из объявленного параметра, `purposes` → seed'ы |
запись фикстуры не проходит схему своего шаблона ⇒ ошибка компиляции; `fonts` IR непуст на
`captionEmphasis@1` | (R3, D1 перечитан) | 2 | закрывает №35 целиком, №119, №120, №135, №136,
№139, №141; **тест D1 перечитывается, а не подгоняется** |
```

**Коллизия имён, которую обязан развести владелец:** имя `CP-06` в roadmap §3 **уже занято** —
строка 263, «Policy Guard (MVP-объём)», срез `mvp`. Предложение: новая задача получает имя
**`CP-07`**, либо Policy Guard переименовывается. Молча переиспользовать номер нельзя: дрейф
roadmap §9 уже содержит два случая, где адрес долга достался строке от СТАРОГО значения имени
(№8, №92, №128 — «адрес достался от старого значения `CP-05`').

### roadmap §4.8 `TS-01` — таблица полей манифеста

1. **`determinismClass` убрать из таблицы полей** и записать производным (решение владельца 3):
   «класс живёт в каждой записи гейта; уровень манифеста — `worst(gates)`, без записей —
   `UNGATED`, и он НЕ хранится».
2. **`gate: {…}` → `gates: GateRecord[]`, 0..2, по одной на профиль** — таблица несёт форму в
   единственном числе, а решение владельца 12 (RM1) уже сказало «записей ровно две».
3. **Добавить `purposes[]`** (ADR-0007 §1) и **`forkedFrom?`** (ADR-0008) — оба поля санкционированы
   заданием, но в таблице §4.8 их нет.

### ADR-0008 (не правился)

* «Декларация ресурсов шаблона» — записать, что `AssetRef` есть **alias-форма**: шаблон
  объявляет alias каталога, sha разрешает компилятор (`resolveAlias`, `M-02`). Сегодня ADR
  говорит `declareAssets(params) → AssetRef[]`, не называя, что в `AssetRef`;
* «Оспариваю V3» — записать, что **наличие `forkedFrom` и есть признак локальности**
  (namespace отдельным полем не хранится), и назвать функцию хэша `forkedFrom.hash` (№150).

### ADR-0007 §1 (не правился)

* Записать, что **перечень `purpose` объявляется манифестом шаблона** — сегодня §1 даёт только
  пример `'kenburns.jitter'`, а место, где перечень живёт, не названо (это и породило №135).

## 10. Известные ограничения

1. **Кода шаблонов нет.** Пять спеков — контракт, а не реализация: ни CSS, ни разметки, ни
   GSAP-таймлайна. Их пишут `E-*`/`H-06`.
2. **Реестра easing нет** (`TS-02`): `easingIds` проверяется по форме, не по членству.
   `kenburns@1` принимает ровно `power2.inOut`, потому что схема и манифест построены из ОДНОЙ
   константы, — но что эта строка законна в реестре D5, здесь никем не проверено.
3. **Записей гейта нет ни одной.** `gates: []` у всех пяти — рендерера нет, прогонов не было.
4. **Оба входа без вызывающих.** R3 и R12 остаются `named`.
5. **`fit`/`style` — списки из одного значения** (№151).
6. **Долг №6 не закрыт:** `rootDir: '.'` у `templates-spec` смещает `main` в `dist/src/`, как у
   `voice`/`media`/`compile`. Новая строка не заводится — тот же долг.
