# SP-2 — что измерено и что из этого следует

Пометки по Charter §7: **FACT** — измерено, число лежит в `results/`; **INFERENCE** — вывод из
измеренного; **UNKNOWN** — не измерялось и не выводится. Числа — в [summary.md](summary.md),
сырьё — в [raw/](raw/), журнал — в [PROGRESS.md](PROGRESS.md).

**Спайк только отвечает на вопросы.** Ни один ADR и ни одна строка Charter здесь не меняются:
решения принимает владелец отдельным коммитом.

**Условие, общее для всего документа.** Голос из задания
(`Michael C. Vincent — Confident, Expressive`, `category: professional`) на тарифе Free через API
недоступен: HTTP 402 `paid_plan_required`, списано 0. Замеры сняты на
`Daniel — Steady Broadcaster` (`category: premade`). Что от этого зависит, а что нет, разобрано
в [voice-and-tier.md](voice-and-tier.md) и повторено ниже в каждом затронутом разделе.

## U4 — тождество `characters.join('') === input`, единица массива, лид-ин/хвост

### U4.1 Тождество выполняется

**FACT.** На 28 строках, покрывающих F1–F16 из ADR-0010 §10 плюс числа, даты, деньги и дату
`03/04`, `alignment.characters.join('')` **побайтово равен отправленному тексту — 28 из 28**.
Ни одна ловушка его не сломала, включая NFD-диакритику, NBSP, суррогатную пару, эмодзи с
модификатором тона, curly quotes, эллипсис одним символом, URL и все числовые классы.
Попутно: три массива `alignment` одной длины во всех 28 случаях, `start` неубывает и
`start[i] ≤ end[i]` во всех 28. Файл: [raw/block1-block2.json](raw/block1-block2.json).

**FACT.** То же тождество держится на длинных чанках: 202, 403, 810 и 1514 символов —
`charIdentity` истинно на всех четырёх ступенях ([raw/block4-health.json](raw/block4-health.json)).

**INFERENCE.** `charIdentity` из ADR-0010 §1 — не «защита от вероятного», а **дешёвый ассерт на
редкое событие**. Это не довод его убрать: гарантия по-прежнему нигде не декларирована
(`FACT` r1 §1.4), а цена проверки — одно сравнение строк.

**INFERENCE.** Риск, записанный в ADR-0010 («если SP-2 покажет, что `charIdentity` не
выполняется на английском даже при `off`, придётся ужесточать линт либо включать fuzzy-алигнер»),
**не реализовался**. Fuzzy-алигнер original↔normalized в v1 не нужен ни как дефолт, ни как
включаемая опция для ElevenLabs.

**UNKNOWN.** Поведение при `alignment: null` (оба поля nullable, `FACT` r1 §1.3) не наблюдалось:
за 49 успешных вызовов `alignment` пришёл всегда. Это не значит, что он приходит всегда —
приёмка обязана обрабатывать `null`, и в `tts:mock@1` соответствующий тест написан.

### U4.2 Единица массива — code points

**FACT.** Длина `alignment.characters` совпала с числом **code points** входа во всех 28 строках;
с числом UTF-16 units — в 26; с числом графем — в 26. Три строки различают гипотезы, и все три
дают один ответ:

| строка | UTF-16 | code points | графемы | массив |
|---|---|---|---|---|
| `cafe`+U+0301 (NFD) | 45 | 45 | 44 | 45 → не графемы |
| `🚢 ahead` | 43 | 42 | 42 | 42 → не UTF-16 |
| `👍🏽 ok` | 47 | 45 | 44 | 45 → не UTF-16 и не графемы |

**FACT.** Тот же счётчик используется в **тарификации**: сумма code points по всем отправленным
строкам = **5222** = списанию провайдера (`character_count` 605 → 5827); сумма UTF-16 units = 5225 и
списанию не равна. Разница ровно 3 приходится на две строки с эмодзи (−1 и −2).

**INFERENCE.** Это прямо поддерживает F13 из ADR-0010 §10: span-map трансдьюсера обязана быть
монотонной **в code points**, а не в UTF-16 units. Реализация, индексирующая spoken-текст через
`str[i]` или `str.length`, разъедется с `alignment` на первом же эмодзи — и разъедется молча,
потому что `charIdentity` при этом останется истинным.

**INFERENCE.** Практическое следствие для кода: индексация spoken-текста ведётся по
`[...text]` (или по итератору строки), а `Intl.Segmenter` в движке не нужен вовсе —
он дал бы **неверную** единицу. Это удачно совпадает с запретом `Intl` из Charter V8.

### U4.3 Лид-ин и хвост: таймкоды говорят «ноль», аудио говорит другое

**FACT.** По таймкодам `start[0] = 0` ровно у **28 из 28** строк; `audioDuration − end[last]`
имеет медиану 0.042 мс и весь разброс в пределах ±0.5 мс. То есть alignment по своей арифметике
покрывает возвращённое аудио целиком, без зазоров с обеих сторон.

**FACT.** По самому PCM (RMS, окно 10 мс, порог −45 dBFS) на тех же 28 файлах:
акустический лид-ин — медиана **100 мс** (40–110), акустический хвост — медиана **310 мс**
(245–392). Файл: [raw/block2-acoustic.json](raw/block2-acoustic.json).

**FACT.** Эта тишина приписана крайним символам: длительность **первого** символа — медиана
93 мс (46–128), длительность **последнего** — медиана 337 мс (278–395). У обычных букв в
середине строки длительность порядка 23–120 мс.

**INFERENCE — и это главный результат спайка.** Формулировка T7 (ADR-0003) —
«PCM обрезается до `[start первого токена, end последнего токена]`, после чего вся тишина между
чанками принадлежит движку» — **работает наполовину**:

* **хвост снимается.** Последний символ прозы — точка, а точка по правилу интервала токена
  (D10 п.6) в слово не входит. Конец последнего слова оказывается на ~314 мс раньше конца файла,
  и обрезка действительно срезает провайдерский хвост.
* **лид-ин не снимается.** `start[0] = 0` **всегда**, поэтому «start первого токена» — это
  нулевой сэмпл, и обрезка слева удаляет ровно ноль. Медианные 93 мс тишины остаются **внутри**
  интервала первого слова чанка.

**INFERENCE.** Цена этого — два разных дефекта, и оба выше бюджета AC5 (p95 ≤ 80 мс):

1. **привязка первого слова каждого чанка уезжает вперёд на 46–128 мс.** Субтитр появляется
   раньше звука. Остальные слова чанка не затронуты — у них старты честные.
2. **`[pause: 400ms]` даёт не 400 мс.** К заказанной паузе добавляется несрезанный лид-ин
   следующего чанка. На ролике из ~8 чанков это ~0.7 с незаказанной тишины, распределённой по
   границам абзацев. Именно это T7 и был написан предотвратить.

**INFERENCE, кандидат в решение (за владельцем).** T7 должен обрезать голову **по акустике**, а
не по таймкодам: детектор начала энергии на импорте дубля, результат — в `leadInSamples`.
Константу вместо детектора брать нельзя: разброс 40–110 мс шире, чем весь бюджет AC5.
Хвост при этом можно продолжать снимать правилом D10 п.6 — но см. следующий пункт.

**FACT.** Если чанк кончается **не пунктуацией**, хвост достаётся последней **букве**, и правило
D10 п.6 его не снимает: на строке `The pilot called out one last time` (без точки) правило
срезало **0.4 мс** вместо 313.9 мс, и **278 мс тишины осталось внутри интервала последнего
слова**. Контрольная строка с точкой на том же материале — 313.9 мс срезано, 11 мс осталось.
Файл: [raw/block2b-nopunct.json](raw/block2b-nopunct.json).

**INFERENCE.** В нашем формате чанк = абзац, а абзац прозы кончается точкой, поэтому штатно
этот случай не наступает. Но он наступает при делении абзаца по `[pause:]`, если автор поставил
паузу не на границе предложения, и при чанке, кончающемся на `[say:]`. Дешёвая защита: ассерт на
импорте дубля «последний символ spoken-текста — пунктуация, иначе применить акустическую обрезку
хвоста тоже». Это тот же детектор, что нужен для головы.

**FACT.** У 12 строк из 28 `end[last]` **превышает** длину PCM, максимум на **12 сэмплов**
(0.5 мс). Ассерт T7 `end[last] ≤ numSamples` в буквальном виде **упал бы** на 12 строках из 28.

**INFERENCE.** Ассерту нужен допуск. Разумная форма: `end[last] ≤ numSamples + ⌈sampleRate/1000⌉`
(один миллисекундный запас на округление), а не точное неравенство.

**Голосозависимость.** Числа 100 мс, 310 мс, 93 мс, 337 мс — характеристика темпа диктора и на
боевом голосе будут другими. Структура (тишина существует; она приписана крайним символам;
`start[0] = 0`) — `INFERENCE` — структурна и голосом определяться не должна. Перемер блока 1 на
боевом голосе стоит 1215 кредитов.

## U16 — что делает `apply_text_normalization: "off"` с английскими числами

**FACT.** `alignment` равен входу побайтово у всех 28 строк, включая все девять числовых классов:
`Dr. Smith`, `in 1793`, `the 3rd of May`, `21st century`, `$5`, `5%`, `03/04`, `1,000,000`, `3.14`.

**FACT.** `normalized_alignment` не равен входу **ни в одной** из 28 строк. Но у 20 строк
единственное отличие — **по одному пробелу с каждого края** (форма паддинга `1/1` у всех 28).

**FACT.** Настоящие подстановки в `normalized_alignment` есть у 8 строк, и **ни одна из них
не касается чисел**:

| вход | становится |
|---|---|
| `’` U+2019 | `'` U+0027 |
| `—` U+2014 | `--` |
| `–` U+2013 | `-` |
| `“` `”` | `"` |
| `…` U+2026 | `...` |
| NBSP U+00A0 | пробел U+0020 |
| `🚢`, `👍🏽` | удалены |

**FACT.** Все девять числовых классов доходят до `normalized_alignment` **дословно** — после
снятия обрамляющих пробелов строка равна входу.

**INFERENCE.** `apply_text_normalization: "off"` действительно **выключает нормализатор
чисел, дат, денег и сокращений**. Но он не выключает второй, отдельный слой — **канонизацию
типографики и удаление непроизносимых символов**, — и этот слой виден только в
`normalized_alignment`. Это уточняет `FACT` r1 §1.4 («нормализатор переписывает текст»):
переписывателей два, и `off` гасит только один.

**INFERENCE.** Для движка это безопасно ровно потому, что привязки строятся по `alignment`, а не
по `normalized_alignment`. `normalized_alignment` проекту **не нужен вообще** и не должен
попадать ни в дубль, ни в приёмку: его единственная роль — окно в чужой нормализатор.

**INFERENCE — прямой ответ на критерий core.md §16.** Критерий сформулирован так: «если при `off`
строка возвращается побайтово равной входу для всех шести классов — линт-запрет цифр остаётся как
есть, и Charter V5 закрывается без изменений». Проверены все шесть названных классов
(`1793`, `3rd`, `$5`, `5%`, `03/04`, `Dr.`) плюс три сверх списка. **Все девять равны входу
побайтово.** Смягчение по этому критерию возможно только в третьем случае — «`off` честно не
трогает текст **и** доля токенов под запретом велика». Доля измерена в блоке 9 и составляет
**1.20 %** при пороге ADR-0002 «> ~2 %». Второе условие **не выполнено**.

**Вывод по U16:** линт-запрет цифр **остаётся как есть**, пометка-вопрос Charter V5 закрывается
**отрицательно** — смягчения нет. Решение — за владельцем, отдельным коммитом.

**Оговорка, которую нельзя опускать.** Доля 1.20 % посчитана на **единственном** английском
драфте репозитория (166 токенов), и этот драфт написан **уже под линт**: автор трижды применил
`[say:]`, то есть выборка систематически смещена в сторону «запрет соблюдаем». Число 1.20 % —
нижняя оценка. Верхняя граница на том же тексте (если считать сокращением каждый токен с точкой
на конце) — 6.63 %. Честный вывод: доля **скорее всего** ниже порога, но одного фикстурного
абзаца для этого утверждения мало. Настоящая проверка — первый живой LLM-драфт.

**Не выполнено по сравнению с core.md §16.** Прогон того же текста с `apply_text_normalization:
"auto"` для сравнения `off` vs `auto` **не делался**: задание SP-2 фиксирует параметры платных
вызовов и прямо запрещает менять их между блоками. Это записано в [decisions.md](decisions.md) п.4
и в долги. Цена досъёмки: 6 строк × ~45 симв. ≈ **270 кредитов**.

## U6 — безопасный предел длины чанка по качеству alignment

**FACT.** `uniqueTimestampRatio = 1.000` и `maxEqualRun = 1` на **всех** ступенях: 202, 403, 810 и
1514 символов, что дало 14.6, 28.6, 59.3 и **113.7 секунды** аудио. `charIdentity` истинно на всех
четырёх. Порог деградации `ratio < 0.9` не достигнут.

**INFERENCE.** Картина деградации из r1 §2.1 (падение до 1–3 % уникальных таймстемпов после
~250 символов / ~15 с) на `eleven_multilingual_v2` **не воспроизводится**. Это согласуется с
источником: issue #707 и #760 заведены на `eleven_v3` и `text-to-dialogue`. Решение ADR-0010
(«не брать v3, пока #707 открыт») измерением **подтверждено**, а не просто сохранено.

**INFERENCE.** Проверенный потолок — 1514 символов / 113.7 с — с большим запасом перекрывает
рабочий диапазон: абзац ролика AC1 (~150 слов на ролик целиком) до него не дотягивается на
порядок. Безопасный предел деления абзаца (D10 п.3) **упирается не в качество alignment**.
Значит `maxChunkChars` в профиле остаётся, но его значение выбирается из других соображений —
просодия, стоимость перегенерации, гранулярность AC3 — а не из здоровья таймкодов.

**FACT.** На здоровом материале `uniqueTimestampRatio` равен **ровно 1.000**, а `maxEqualRun`
равен **1** — у 26 строк из 28. Обе строки с `ratio < 1` — строки с **эмодзи**, и причина у них
одна: непроизносимые code points получают интервал **нулевой длины** и делят старт с соседом.
`🚢` даёт `ratio` 0.976 и `maxEqualRun` 2 (нулевой пробел после эмодзи); `👍🏽` даёт 0.956 и 3
(нулевые модификатор тона и пробел). Ни одна строка без эмодзи ниже 1.000 не опустилась.

**INFERENCE.** Порог приёмки можно держать **высоким**: рабочая точка — 1.000, а порог 0.9 из
задания лежит от неё далеко и сработает только на настоящей патологии, то есть ложных
срабатываний не даст. `maxEqualRun` — тот же вывод, но с оговоркой: **агрессивный порог по
`maxEqualRun` спотыкается об эмодзи**. Порог-кандидат ADR-0010 (8) безопасен; порог 2 сломал бы
приёмку на любом абзаце с эмодзи. Эмодзи в прозе линтом ADR-0002 §3 **не запрещены**, так что
случай достижим.

**INFERENCE.** Отдельное следствие для стадии `bind`: непроизносимый символ приходит с интервалом
нулевой длины, а не отсутствует. Значит токен, состоящий только из таких символов, обязан
получать `status: 'absent'` (ADR-0010 §5), а не интервал `[t, t]`, — иначе субтитр получит слово
нулевой длительности и это пройдёт мимо всех проверок.

**UNKNOWN.** Не проверено, что происходит **выше** 1514 символов — в частности, вблизи
2674 символов / 60 с, где issue #707 фиксировал залипание у v3. Досъёмка одной ступени 2700
символов стоит **2700 кредитов** и в бюджет спайка не влезала.

**UNKNOWN.** Не проверено поведение при **многократных** длинных запросах подряд и под нагрузкой
аккаунта — деградация в issue #760 описывалась как зависящая от суммарной длительности сессии,
а не только от одного запроса.

## D10 п.6 — куда падает межпредложенческая пауза

**FACT.** На одной фразе с пятью разделителями пауза между `stop` и `then` целиком лежит на
**знаке и пробелах**; ни буква перед разделителем, ни буква после не удлиняются:

| разделитель | пауза всего | на знаке | на пробелах | доля на знаке |
|---|---|---|---|---|
| `, then` | 453 мс | 174 | 279 | 0.384 |
| `; then` | 476 мс | 151 | 325 | 0.317 |
| `. Then` | 499 мс | 174 | 325 | 0.349 |
| ` — then` | 557 мс | 58 | 174 + 325 | 0.104 |
| `… then` | 673 мс | 232 | 441 | 0.345 |

**FACT.** Длительность буквы **до** разделителя по пяти вариантам: 82–117 мс, разброс **35 мс**.
Длительность буквы **после**: 23–58 мс, разброс **35 мс**. Обе величины остаются в обычном
диапазоне букв и от знака практически не зависят.

**INFERENCE.** Правило ADR-0010 §6 — «интервал = [start первого небелого символа, end последнего
небелого символа]; пробелы и пунктуация в интервал слова не входят» — **верно и достаточно**.
Оно исключает ровно те две категории символов, на которые провайдер и кладёт паузу.
Формулировка «куда падает пауза — на точку, на пробел или распределяется» получает ответ
**«на точку и на пробел, в переменной пропорции, и НЕ распределяется по соседним словам»** —
а переменность пропорции для правила безразлична, потому что обе категории исключены.

**INFERENCE.** Ранжирование пауз по знакам даёт автору управляющий рычаг без единого нового
маркера: `,` 453 → `;` 476 → `.` 499 → `—` 557 → `…` 673 мс. Разница между запятой и эллипсисом —
**220 мс**, то есть сопоставима с `defaultParagraphGapSamples` (180 мс, ADR-0003 T8). Это стоит
записать в документацию формата: пунктуация — уже работающий инструмент тайминга.

**Голосозависимость.** Абсолютные значения (453–673 мс) — характеристика диктора. Структурный
вывод (пауза не попадает в слово) — `INFERENCE` — голосом определяться не должен.

## U5 — слышимость отказа от `request_ids`

**FACT.** `previous_text` / `next_text` **влияют на звук**: PCM отдельного предложения не совпал
с версией без контекста **ни разу** из трёх, а длительность отличается до **139.3 мс (3.06 %)**.

**FACT.** Суммарная длительность склейки против одного запроса: с контекстом **−232 мс**, без
контекста **−464 мс** (эталон 15.093 с).

**INFERENCE.** Контекст **восстанавливает примерно половину** того, что теряется при разбиении:
из 464 мс расхождения с одиночным запросом 232 мс возвращаются просто передачей соседних
предложений. Это объективное свидетельство, что `previous_text`/`next_text` — не декоративный
параметр, и что решение ADR-0010 §4 (стичинг только текстом) имеет измеримое основание.

**FACT.** `previous_text` и `next_text` **не тарифицируются**: 264 символа контекста не попали
в списание (5222 = сумма code points только полей `text`).

**INFERENCE.** Стичинг текстом **бесплатен**. Довод «контекст стоит денег» из рассмотрения
исключается целиком; остаётся только довод про ключ кэша (ADR-0006), и он не про деньги.

**UNKNOWN — и остаётся UNKNOWN по построению.** Слышна ли разница на шве — вопрос к ушам, и
спайк его не решает. Файлы готовы:

* `out/b5-a.wav` — эталон, три предложения одним запросом;
* `out/b5-b.wav` — три запроса с `previous_text`/`next_text`, склеены встык, швы на **4.690 с** и **10.263 с**;
* `out/b5-c.wav` — три запроса без контекста, склеены встык, швы на **4.551 с** и **10.124 с**.

Слушать на отметках шва: скачок высоты или громкости, оборванная интонация конца фразы, разная
скорость соседних предложений. Если разница между `b` и `c` не слышна — вопрос о fallback-ключе
кэша (смежное предложение в `voiceKey`, ADR-0006) закрывается отрицательно и `conditionedOn`
остаётся чисто диагностическим полем.

## Детерминизм seed

**FACT.** Три вызова одной строки с одним `seed: 20260821` и совпадающими параметрами дали
**побайтово одинаковый PCM** (sha256 совпал 3/3, длина 117 029 сэмплов у всех трёх) и **побайтово
одинаковый `alignment`**.

**INFERENCE.** Это **не** опровергает `FACT` (r1 §2.3) «Determinism is not guaranteed»: вендор
даёт best-effort, три совпадения подряд best-effort не отменяют. Практический вывод обратный и
скучный: **на детерминизм нельзя опираться, но и лестница ретраев ADR-0010 §1 не бесполезна** —
если бы ответ был случаен, ретрай того же запроса не имел бы смысла; раз он в норме
детерминирован, ретрай проверяет именно сбой, а не подбрасывает монету.

**INFERENCE.** Для AC4 это ничего не меняет: аудио остаётся закоммиченным артефактом, а не
результатом вызова на рендере (V9). Совпадение sha256 — приятный факт, а не разрешение
ходить в сеть.

## C1 — словарь произношения с alias

**FACT.** Замер **не выполнен**. `POST /v1/pronunciation-dictionaries/add-from-rules` вернул
**HTTP 401**: `The API key you used is missing the permission pronunciation_dictionaries_write`.
Списано 0. Словарь не создавался, удалять было нечего.

**FACT.** Это ограничение **прав API-ключа**, а не тарифа: сообщение говорит о разрешении ключа,
а не о плане (сравни с 402 `paid_plan_required` на голосе).

**UNKNOWN.** Сохраняется ли `charIdentity` при включённом alias-правиле — **не измерено**.
Запрет alias в ADR-0010 §7a остаётся обоснованным **рассуждением** (alias меняет длину
нормализованного текста ⇒ тождество обязано нарушиться), но не измерением. Досъёмка: включить
`pronunciation_dictionaries_write` в дашборде ElevenLabs, затем `./run.sh block7.mjs` —

**INFERENCE.** Косвенное свидетельство в пользу того же вывода спайк всё-таки даёт: блок 1
показал, что `alignment` **не отражает** ничего из того, что делает нормализатор — все
подстановки видны только в `normalized_alignment`. Если словарь работает на том же слое, alias
проявится в `normalized_alignment` и **не** сломает `charIdentity`. Если он работает раньше —
сломает. Различить эти две гипотезы без замера нельзя, поэтому это `UNKNOWN`, а не `INFERENCE`.

## Тарификация и учёт (побочные факты, полезные движку)

**FACT.** Тарификация — по **code points** отправленной строки. Поштучного минимума на запрос
нет: первая строка в 46 символов списала ровно 46.

**FACT.** `previous_text` / `next_text` не тарифицируются (264 символа контекста — 0 списания).

**FACT.** `GET /v1/user/subscription` обновляет `character_count` **с задержкой 20–40 секунд**.
Дельта, снятая вокруг вызова, читается как 0.

**INFERENCE.** Поле `billedUnits` в provenance дубля (ADR-0010 §2) **нельзя** заполнять дельтой
подписки вокруг запроса — там будет ноль. Его надо заполнять числом code points отправленного
`spokenChunkText`, а подписку использовать только как редкую сверку на границе сборки.
Заодно это делает `billedUnits` вычислимым офлайн и проверяемым тестом.
