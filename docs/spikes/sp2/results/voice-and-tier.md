# Почему голос из `.env` не сработал и что изменится, если купить подписку

Файл написан по прямой просьбе владельца. Он не содержит измерений — только объяснение
одной ситуации, из-за которой спайк снимался не тем голосом, который был задан.

> **Дописано после досъёмки SP-2b (тариф Creator, 2026-08-20).** Прогноз этого файла проверен
> измерением на боевом голосе. Таблица §4.1 («что не изменится») подтвердилась **на 8 строках
> из 12**: две строки опровергнуты — ставка тарификации оказалась свойством **тарифа**
> (Free ×1.00, Creator ×0.55), а ранжирование пауз по знакам — свойством **голоса**; две строки
> не перемерялись. Все величины таблицы §4.2 («что придётся перемерить») действительно
> изменились. Оценка стоимости перемера (§4.2: ≈1440 кредитов) сошлась: блоки 1 и 3 стоили
> 1433 отправленных code points. Прогноз §4.4 («подписка не починит блок 7») подтвердился:
> право ключа так и не появилось. Числа и разбор — в
> [findings.md, раздел «Досъёмка SP-2b: боевой голос»](findings.md#досъёмка-sp-2b-боевой-голос).

---

## 1. Короткий ответ

**`ELEVENLABS_VOICE_ID` в `.env` правильный, и он был использован правильно.** Дело не в id.
Дело в том, к какому **классу** принадлежит голос с этим id, и что этот класс запрещён на
тарифе Free при обращении **через API**.

Ответ провайдера дословно:

```
HTTP 402
{"detail":{"type":"payment_required","code":"paid_plan_required",
 "message":"Free users cannot use library voices via the API.
            Please upgrade your subscription to use this voice."}}
```

Списано за этот вызов: **0 кредитов**. Отказ приходит до того, как что-либо синтезируется.

---

## 2. Почему id тут ни при чём

У ElevenLabs голоса делятся на классы, и класс лежит в поле `category` ответа
`GET /v1/voices/{id}`. Для нашего голоса:

```
name     : Michael C. Vincent - Confident, Expressive
category : professional
sharing  : { status: "copied", public_owner_id: <есть> }
```

`category: professional` + `sharing.status: copied` означает: это **чужой голос из Voice
Library**, который был добавлен («скопирован») в твой аккаунт. В веб-интерфейсе он выглядит
как «твой» — он есть в списке, им можно озвучить текст на сайте. Но у API отдельное правило:
библиотечные голоса (`professional`, а также клонированные) **на Free через API не работают**.

То есть расхождение не «id неверный», а «id верный, но за ним стоит голос того класса,
который твой тариф не пускает в API». Проверить класс можно бесплатно:

```bash
curl -s -H "xi-api-key: $ELEVENLABS_API_KEY" \
     https://api.elevenlabs.io/v1/voices/$ELEVENLABS_VOICE_ID | jq '.name, .category'
```

В аккаунте одновременно есть **21 голос с `category: premade`** — это встроенные голоса
ElevenLabs (Roger, Sarah, George, Daniel, Brian, Adam и так далее). Они на Free через API
работают без ограничений. Именно поэтому спайк не встал совсем.

---

## 3. Что сделано вместо

Спайк снят на **`Daniel — Steady Broadcaster`** (`category: premade`), выбранном как ближайший
к «Confident, Expressive» по регистру и темпу: мужской, ровный дикторский.

Как это устроено в коде, чтобы не создать вторую проблему:

* `.env` **не читался и не менялся** — там по-прежнему лежит боевой voice_id;
* голос спайка резолвится **по имени** через `GET /v1/voices` на каждом запуске
  (`lib/voice.mjs`), поэтому в репозитории нет ни одного захардкоженного секрета;
* id премейд-голоса записан в `machine.json` открыто — он публичен в документации
  ElevenLabs и нужен для воспроизводимости замера. Боевой id из `.env` не записан нигде.

## 4. Что будет, если купить подписку

Разделим находки спайка на две группы. Это главное, ради чего файл написан.

### 4.1 Что НЕ изменится — эти числа и выводы переносятся на боевой голос как есть

Всё перечисленное — свойства **эндпоинта, модели и нормализатора**, а не тембра. Смена
голоса и смена тарифа их не трогают.

| Находка | Почему не зависит от голоса |
|---|---|
| `alignment.characters.join('') === input` выполняется (28/28) | это контракт эндпоинта при `apply_text_normalization: "off"`; голос в него не входит |
| Массив `alignment` приходит в **code points** | свойство сериализации ответа API |
| Тарификация идёт по **code points**, а не по UTF-16 units | свойство биллинга |
| `previous_text` / `next_text` **не тарифицируются** | свойство биллинга |
| `normalized_alignment` переписывает `’ → '`, `— → --`, `– → -`, `“” → "`, `… → ...`, NBSP → пробел, эмодзи выбрасывает, добавляет по пробелу с краёв | свойство слоя канонизации текста, общего для всех голосов |
| При `off` **не переписываются** числа, годы, порядковые, `$`, `%`, даты, сокращения с точкой | то же — свойство нормализатора |
| Деградации `uniqueTimestampRatio` нет до 1514 симв. / 113 с | свойство модели `eleven_multilingual_v2`; на платном тарифе модель та же |
| Пауза ложится на **знак и пробел**, соседние буквы её не забирают | структурное свойство разметки, а не тембра |
| Тишина в начале приписывается **первому символу**, в конце — **последнему** | структурное свойство разметки |
| Одинаковый `seed` дал побайтово одинаковый PCM 3/3 | свойство инфраструктуры модели |

`INFERENCE` для трёх последних строк: они структурны, но проверялись на одном голосе.
Вероятность, что структура поменяется от тембра, низкая; доказательства этому спайк не даёт.

### 4.2 Что ПРИДЁТСЯ перемерить на боевом голосе

Всё, что выражено в **миллисекундах**. Темп речи и длина пауз — это и есть характер голоса.

| Число | Измерено на Daniel | Почему зависит от голоса |
|---|---|---|
| акустический лид-ин | медиана **100 мс** (40–110) | сколько диктор «набирает воздух» перед первым словом |
| акустический хвост | медиана **310 мс** (245–392) | как долго он держит конец фразы |
| длительность первого символа (он и несёт лид-ин) | медиана **93 мс** (46–128) | то же |
| длительность последнего символа (он несёт хвост) | медиана **337 мс** (278–395) | то же |
| межпредложенческая пауза по знакам | `,` 453 · `;` 476 · `.` 499 · `—` 557 · `…` 673 мс | темп |
| скорость речи | 13.3–14.1 символа/с | темп |

Это **не** повод переделывать спайк целиком: перемерить нужно ровно блок 1 (28 строк, 1215
символов) и блок 3 (5 строк, 221 символ) — суммарно **≈ 1440 кредитов**, полчаса работы.
Блоки 4, 5, 6, 8, 9 переснимать не нужно: их выводы попадают в таблицу 4.1.

### 4.3 Что ещё откроется на платном тарифе

* **Библиотечные голоса через API** — собственно то, ради чего покупается подписка.
* **`pcm_44100` и `wav_44100`** требуют тарифа **Pro и выше** (не Starter). Пока проект
  живёт на `pcm_24000`, и ADR-0010 §9 это уже зафиксировал.
* **Коммерческие права на аудио** даёт только платный план — это отдельно записано в
  Charter/ADR-0010 (`planTierAtGeneration` в дубле существует ровно для этого).
* Лимит символов вырастет: сейчас `character_limit = 10000`.

### 4.4 Чего подписка НЕ починит

**Блок 7 (словарь произношения) упал не из-за тарифа, а из-за прав ключа:**

```
HTTP 401
"The API key you used is missing the permission
 pronunciation_dictionaries_write to execute this operation."
```

Это область действия **API-ключа**, а не план. Чинится в дашборде ElevenLabs
(ключ → права → включить `pronunciation_dictionaries_write`) и на Free тоже. После этого блок 7
стоит ещё **76 кредитов** и два бесплатных вызова.

## 5. Что положить в проект по итогам

`INFERENCE`, решение за владельцем:

1. В `provenance` дубля (ADR-0010 §2) рядом с `voiceId` имеет смысл держать **`voiceCategory`**.
   Тогда «дубль снят премейдом» и «дубль снят боевым голосом» различимы задним числом, а не
   восстанавливаются по дате.
2. Константы `audioProfile`, выраженные в миллисекундах (лид-ин, хвост, дефолтные паузы),
   стоит пометить как **привязанные к паре (голос, модель)**: смена голоса обязана
   инвалидировать их так же, как смена модели.
3. `vpe doctor` (или что займёт его место) может делать один бесплатный
   `GET /v1/voices/{id}` и падать заранее с понятным текстом, если `category` голоса
   несовместима с текущим тарифом. Сегодня это выясняется только первым платным вызовом.
