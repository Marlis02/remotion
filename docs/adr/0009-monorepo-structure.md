# ADR-0009 — Монорепо: 17 пакетов, стрелки вниз, границы охраняются тестами

* **Статус:** принято (A1, 2026-08-19)
* **Связь с Charter:** V9, V10, §6 (pnpm workspaces)
* **Вход:** r2 §8.1/§9.1, r3 §6
* **Раздел архитектуры:** [core.md D9](../architecture/core.md#d9-монорепо-и-направление-зависимостей)

## Context

Направление зависимостей здесь — не стиль, а исполнимая формулировка двух вещей: V9 («рендерер
глупый») и страховки r2 §8.1 («не дать Remotion протечь в модель проекта»). Без тестов
зависимостей граница протекает за две недели: сначала «удобно импортировать тип из remotion»,
потом `assembly` начинает звать `combineChunks()`, и плана Б, ради которого вводился RenderIR,
больше нет. Дополнительно `FACT` (r3 §6): ruleset Policy Guard обязан быть **данными**, потому
что формулировки политик YouTube менялись в июле 2025 и июле 2026 — захардкоженные цитаты
протухают за один цикл и становятся хуже отсутствия.

## Decision

```
schema            → —                        zod, канонический JSON, blake3, branded-типы (Samples/Frames/Sha256)
core-model        → schema                   сущности ADR-0001, типы времени
store             → schema                   CAS, sha256, бэкенды (каталог/SSD/rclone/LFS)
provenance        → schema                   r3 §3.4: раздельные статусы произведения/репродукции/записи
script            → core-model               лексер, линт, span-map, ledger якорей
assets            → provenance, core-model, store   ingest, ресайз, aliases
tts               → core-model, provenance   провайдеры за интерфейсом, приёмка дублей, tts:mock
align             → core-model               bind: provider-timestamps | forced-alignment; контролёр AC5-b
audio             → core-model, store        PCM-сборка, микрофейды, микс, feature-track (ffmpeg)
templates-spec    → core-model               схемы params, declareAssets/declareFonts; БЕЗ react
timeline          → script, assets, audio, align, templates-spec, core-model
render-ir         → core-model, templates-spec      БЕЗ remotion, БЕЗ react
policy            → core-model, provenance          ruleset — ДАННЫЕ, не код
cache             → schema, store
templates-remotion→ templates-spec, remotion, react
renderer-remotion → render-ir, templates-remotion, remotion
assembly          → core-model, audio               ffmpeg; НЕ импортирует remotion
cli               → всё
```

Циклов нет; `cli` — единственный пакет, который знает про всех.

**Исполнимые тесты границ (не соглашения):**

1. `remotion` импортируют только `templates-remotion`, `renderer-remotion`, `cli`.
   В частности **`assembly` не импортирует remotion** — значит склейка только ffmpeg, и вопрос
   `combineChunks()` закрыт архитектурой, а не спайком.
2. `react` не импортируют `render-ir` и `templates-spec`.
3. `core-model` не импортирует `node:fs` (модель не умеет читать диск).
4. **Тест протечки профиля:** хэш RenderIR фикстуры не меняется при изменении любого поля
   `pixelProfile` (меняется только при изменении `compileProfile`). Это исполняемая версия
   ADR-0002 п.7 и плана Б из ADR-0008.
5. `SegmentRenderRequest` переживает JSON round-trip (защищает вынос рендера за процесс).
6. В пакете `policy` нет захардкоженных цитат политик: ruleset читается из версионируемого файла
   с `rulesetVersion` и `policySnapshotDate`.
7. Ни один пакет, кроме `tts`, не обращается к сети; `align` — только в реализации
   сетевого контролёра, помеченной `requiresNetwork: true`.

**Расположение `public/` для Remotion.** `FACT` (r2 §7.2): каталог `public/` обязан лежать рядом
с тем `package.json`, который содержит зависимость `remotion`, «even if your Remotion code lives
in a subdirectory». В pnpm-workspace это неочевидно и укусит при первой реорганизации, поэтому
фиксируется здесь: `public/` живёт в `packages/renderer-remotion/`, наполняется симлинками/копиями
из `.store` перед рендером сегмента и очищается после. Имена файлов внутри — **ASCII-safe по
sha256** (`FACT` r2 §7.2: `staticFile()` сам применяет `encodeURIComponent`, кодировать самому
нельзя), поэтому весь класс ошибок двойного кодирования исчезает.

## Alternatives

| Альтернатива | Почему могла быть лучше | Почему отклонена |
|---|---|---|
| **Один пакет с папками** | ноль накладных расходов, никаких `package.json` | тесты зависимостей невозможны в принципе ⇒ V9 и страховка r2 §8.1 остаются пожеланиями |
| **Пакет на сущность (~25)** | максимально мелкие границы | накладные расходы на одного разработчика превышают пользу; границы, которые никто не нарушает, охранять не нужно |
| **Отдельный пакет `ffmpeg-wrapper`** | ffmpeg используется и в `audio`, и в `assembly` | обёртка над CLI-бинарником на ~100 строк; при необходимости выносится позже без изменения стрелок |
| **`templates` одним пакетом (спека + реализация)** | меньше файлов | тогда `render-ir` (который зависит от спеки) потянул бы react и remotion — прямое нарушение главной границы |
| **`policy` зависит от `timeline`** | Guard читает Timeline | сделало бы `policy` зависимым от почти всего графа; вместо этого Guard получает Timeline как **значение** (структуру из `core-model`), а не как пакет |

## Consequences

**Положительные**

* Каждая стрелка соответствует строке «НЕ знает» из ADR-0001; модель охраняется механически.
* План Б по рендереру проверяем: тесты 1 и 4 доказывают, что смена бэкенда затрагивает один
  пакет.
* Ruleset как данные позволяет обновлять политики YouTube без релиза кода (r3 §6).

**Отрицательные**

* 17 `package.json`, 17 tsconfig-ссылок, шум в диффах при рефакторинге. Смягчается общим пресетом
  и тем, что половина пакетов — по 200–500 строк.
* `cli` знает про всех и рискует стать свалкой; правило: в `cli` только парсинг аргументов,
  оркестрация стадий и вывод — никакой доменной логики (проверяется размером и ревью).

**Риски**

* `timeline` зависит от шести пакетов и станет самым тяжёлым узлом графа. Это ожидаемо (он и есть
  компилятор), но если он начнёт расти быстрее остальных — признак того, что доменная логика
  утекает из специализированных пакетов.
* Локальные форки шаблонов (ADR-0008) — renderer-специфичный код **внутри проекта пользователя**,
  то есть исключение из теста 2 по расположению; тест должен различать пакеты монорепо и
  содержимое проектов.
