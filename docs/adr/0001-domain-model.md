# ADR-0001 — Доменная модель: три слоя и 36 сущностей

* **Статус:** принято (A1, 2026-08-19); правки RT-01 внесены в A2 (2026-08-19): `Lexicon` удалён (C1), добавлены `ChunkKey`/`VoiceKey` (C2), `AssetGrid` (M5), `PublishSpec` (C7), уточнены `Silence`, `Override`, `Clip`/`Segment`
* **Связь с Charter:** V1, V2, V3, V4, V9, V10
* **Вход:** `PROJECT_CHARTER.md`, r1 §1/§3, r2 §8.1, r3 §3.4/§5
* **Раздел архитектуры:** [core.md D1](../architecture/core.md#d1-domain-model)
* *Пометка 2026-08-21: упоминания рендерера ниже — **исторические**. Рендерер v1 — **HyperFrames** (решение владельца 1, [sp3-closure.md](../spikes/sp3-closure.md)); Remotion в v1 не реализуется. Текст документа не правится.*

## Context

Привычный набор видеоредактора (Project → Scene → Track → Clip → Asset) не отвечает на четыре
вопроса, которые в этом движке необратимы:

1. **Кто владеет временем.** Времён три: порядковое (слова, биты, сцены, главы), физическое
   (сэмплы) и кадровое. Если они живут в одном объекте, смена fps меняет слой, к которому
   привязаны ручные правки.
2. **Кто владеет идентичностью.** V1 требует, чтобы правка переживала регенерацию TTS. Это
   возможно только если у адресуемого объекта есть id, не производный от времени.
3. **Где граница «человек пишет» / «машина пишет».** V2 требует, чтобы generated-артефакты не
   правились руками; без явного списка это соглашение, а не свойство.
4. **Где кончается модель произведения и начинается модель рендера.** `FACT` (r2 §8.1): единственная
   реальная страховка от переписывания при смене рендерера — renderer-agnostic IR.

## Decision

**Три слоя модели:**

| Слой | Единица времени | Знает | Не знает |
|---|---|---|---|
| **Score** (авторский) | порядковая | прозу, режиссуру, якоря | сэмплы, кадры |
| **Timeline** (физический) | **сэмплы** | клипы, треки, привязки, ассеты | fps, кодеки, шаблонную реализацию |
| **RenderIR** (кадровый) | **кадры**, segment-relative | геометрию, seed'ы, ссылки на ассеты | Remotion, React, сеть, якоря, сэмплы |

**Сущности и «чего НЕ знает»** (полный список; сокращённая версия — в core.md D1):

| Сущность | Ответственность | Вход → выход | НЕ знает |
|---|---|---|---|
| `Project` | константы произведения: `fps{num,den}`, `width/height`, `projectSampleRate`, `seedRoot`, `channelId`, ссылки на профили | `project.yaml` → объект | рендерер, TTS-провайдера, раскладку кэша |
| `Chapter` | редакторская единица; жёсткий барьер V4 | сцены → упорядоченный список | абсолютное время, соседние главы |
| `Scene` | единица авторства, scope локальных id, кандидат на разрез сегмента | проза + режиссура → сцена | кадры, сэмплы |
| `Paragraph` | структурная единица прозы; **совпадает со SpeechChunk** | текст → абзац | аудио |
| `SourceToken` | токен исходника: поверхностная форма + span | Script → токен | своё время |
| `Anchor` | стабильный id (`w:`/`b:`/`sc:`/`ch:`/`r:`) | ledger → id | время, аудио |
| `AnchorLedger` | соответствие id ↔ токен между версиями текста | старый ledger + новый список токенов → новый ledger | режиссуру, время |
| `Marker` | авторская инструкция в прозе со span'ом | лексер → маркер | как реализуется |
| `DirectionRecord` | одна запись режиссуры `{recordId, at, until, track, z, template, params}` | YAML → запись | реализацию шаблона, кадры |
| `TemplateCall` | `{templateId, templateVersion, params}` (V3) | запись → вызов | свою визуальную реализацию |
| `SpeechChunk` | единица TTS-запроса = абзац | абзац → spoken-текст | деньги, аудио |
| `ChunkKey` | **идентичность места** чанка в тексте: имя take-файла, элемент `conditionedOn`, единица blast-radius (формула — ADR-0010 §3a) | структурный адрес + spoken-текст → ключ | байты аудио, деньги |
| `VoiceKey` | **идентичность содержимого** чанка: ключ кэша стадии `voice` (ADR-0006 §2) | spoken-текст + параметры генерации → ключ | где этот текст стоит |
| `VoiceTake` | иммутабельный дубль (см. ADR-0010) | чанк → дубль | где он стоит на таймлайне |
| `TokenBinding` | `anchorId → [startSample,endSample)` внутри дубля + статус | дубль → привязка | глобальное время |
| `Track` | типизированная дорожка `speech·music·sfx·caption·visual·effect·voice` *(`voice` добавлено: RM2, решение владельца 1, 2026-08-22 — **директивный** трек: запись клипа Timeline не порождает, а питает SpeechPlan; форма записи — [ADR-0010](0010-tts-boundary-and-takes.md) §3a-bis. Это отличает его от `speech` — дорожки Timeline, на которой лежат клипы речи)* | клипы → дорожка | рендеринг |
| `Clip` | размещение элемента в интервале, заданном `TimePoint`+`Duration`; несёт `clipDurationInFrames` | запись + привязки → клип | пиксели |
| `Silence` | явный клип тишины. Ровно три вида, и это **необратимая часть модели времени** (ADR-0003 T6): `author` (`[pause:]`), `gap` (межабзацная/межсценовая/межглавная тишина движка), `boundary-correction` (поправка δ, **не входит ни в один `L̃`**). Таксономия «причин» сверх этих трёх — отложена (раскрой 2.2) | длительность в сэмплах + вид → клип | почему автор поставил паузу |
| `CaptionGroup` | строка субтитра из 2–4 токенов; подсветка слова — атрибут внутри | привязки → группы | шрифты, раскладку |
| `Asset` | байты по sha256 + kind + интринсики (w/h/duration) | store → ассет | где используется |
| `AssetAlias` | человеческое имя → sha256 | `aliases.yaml` → отображение | лицензию |
| `Provenance` | юридическая запись (r3 §3.4): раздельные статусы произведения/репродукции/записи; поле `derivedFrom` (m4) | запись → факт | пиксели |
| `AssetGrid` | сетка позиций внутри ассета (биты музыки) для `GridPoint`; **объявлена, в v1 не реализуется** (ADR-0006 §14) | ассет + детектор → массив позиций в сэмплах ассета | таймлайн, кадры |
| `PublishSpec` | `publish.yaml`: title, `descriptionTemplate`, `topic`, `voiceRole`, `madeForKids`, `disclosure`, `sources` — вход BLOCK-правил Policy Guard (C7) | человек → запись | пиксели, время |
| `Override` | одна запись правки `{id, op, target, value, reason, boundTo, dependsOn?}`. В v1 статус ровно один — `applied`; несовпадение `boundTo` — **ошибка компиляции**, не статус (раскрой 2.1 п.1) | журнал → запись | структуру generated-файла |
| `Timeline` | физическая модель произведения | Script+bindings+direction+overrides+assets → Timeline | fps, кодеки |
| `Segment` | производная единица рендера и кэша; несёт `segmentDurationInFrames` (не `durationInFrames` — см. m2/ADR-0003 T4) | Timeline+compileProfile → сегменты | своё абсолютное положение |
| `RenderIrSegment` | «Video IR» | Timeline → IR | рендерер |
| `AssemblyManifest` | порядок сегментов, их длины в кадрах, ссылка на дорожку | IR → манифест | содержимое сегментов |
| `CompileProfile`/`PixelProfile`/`AudioProfile`/`ExecutionProfile` | четыре независимых профиля (ADR-0006) | — | друг друга |
| `BuildRecord` | входы, ключи, версии, `now` (подан снаружи), sha256 выходов стадий | сборка → запись | — |
| `PolicyReport` | generated-отчёт Policy Guard | Timeline + ruleset + дата (вход) → отчёт | как чинить |
| `ChannelLedger` | внешний журнал публикаций для проверок уровня канала (r3 §5 B). **Отложен до ролика №3** (раскрой 2.2): домен PG-B бессмыслен на пустом журнале; формат объявлен, механика не строится (m3) | публикация → строка | содержимое проектов |

**Типы времени в авторском слое разделены, а не запрещены:**

```ts
type TimePoint =
  | { kind: 'anchor';    anchor: AnchorId; nudgeSamples?: Samples }
  | { kind: 'mediaTime'; asset: Sha256; offsetSamples: Samples }
  | { kind: 'gridPoint'; asset: Sha256; gridId: string; index: number };   // v1: схема допускает, валидатор отвергает
interface Duration { samples: Samples }
```

V1 запрещает абсолютную форму ровно у `anchor`. `mediaTime` (in-point музыки) и `Duration`
(фейд, минимальное время показа) абсолютны и разрешены.

**`gridPoint` в v1 не реализуется (M5).** Вариант остаётся в схеме, потому что форвард-совместимость
типа-суммы стоит одну строку, а введение третьего варианта задним числом — миграция `direction/1`.
Но валидатор `direction/` **отвергает** `gridPoint` с сообщением «сетки ассетов не реализованы в v1»:
формат не имеет права обещать то, чего нет. Сама сетка, когда будет строиться, — артефакт
`assets/grids/<assetSha>.<gridId>.json` с `detectorId@version`, параметрами детектора и позициями
**в сэмплах ассета**; её sha входит в ключ сегмента рядом с `assetShas[]` (ADR-0006 §14). Без этого
величина, определяющая позиции клипов (то есть пиксели), не входила бы ни в один ключ — ровно тот
класс тихой ошибки, против которого написан ADR-0006.

## Alternatives

| Альтернатива | Почему могла быть лучше | Почему отклонена |
|---|---|---|
| **Одна плоская модель** (Timeline = вход рендерера) | минус одна схема и одно преобразование | fps и геометрия попадают в слой, к которому привязаны overrides ⇒ смена fps ломает правки; исчезает страховка r2 §8.1 |
| **Четыре слоя** (+ отдельный EDL между Timeline и IR) | готовое место для таймлайн-редактора | редактор — anti-scope (Charter §5); слой стоит четвёртой схемы и четвёртой цепочки миграций |
| **Модель без `Silence` как сущности** (тишина — побочный эффект правил) | меньше объектов | аудио-дорожка перестаёт быть воспроизводимой из Timeline; ассерт «Σ длительностей speech == numSamples» становится невыразимым |
| **Один `sampleRate` на проект** | проще | не примиряет три частоты (нативная у TTS 24 кГц, таймлайн, доставка 48 кГц у Remotion); развести обязательно (ADR-0003/0006) |

## Consequences

**Положительные**

* Каждая строка «НЕ знает» превращается в тест зависимостей (ADR-0009) или тест ключа кэша
  (ADR-0006), то есть модель охраняется механически.
* `TokenBinding` со статусом `measured|interpolated|absent` не позволяет компилятору выдумывать
  время, когда TTS проглотил слово.
* `Silence` как сущность делает арифметику дорожки проверяемой одним ассертом; три её вида дают
  формальное определение `L̃` (ADR-0003 T6) — без вида `boundary-correction` определение `L̃`
  циклично (C3).
* Разделение `ChunkKey` (место) и `VoiceKey` (содержимое) снимает выбор между двумя сломанными
  вариантами адресации дубля (C2): повторяющийся абзац получает **два** take-файла и **один**
  оплаченный дубль.

**Отрицательные**

* Три схемы и два преобразования вместо одного; постоянный налог «где живёт это поле».
* 36 сущностей — много для одного разработчика; смягчается тем, что примерно половина из них
  — это структуры на 3–5 полей без поведения, а пять (`AssetGrid`, `ChannelLedger`, второй binder,
  `segmentKind: 'seam'`, `c2paManifestBlob`) существуют в v1 **только как поля схем** (раскрой 2.2).
* Три сущности добавлены ревью, а не автором. Это цена того, что нормативное правило пользовалось
  именем, которого никто не определил (`chunkKey`), и что BLOCK-правила Guard'а не имели входа.

**Риски**

* `Segment` — производная сущность; если она случайно попадёт во входы seed'а или в адресацию
  overrides, сегментация начнёт менять картинку. Охраняется тестом из ADR-0007.
