# ADR-0004 — Якоря через ledger; overrides как журнал, который пишет CLI

* **Статус:** принято (A1, 2026-08-19); объём подтверждается спайком **SP-3**
* **Связь с Charter:** V1 (word anchors), V2 (overrides-слой), V8, AC6
* **Вход:** r1 §1.4, r3 §5 (Policy Guard читает Timeline)
* **Раздел архитектуры:** [core.md D4](../architecture/core.md#d4-адресация-якоря-и-слой-overrides)

## Context

Это самое необратимое решение A1: адресное пространство, в котором живут все ручные правки.
Ошибка здесь не чинится миграцией — она уничтожает пользовательские данные тихо.

Наивная схема `anchorId = hash(scopeId ‖ нормализованная_форма ‖ occurrenceIndex)` красива
(регенерация TTS не меняет текст ⇒ не меняет якоря), но имеет четыре отказа, три из них тихие:

1. **Тихое перенацеливание.** Вставка ещё одного экземпляра частотного слова в начало сцены
   сдвигает `occurrenceIndex` у последующих ⇒ существующий override резолвится успешно, но
   **в другое физическое слово**. Ни ошибки, ни предупреждения.
2. **Якорь от нормализованной формы.** (а) Любой багфикс нормализатора обнуляет ВСЕ якоря во
   всех проектах разом. (б) Нет биекции «токен исходника ↔ якорь»: `FACT` (r1 §1.4)
   `$45.67` → пять произносимых слов, `123-456-7890` → десять, `XIV` → одно или два «по
   контексту». Автор ставит маркер на один токен — якорей ноль или пять; `occurrenceIndex`
   считается по словам, которых в исходнике нет, и автор не может предсказать номер вхождения,
   глядя в свой текст.
3. **Обрезка хэша** до 10 символов без проверки уникальности — коллизия применяет правку к
   чужому слову.
4. **Нет пути авторства.** Единственный способ создать override — вписать руками непроизносимый
   хэш `k7f2q9x1bd`, которого человек нигде не видит. Слой V2 рискует стать мёртвым кодом со
   схемой, статусами и миграциями, которым никто не пользуется, — прямой anti-scope.

## Decision

**1. Пространства имён.** `w:` (токен исходника, **внутреннее**), `b:` (бит),
`sc:`/`ch:` (сцена/глава, id из заголовков), `r:` (запись режиссуры).

**2. Правило, убирающее большую часть проблемы:**
**ни один override и ни одна direction-запись не имеют права ссылаться на `w:` напрямую.**
Только `b:`/`sc:`/`ch:`/`r:`. `w:` остаётся внутренним пространством для caption-токенов и
измерений (AC5-a). Ссылок на `w:` в артефактах нет ⇒ проблема `occurrenceIndex` перестаёт быть
проблемой пользовательских данных.

**3. CLI — единственный писатель overrides.**
`vpe nudge <selector> +120ms --reason "…"` дописывает в прозу `[beat: auto-<slug>]` рядом с
целевым словом и привязывает правку к `b:`. Синтаксис уже есть (ADR-0002), шум в исходнике
пропорционален числу правок (единицы на ролик), а не длине текста. Это же закрывает дефект (4):
у слоя V2 появляется исполнимый путь авторства. Ему нужен инспектор:
`vpe inspect <scene>` печатает таблицу «якорь | слово | время | что к нему привязано».

**4. Ledger якорей.** `anchors.lock.json` (git, машинный):

```
anchorId → { chapterId, sceneId, ordinal, surface, prev, next, status: live|dead, mintedAtRev }
```

При парсинге берётся список токенов из предыдущего ledger'а и новый список, прогоняется
word-level diff (Myers/patience, готовая библиотека): совпавшие токены наследуют id, новые
получают свежий, исчезнувшие помечаются `dead` и хранятся N ревизий.
Минт детерминирован (V8): `w:<base32(blake3(seedRoot ‖ ledgerRev ‖ mintIndex))[:12]>`;
коллизия проверяется по множеству живых id при минте — не «маловероятна», а невозможна.
Проза остаётся чистой: id в неё не пишутся.

**5. Единица якоря — токен ИСХОДНИКА** (поверхностная форма), не нормализованное слово.
`TokenBinding` токена = объединение интервалов его произнесённых слов (`[min start, max end]`).
Следствия: `[emph]` на `$45.67` выразим; версия нормализатора на якоря не влияет вовсе;
замена «$45.67» на «45 долларов 67 центов» — осознанная правка текста, а не тихая смена якорей.

**6. `boundTo` = blake3(prevSurface, surface, nextSurface, ordinal)**, сверяется **перед**
применением. Совпал id, не совпал контекст ⇒ статус `drifted`, громкий WARN, правка **не
применяется**. Пять строк кода, превращающие тихий отказ (1) в громкий.

**7. Формат — журнал.** `overrides/<sourceFile>.jsonl`, append-only, запись на строку;
отмена = `{op:'revoke', supersedes: id}`; `vpe overrides compact` схлопывает журнал отдельным
коммитом. **Порядок применения = порядок строк** — тотальный по построению и не зависящий от
порядка чтения каталога (иначе это тихое нарушение V8).
Единица времени в записях — **сэмплы** (CLI конвертирует ввод из мс по ADR-0003 T1).
Поля `reason`/`createdAt`/`boundTo` — **не участвуют** в ключах кэша (ADR-0006): это метаданные,
они не должны инвалидировать пиксели.

**8. Статусы записи:** `applied` · `drifted` (boundTo не сошёлся) · `orphan` (цель отсутствует) ·
`stale` (зависела от конкретного дубля, дубль перегенерирован) · `quarantined`.

**9. Карантин вместо потери.** `overrides/<file>.quarantine.jsonl` хранит немигрируемую запись
**дословно**, с исходной версией схемы, `quarantinedAt`, `byMigration`, `reason`. Сборка печатает
WARN, пока карантин непуст. Миграция, удаляющая запись без карантина, — баг класса «порча данных».

**10. Refactor-команды обязательны до первого ролика с overrides:**
`vpe scene rename`, `vpe scene move` переносят ledger и overrides. Ручная правка заголовка
`## scene:` меняет `scopeId` и тихо уничтожает все правки сцены — значит она должна быть
либо запрещена линтом, либо обработана командой.

**Таксономия правок — что куда идёт.** Из 17 реальных классов ручных правок на слой overrides
приходится 7; остальное — правка исходника, режиссуры или отдельных файлов. Это надо записать
прямо, иначе будет построен универсальный override-движок под три реальных случая.

| # | Класс правки | Куда | Переживает regen TTS |
|---|---|---|---|
| 1 | «эффект на 120 мс позже» | override `{anchor, nudgeSamples}` | **да** |
| 2 | «алигнер ошибся на этом дубле» | override + `dependsOn:[takeSha]` | нет → `stale` (честно) |
| 3 | текст субтитра ≠ произнесённое | override `setCaptionText` | да |
| 4 | группировка/разбиение субтитров | override с `AnchorRange` | да |
| 5 | заменить фото | `assets/aliases.yaml` | да |
| 6 | параметры шаблона | `direction/*.yaml` | да |
| 7 | выбрать другой дубль | слой `takeChoice` (ADR-0010) | н/п |
| 8 | произношение имени | `lexicon.yaml` | да |
| 9 | пауза между сценами | `source` (`[pause:]`) | да |
| 10 | удлинить показ кадра | direction, тип `Duration` | да |
| 11 | in-point музыки | direction, тип `MediaTime` | да |
| 12 | фейд/дакинг музыки | override `{AnchorRange, gainCurve, Duration}` | да |

| 17 | уточнить провенанс | `assets/records/<sha>.json` (пишет CLI) | да |

## Alternatives

| Альтернатива | Почему могла быть лучше | Почему отклонена |
|---|---|---|
| **Контент-производные id** (исходная идея) | ноль состояния, merge-безопасно (обе ветки дадут один id одинаковому тексту), `parse` — функция только исходника | тихое перенацеливание при сдвиге `occurrenceIndex`; смерть якорей при смене нормализатора; отсутствие биекции с токенами исходника |
| **Явные id в прозе для каждого слова** (`[#w7f2]`) | абсолютная стабильность | засоряет прозу пропорционально её длине; делает текст нечитаемым для LLM и для человека |
| **Явные id только для «ручек» (биты, сцены, экземпляры)**, слова — хэш | шум пропорционален числу правок | принято **частично** — как правило №2 (запрет ссылок на `w:`) и №3 (CLI дописывает `[beat:]`); не заменяет ledger, потому что биты не спасают caption-уровневые правки и не дают метрики churn |
| **Полный 3-way rebase overrides при каждой правке текста** | автоматический перенос правок с git-подобными конфликтами | отдельный продукт уровня merge-tool; ledger + `boundTo` покрывают ~90 % за ~5 % цены |
| **JSON Patch по указателям** вместо типизированных записей | стандарт, готовые библиотеки | указатели ломаются при сдвиге индексов массивов (вставили слово — поехали все) |
| **YAML-файлы правок, редактируемые руками** | человекочитаемо, комментарии | пишут и машина (`boundTo`, статусы), и человек (`reason`) ⇒ нужен comment-preserving round-trip, который большинство библиотек не даёт; порядок применения между файлами не определён |

## Consequences

**Положительные**

* Отказ всегда громкий: токен не сматчился → новый id → override становится `orphan`;
  контекст не сошёлся → `drifted`. Тихого применения к чужому слову не существует.
* Ledger — бесплатный прибор для замера churn якорей (нужен в SP-3).
* Журнал даёт тотальный порядок, историю «зачем я это сделал» и бесплатный A/B (revoke вместо
  удаления).

**Отрицательные**

* `parse` перестаёт быть функцией только байтов исходника: `parse(sourceBytes, ledger, parserVersion)`.
  Ledger входит в ключ стадии — это принято честно.
* Ledger — машинный файл в git; при merge двух веток, правивших одну сцену, он конфликтует.
  Смягчение: одна запись = одна строка, детерминированный порядок, `vpe fmt --check` в CI.
* Нужны CLI-команды (`nudge`, `inspect`, `scene rename/move`, `overrides compact/quarantine`)
  до первого ролика с правками — это объём, который надо признать в roadmap, а не обнаружить.

**Риски**

* Если SP-3 покажет, что частота тихого перенацеливания близка к нулю, ledger можно свернуть до
  чистого хэша — дешёвое упрощение. Обратный переход (от хэша к ledger'у после потери правок)
  дешёвым не будет; поэтому выбран более дорогой вариант.
* Word-diff на «переписал абзац целиком» даст массовый `orphan`. Это правильно (правки к тексту,
  которого нет), но список должен показываться с контекстом ±5 слов, иначе им нельзя
  воспользоваться.
