## Context

`FACT` (r1 §2.3): «Determinism is not guaranteed» у TTS ⇒ аудио-дубль **невоспроизводим** ⇒
обязан храниться как байты. `FACT` (r3 §3.4): для защиты при споре нужен `sourceSnapshot` —
локальная копия страницы лицензии с датой, потому что страницы исчезают, а лицензии меняются
(Pixabay менял режим в 2019 и 2023). `FACT` (r3 §4.3): входящий C2PA-манифест исходника надо
сохранить как blob. То есть бинарных семейств минимум четыре: аудио, ассеты, шрифты, снимки
страниц.

Наивный вариант («аудио в git-LFS, ассеты в своём store, кэш в третьем месте») даёт три
параллельных механизма хранения при одном разработчике и не оставляет места снимкам страниц.
Плюс три отдельных дефекта: один `schemaVersion` на проект склеивает три независимых диалекта;
миграции обещаны для 7+ семейств, включая бесплатно пересчитываемые; AC6 в форме «пара фикстур
до/после» проверяет функцию миграции, а не утверждение Charter.

## Decision

**1. Раскладка.**

```
project.yaml                 git   schema: project/1
profiles/compile.yaml        git   schema: compile-profile/1   (часть ПРОИЗВЕДЕНИЯ)
profiles/render.final.yaml   git   pixelProfile + executionProfile
profiles/render.draft.yaml   git   то же для draft
profiles/render.ac4.yaml     git   то же для выделенного профиля AC4 (Charter AC4 rev5)
profiles/audio.yaml          git   audioProfile
source/NN-name.md            git   schema: source-dialect/1
direction/NN-name.yaml       git   schema: direction/1
overrides/*.jsonl            git   schema: override/1 (пишет CLI)
anchors.lock.jsonl           git   schema: anchors/1 — строка = якорь (M3)
publish.yaml                 git   schema: publish/1 — метаданные публикации (C7)
assets/aliases.yaml          git   alias → sha256
assets/records/<sha256>.json git   provenance по файлу на ассет
fonts/records/<sha256>.json  git
voice/roles.yaml             git   schema: voice-roles/1 — пресеты ролей голоса (решение 1)
voice/takes/<chunkKey>.json  git   дубль: spokenText, health, provenance, ref, привязки
store.lock                   git   sha256 → {size, kind, origin}
.store/ab/cd/<sha256>        ign.  CAS ВСЕХ байтов
build/                       ign.  timeline.json, ir/, segments/*.mts, audio/track.wav, final.mp4, reports/
.cache/<stage>/              ign.  CAS по ключам + manifest.json
```

**1a. Имя файла профиля и `profileId` связаны явно** *(добавлено: RM1, 2026-08-22, дрейф
`docs/roadmap.md` §9 п. 7).* До этой строки ADR-0005 §1 называл файл `render.draft.yaml`,
а ADR-0008 («Draft») — `profileId: draftHalf`, и нигде не было сказано, что это одна сущность.
Два документа называли одно двумя именами; при появлении второго черновичного профиля это
стало бы ошибкой, а не неудобством. Связь **однозначна и является частью формата**:

| файл | `profileId` | что это | гейт V13 |
|---|---|---|---|
| `profiles/render.final.yaml` | `final` | продакшн-рендер; на нём меряется AC2 | **да, N = 10** |
| `profiles/render.draft.yaml` | `draftHalf` | `scale` 0.5, `crf` 28; механизм AC3 | **да, N = 3** |
| `profiles/render.ac4.yaml` | `ac4` | **полный прогон фикстурного проекта** (Charter AC4 rev5) | **нет** (решение владельца 12) |

Правило чтения: `profileId` — то, чем именуются пространства имён кэша (ADR-0006 §13) и чем
адресуется запись гейта в манифесте шаблона (**R12**); имя файла — то, на что ссылается
`project.yaml`. Совпадать они не обязаны, но соответствие обязано быть записано **здесь**,
и второе имя для той же сущности не заводится.

**1b. `voice/roles.yaml` — семейство, а не поле** *(добавлено: RM1, решение владельца 1,
2026-08-22).* Пресеты ролей («основной диктор», «цитата», «вставка») задаются один раз на канал
и переиспользуются между роликами; в них лежат `voice_settings` и модель/голос по умолчанию
для роли. Файл **рукоправимый** (см. §9). Форма ссылки: запись `direction/*.yaml` с
`track: voice` и полем `voiceRole` (ADR-0010 §3a). Обязательное следствие, без которого
семейство не вводится: **`roleDigest` входит в `cacheKeyView` стадии `voice`**
(ADR-0006 §2) — иначе правка роли меняет звук, не меняя ключ, а это ровно та дыра,
из-за которой `Lexicon` удалён из модели (ADR-0010 §7a). `voice_id` в файл **не попадает**:
он берётся только из `process.env` (CLAUDE.md §2), в роли лежит имя переменной, а не значение.

**2. Артефакт против кэша — сквозное правило.**
Артефакт — то, что нельзя воссоздать чистой функцией из репозитория (проза, режиссура, overrides,
ledger, provenance, дубли, профили, aliases, `publish.yaml`). Кэш/производное — Script, SpeechPlan,
Timeline, RenderIR, сегменты, дорожка, final.
**Миграции существуют только для артефактов. Для кэша существует только инвалидация:**
несовпадение версии = удалить и пересчитать. Это сокращает объём AC6 примерно вдвое и снимает
вопрос «надо ли мигрировать RenderIR».

**2a. `publish.yaml` — семейство, без которого половина BLOCK-правил Guard'а неисполнима (C7).**

Сверка каталога правил r3 §5 с моделью показала: **три BLOCK-правила из четырёх не имеют входа**,
а одно конфликтует с нормативным линтом прозы.

| Правило | Severity | Что ему нужно | Было в модели |
|---|---|---|---|
| PG-D5 | **BLOCK** | текст атрибуции в сгенерированном описании ролика | описания ролика не существует |
| PG-A1 | **BLOCK** | указанный источник текста сценария | негде записать; **URL запрещён линтом прозы** |
| PG-A5 | **BLOCK** | тема ролика + роль голоса | ни `topic`, ни `voiceRole` |
| PG-A6/A8/C8 | WARN/INFO | ссылки, made-for-kids, текст дисклеймера | некуда положить |

Это единственная находка ревью, которая **после первого ролика становится миграцией формата**
(новое поле в `project/1` + новое семейство файлов), а не правкой кода. Поэтому семейство вводится
сейчас, до заморозки формата (раздел 2.3 п.17), максимум на страницу спецификации — это формат
данных, а не модуль, поэтому anti-scope не нарушается:

```yaml
schema: publish/1
title: …
descriptionTemplate: |            # слоты {{attributions}} заполняет компилятор
topic: history                    # PG-A5/A6
voiceRole: narrator | expert      # PG-A5 (трёхфакторный чек AI-персоны)
madeForKids: false                # PG-A8
disclosure: { syntheticVoice: true, aiImagery: false, aiMusic: false }   # PG-C1/C2/C3
sources: [ { url: …, appliesTo: sc:intro } ]                             # PG-A1/A6
```

Файл **рукоправимый**; `{{attributions}}` — единственный слот, который заполняет компилятор из
provenance ассетов (и это делает PG-D5 исполнимым). В MVP реально проверяются только правила
доменов D и E (раскрой 2.1 п.7), но **поля заводятся все**: поле стоит строки в схеме, а миграция
после первого ролика стоит несравнимо больше.

**3. Версия схемы — у каждого семейства своя**, в шапке файла (`schema: override/1`).
Три диалекта (маркеры исходника, схема overrides, схемы локов) развязаны; бамп одного не
заставляет врать про остальные.

**4. Толерантный читатель, канонический писатель.** Одна функция чтения на семейство понимает
все исторические варианты (union-схема zod); писатель всегда пишет текущую каноническую форму.
«Миграция» = прочитать и переписать.

**Переписывателя прозы не существует (M7).** Первая редакция делала для диалекта `source/`
исключение («нужен явный переписыватель»), и одновременно объявляла гейт `--dry-run`: «байтов
**прозы** затронуто — обязано быть 0». Один документ содержал гейт и механизм, который нарушает
его в первом же применении. Настоящий инвариант безопасности сформулирован рядом и верен
(«spoken-текст каждого чанка побитово не изменился»), а «0 байт прозы» — лишний и невыполнимый:
отключённый гейт не защищает и от настоящих ошибок.

Вместо переписывателя — **правило роста диалекта**: маркеры **добавляются**, старые **никогда не
удаляются и не меняют смысла**, толерантный читатель понимает все исторические варианты.
Тогда `source-dialect/` не мигрируется **никогда**, самая опасная миграция просто не существует,
и вопрос «как сохранить авторское форматирование при машинной переписи» не возникает. Если когда-то
понадобится удалить маркер, это будет отдельный ADR с явным переписывателем, property-тестами
идемпотентности (`rewrite(rewrite(x)) == rewrite(x)`) и сохранения разбора
(`parse(rewrite(x)) ≡ parse(x)`) — а не рядовая процедура.

**5. `vpe migrate --dry-run` в v1 не пишется** (раскрой 2.1 п.11): мигрировать пока нечего.
Необратимая часть — заголовок `schema: <family>/N` в каждом файле и толерантный читатель — вводится
**сразу** (п.3, п.4); сама команда со всей её экономикой пишется при первом бампе схемы, и её
спецификация фиксируется здесь, чтобы не проектировать её заново: печатать до записи, сколько
якорей исчезнет/появится, сколько overrides перестанет применяться, **сколько символов TTS придётся
перегенерировать и сколько это стоит** (по `billedUnits` из дублей), сколько сегментов
инвалидируется; при оценке перегенерации TTS > 0 — требовать флаг `--i-know-it-costs`.

**6. Инвариант безопасности миграций, заменяющий рассуждения о необратимости:**
«**spoken-текст каждого чанка побитово не изменился**» ⇒ voice-кэш не промахнулся ⇒ денег не
потрачено ⇒ дубли и привязки валидны. Неравенство ⇒ миграция затрагивает звук и объявляется
громко, отдельным коммитом. Гоняется на каждой миграции диалекта исходника и на каждой
refactor-команде.

**7. AC6 определяется и тестируется корпусом.**
«Проект открывается» = **компилируется до Timeline** и **все overrides применяются**.
**Два уровня, потому что одного было мало.** Определение выше выполняется и тогда, когда `.store`
потерян (M8): проект открывается, но не звучит и не рендерится, а повторная генерация даст **другое**
аудио (`FACT` r1 §2.3) — критерий зелёный, работа потеряна. Поэтому вводится второй уровень:
`vpe open --full` дополнительно требует наличия **всех** sha из `store.lock`. AC6 в корпусе
`fixtures/legacy/` проверяется на первом уровне (иначе корпус потянул бы за собой байты), гейт перед
работой с реальным старым проектом — на втором.
Покадровое совпадение после миграции не требуется (косметическая миграция может законно
изменить кадры). Проверка: `fixtures/legacy/vN/` — реальные старые проекты, положенные в
репозиторий и **никогда не обновляемые**; тест открывает каждый текущей версией движка. Пары
«до/после» на конкретную миграцию остаются как дополнение, не как замена.
Фикстуры используют `tts:mock@1` (ADR-0010) ⇒ бинарников в тестовом контуре нет вовсе.

**8. Хранилище байтов — одно.** Интерфейс:

```ts
interface Store {
  has(sha: Sha256): Promise<boolean>;
  read(sha: Sha256): Promise<Uint8Array>;
  put(bytes: Uint8Array, kind: BlobKind): Promise<Sha256>;   // 'voice'|'asset'|'font'|'snapshot'|'c2pa'
  path(sha: Sha256): Promise<string>;                        // локальный путь для рендерера
  missing(required: readonly Sha256[]): Promise<readonly Sha256[]>;
}
```

Команды `vpe store fetch|push|verify`. **Бэкендов в v1 два** (раскрой 2.1 п.4): локальный каталог
и один удалённый через rclone. Интерфейс из пяти методов остаётся — он и так минимален, и именно он
делает добавление третьего бэкенда (внешний SSD, git-LFS) конфигурацией, а не переписыванием.
`vpe store gc` не пишется: `.store` **не подлежит LRU-GC никогда**, дубли TTS невоспроизводимы.
Клон без стора открывается и компилируется до Timeline и падает только на стадии, которой нужны
байты, с точным списком недостающих sha256.

**8a. Сохранность `.store` — механизм, а не привычка (M8).**
`.store` лежит в `.gitignore`, не подлежит GC и содержит **единственную копию** PCM всех дублей и
снимков страниц лицензий. `FACT` (r1 §2.3): повторная генерация даёт **другое** аудио, значит потеря
не восстанавливается деньгами — старые ролики становятся невоспроизводимыми навсегда, а юридическая
доказательная база по лицензиям (`FACT` r3 §3.4) исчезает. Механизм «привычка `push` и `verify` в
ночном прогоне» этому не соответствует по классу риска. Вводится:

1. **`.store` живёт вне рабочего дерева проекта** — в `~/.vpe/store/` (или по пути из
   `project.yaml`), а в проекте остаётся только `store.lock`. Причина конкретна: `git clean -xdf` —
   рутинная команда, и она удаляет `.gitignore`-каталог внутри дерева вместе со всем оплаченным
   аудио. Каталог вне дерева ей недостижим.
2. **`store.lock` расширяется полем `replicas: [backendId]`** с инвариантом: для ~~`kind: voice`
   и `kind: snapshot`~~ *(расширено: RM1, решение владельца 6, 2026-08-22)* **`kind: voice`,
   `kind: snapshot` и `kind: ai-image`** реплик **≥ 2**. Проверяет `vpe store verify`;
   `vpe build` **падает**, если verify не выполнялся дольше `storeVerifyMaxAgeDays` (кандидат 14).
   *Почему добавлен третий вид:* решение владельца 6 объявило AI-арт **невоспроизводимым
   артефактом** — воспроизводимость по `seed` от него **не требуется**, и защищается он «тем же
   способом, что оплаченный дубль TTS». Класс риска тот же: пересоздать байты нельзя, а на них
   стоит provenance и `disclosure.aiImagery`. Охранник — строка **P7** в
   [invariants.md](../invariants.md).
3. **DoD этапа (00-PROCESS §8) получает строку:** «после каждого ролика — `vpe store push`».

Второй репликой в v1 служит удалённый бэкенд rclone. Аргумент «git-LFS — отдельная инфраструктура»
остаётся справедливым для **основного** хранилища, но не запрещает использовать LFS как вторую
реплику критичного подмножества (~5–10 МБ на ролик во FLAC), если rclone окажется неудобен.

**9. Generated vs overrides (V2), исполнимо.**
Руками правятся ровно: `project.yaml`, `profiles/*`, `source/*`, `direction/*`, `aliases.yaml`,
`publish.yaml`, **`voice/roles.yaml`** *(добавлено: RM1, решение владельца 1, 2026-08-22)*.
Всё остальное в git пишет CLI.

**Профиль содержит только намерение (M9).** Первая редакция объявляла профили рукоправимыми и
одновременно клала в них вычисляемые величины: `bundleHash`, версию Chrome «из файла VERSION»,
`hostClass`, checksum шрифтов, «версию ffmpeg и строку конфигурации сборки». Такой файл не охраняем
ни одним из двух способов: канонизировать нельзя (правит человек), доверять нельзя (значения
протухают при первом `pnpm update`). Плюс те же величины входили в ключ ещё раз через
`engineFingerprint` — одна информация учтена дважды и получена двумя путями, из-за чего
`cacheKeyView` (объявленный единственным источником истины о ключе) становился неоднозначным.
Разделение:

* **`profiles/*.yaml` — только намерение человека:** `codec`, `crf`, `gopSize`, `scale`,
  `imageFormat`, `jpegQuality`, `colorSpace`, `pixelFormat`, `gl`, `fps`, геометрия, параметры
  энкодера (C5), `safeAreas`, gap'ы (ADR-0003 T8), `maxDurationFrames`;
* **измеренное окружение** ~~(версии Remotion/Chrome/ffmpeg, `bundleHash`, checksum шрифтов,
  `hostClass`)~~ *(изменено: серия SP-3, решение владельца 4, 2026-08-21)* — **вычисляется на
  каждой сборке**, пишется в `BuildRecord` и входит в ключ ровно один раз, как `engineFingerprint`.
  **Состав отпечатка здесь не перечисляется: он определён в [ADR-0006 §3](0006-content-cache.md) и
  только там.** После SP-3 close состав изменился (пять завендоренных компонентов, фактическая
  строка запуска Chrome, платформа; GPU-драйвер убран как шум на софтверном пути) — и перечень в
  скобках выше, будь он оставлен, разошёлся бы с оригиналом молча. Это ровно та ошибка «одна
  информация в двух местах», против которой написан сам пункт M9, поэтому здесь остаётся **ссылка,
  а не копия**. Охранник актуальности отпечатка — строка **R14** в
  [invariants.md](../invariants.md). Разбор — [docs/spikes/sp3-closure.md](../spikes/sp3-closure.md);
* `vpe fmt --check` теперь может охранять профили, потому что в них не осталось протухающих полей. Всё в `build/` и `.cache/` — generated и не
правится никогда. `vpe fmt --check` в CI падает, если машинный файл отличается от канонической
формы. `vpe fmt` делает три вещи: NFC + `\n`, построчную дисциплину прозы (semantic linefeeds —
иначе merge прозы неразрешим) и канонический порядок записей в машинных файлах.

**9a. Производный ассет наследует цепочку прав явно (m4).**
Ресайз даёт новый sha256 ⇒ новую запись `assets/records/<sha>.json`, и на ней PG-D1/PG-D3 (обе BLOCK)
формально сходятся, а юридическое содержание — лицензия исходника, `sourceSnapshot`, `retrievedAt`,
`attributionRequired` — к ней не привязано. Guard зелёный, цепочка прав разорвана, и это происходит
на первом же ролике (все 8 фото проходят через кадрирование под 9:16).

* В схему provenance вводится **сейчас** (формат необратим):
  `derivedFrom: { sha256, transform: { op, params, toolVersion } }`; правило наследования: лицензия,
  `attributionRequired` и `sourceSnapshot` **не дублируются**, а читаются по ссылке на запись
  оригинала; отсутствие `derivedFrom` у ассета, которого нет среди ingest'нутых оригиналов, — ошибка.
* В v1 **ресайза на ingest нет вовсе**: хранятся оригиналы, масштабирование выполняет рендерер
  (браузер и так это делает). Тогда производных ассетов в MVP не существует, и весь класс временно
  пуст — а поле уже есть к моменту, когда ресайз понадобится (например, ради AC2).

**9b. AI-арт как источник ассета: форма provenance.**
*Добавлено: RM1, решение владельца 6, 2026-08-22 (вопрос roadmap §8 №6).* До этой записи в
репозитории не было ни формы, ни провайдера, и задача `A-01` была заблокирована. **Форма
записана; провайдер остаётся `UNKNOWN` и остаётся за владельцем** — условия на коммерческое
использование у разных генераторов различаются, а `FACT` (r3 §3.4) страницы условий исчезают
и меняются.

```
provenance.work.status:    'ai-generated'
provenance.generator:      { providerId, modelId, modelVersion }
provenance.generation:     { prompt, negativePrompt?, seed, parameters, generatedAt }
provenance.reproduction:   { status: <по условиям провайдера>, attributionRequired }
provenance.origin:         { sourceUrl: <ссылка на условия>, retrievedAt }
provenance.sourceSnapshot: { sha256, capturedAt }      # снимок страницы условий
derivedFrom:               { sha256, transform: { op, params, toolVersion } } | null
publish.yaml → disclosure.aiImagery: true
```

Четыре решения владельца, входящие в форму, и почему каждое записано именно так:

1. **`prompt` обязателен.** Он может содержать имена живых художников и названия студий, то есть
   это **юридический след**, а не только техническая запись; сохранять его дешевле, чем потом
   доказывать, чего в нём не было. Обязательность означает: отсутствие поля — **ошибка
   валидации**, а не WARN (критерий готовности `A-01`).
2. **`derivedFrom` обязателен, если генерация шла по референсу.** Тогда цепочка прав тянется к
   референсу, и правило наследования §9a работает без изменений: лицензия, `attributionRequired`
   и `sourceSnapshot` **не дублируются**, а читаются по ссылке на запись оригинала. Если
   референса не было — `derivedFrom: null`, и это осознанное утверждение, а не пропуск.
3. **Воспроизводимость не требуется.** `seed` и `parameters` записываются как provenance
   («как сделано»), но движок **не обещает** пересоздать байты по ним и не имеет права
   ссылаться на такую возможность. Ассет хранится как **невоспроизводимый** — `.store`,
   реплик ≥ 2, `kind: ai-image` (§8a) — тем же способом, что оплаченный дубль TTS. Это
   согласовано с тем, что уже записано про дубли: `FACT` (r1 §2.3) вендор объявляет
   «Determinism is not guaranteed», и ADR-0006 §2 прямо запрещает перегенерацию вместо хранения.
4. **`providerId` — строка, без списка допустимых значений.** Схема не перечисляет генераторов:
   перечень протух бы раньше первого ролика, а незнакомое имя провайдера — не повод отвергнуть
   валидный ассет. Юридическую сторону закрывает не enum, а `origin.sourceUrl` +
   **`sourceSnapshot`** (снимок страницы условий, обязателен независимо от выбора провайдера).

**Что эта форма даёт Policy Guard.** `disclosure.aiImagery: true` в `publish.yaml` — вход
PG-C2/PG-C3; `provenance.work.status: 'ai-generated'` вместе с `origin`/`sourceSnapshot` —
вход PG-D1/PG-D2 (обе BLOCK). Охранники — строки **P11**, **P12** и **P7** в
[invariants.md](../invariants.md).

**Что остаётся открытым и за кем.** **Провайдер AI-арта — `UNKNOWN`, решение владельца.**
До его выбора `A-01` может быть выдана в работу по форме (схема, валидация, Guard), но
`fixtures/reference` не может быть наполнена AI-ассетами: `origin.sourceUrl` и
`sourceSnapshot` берутся со страницы условий **конкретного** генератора.

**10. Все машинные локи — add-only, строка = запись, файл = сущность** (`voice/takes/<key>.json`,
`assets/records/<sha>.json`, `overrides/*.jsonl`, `anchors.lock.jsonl`). Тогда merge двух веток — объединение множеств,
а конфликт возникает ровно там, где он настоящий. Единый JSON-объект давал бы конфликт всегда.

## Alternatives

| Альтернатива | Почему могла быть лучше | Почему отклонена |
|---|---|---|
| **git-LFS для голоса** | готовая инфраструктура, `git clone` приносит всё | ещё одна система (квоты, `lfs prune`, свой биллинг, ломающиеся clone в CI) ради одной операции «дай файл по sha256»; не покрывает снимки страниц и не убирает второй store. Оставлен **бэкендом** `Store`, а не решением формата |
| **Бинарники прямо в git** | ноль инфраструктуры | 20–40 МБ на ролик × churn дублей × 30 роликов — история деградирует необратимо |
| **SQLite как источник истины проекта** (Charter §6 называет SQLite среди предпочтений — **оспариваю**, там это помечено как гипотеза) | транзакции, запросы, индексы | git-мержи, диффы и ревью правок (V2) требуют текста; при трёх кэшируемых стадиях (ADR-0006) индекс не нужен вовсе. В v1 SQLite не появляется |
| **Один `schemaVersion` на проект** | одно число, одна цепочка | склеивает три независимых диалекта; бамп любого заставляет врать про остальные |
| **Цепочки чистых функций vN→vN+1 для всех 7+ семейств** | формально чисто | 7 растущих цепочек и тесты на каждое звено для одного разработчика — прямой anti-scope; мигрировать имеет смысл только невосстановимое |
| **Не коммитить привязки якорей** (только alignment в store) | меньше файлов в git | проект перестаёт быть самоописательным: без байтов временную картину не восстановить, AC6 не выполняется. Привязки живут внутри take-файла (~5 КБ на ролик) |

## Consequences

**Положительные**

* Одно хранилище байтов на все четыре бинарных семейства; одна операция «дай по sha256».
* Проект самоописателен без байтов: временная картина, provenance и правки читаются из git.
* Миграции пишутся для ~7 артефактов вместо ~12 объектов, и ни одной для производных.
* Диалект `source/` не мигрируется никогда (M7): самая опасная миграция удалена как явление,
  а не автоматизирована.
* `publish.yaml` вводится до заморозки формата, поэтому BLOCK-правила Guard'а получают вход
  не миграцией, а строкой в схеме.

**Отрицательные**

* `.store` вынесен из дерева проекта и требует **двух** реплик для `voice`/`snapshot`; сборка
  падает, если `verify` давно не выполнялся. Это лишний шаг в рутине, принятый сознательно: цена
  ошибки — невосстановимая потеря оплаченного аудио и доказательной базы по лицензиям.
* Своя реализация store (~200 строк) вместо готового LFS.
* Много мелких файлов в git (по файлу на ассет и на дубль) — осознанная плата за merge-дружелюбие.
* Правило «маркеры только добавляются» — ограничение на будущее развитие формата, принятое ради
  отсутствия переписывателя прозы. Если формат зайдёт в тупик, выход — новый ADR, а не рядовой бамп.
* `publish.yaml` содержит поля, которые в MVP никто не читает (домены A/B/C Guard'а). Это
  сознательный мёртвый груз ~10 строк против гарантированной миграции формата после первого ролика.

**Риски**

* Реальный объём `.store` на 30 роликов — `UNKNOWN`; измеряется на первом же настоящем ролике
  (логировать байты PCM/FLAC и число уникальных sha256).
* Воспроизводимость FLAC между версиями libFLAC — `UNKNOWN`; поэтому адресация дубля идёт по
  **sha256 декодированного PCM**, а контейнер — деталь хранения.
