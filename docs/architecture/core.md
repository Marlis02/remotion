## 1. Форма пайплайна и глоссарий

### 1.1 Общая форма

```
source/*.md                        человек / ИИ пишет текст с маркерами          [git]
   │  parse — span-aware лексер+парсер
   ▼
ScriptAST                          прозаические блоки, слова, маркеры, span'ы    [НЕ артефакт]
   │  normalize (V5, трансдьюсер со span-map) + токенизация слов → якоря
   ▼
SpeechPlan                         чанки нормализованного текста + таблица якорей [кэш]
   │  TTS — сеть, НЕдетерминирован, стоит денег
   ▼
VoiceTake[]                        FLAC + тайминги в СЭМПЛАХ + provenance         [git/LFS, voice.lock.json]
   │  merge: overrides (V2) + assets.lock (V10) + шаблоны (V3)
   ▼
Timeline                           сцены/главы/треки; время — СЭМПЛЫ; renderer-agnostic  [build/]
   │  ├─→ Policy Guard (R3) ─────────────────────────────→ policy-report.json    [build/]
   │  compile(fps, геометрия) — квантование в КАДРЫ, проверка инварианта V4
   ▼
RenderIR[chapter]                  кадры, chapter-relative, целочисленный          [build/ + ключ кэша]
   │  adapt (единственное место, знающее про Remotion)
   ▼
segments/chapter-NN.ts             НЕМЫЕ видео-сегменты                            [кэш по segmentKey]
                                              +
AudioIR → audio/track.flac         одна сплошная дорожка на весь ролик (V6)         [кэш]
   ▼
ffmpeg concat -c copy → mux → единственное кодирование → final.mp4
```

Персистятся: `VoiceTake`, `Timeline`, `RenderIR`, сегменты, аудио-дорожка, отчёты, `final.mp4`.
**Не** персистится `ScriptAST` — он вырождается в две вещи (Timeline и span-map) и живёт только в памяти;
дамп по флагу `--dump-ast` для отладки. Это сознательное сокращение числа артефактов (см. §3).

### 1.2 Глоссарий (термины употребляются в этом значении во всех ADR)

| Термин | Значение |
|---|---|
| **Якорь (anchor)** | стабильный идентификатор точки текста: слово, предложение, бит, маркер, сцена, глава. Не содержит времени. |
| **Привязка (binding)** | пара «якорь → интервал сэмплов». Производится компилятором Timeline из VoiceTake. |
| **Дубль (VoiceTake)** | иммутабельный артефакт TTS: аудио + тайминги + provenance + отпечаток запроса. |
| **Сцена** | единица авторства и **scope якорей**. Один заголовок `## scene: id` в исходнике. |
| **Глава (chapter)** | единица рендера, кэша и параллелизма (V4). Граница главы = «здесь жёсткая склейка». |
| **Timeline** | renderer-agnostic модель с временем в сэмплах. Здесь применены overrides. |
| **RenderIR** | плоское целочисленное описание одной главы во времени кадров, относительно её начала. |
| **renderProfile** | всё, что влияет на пиксели/байты, но не на раскладку: растеризатор, кодек, качество, версии. |
| **S** | `samplesPerFrame = sampleRate / fps`, всегда целое (инвариант R2 из §4). |
| **Ключ кэша** | blake3 от канонического JSON входов стадии + `stageVersion` пакета-производителя. |

## 2. РЕШЕНИЕ 1 — Domain model

**CURRENT IDEA.** «Есть Project, в нём Scene, в сцене Track'и с Clip'ами, у клипов есть Asset,
поверх — Caption'ы; всё это одна объектная модель, которую движок таскает от парсинга до рендера.»
Так устроены почти все видеоредакторы, и это первое, что приходит в голову.

**PROBLEM.** Единая объектная модель ломается о три требования Charter одновременно:

1. **V1 + V2.** Правки живут отдельным слоем и привязаны к якорям слов. Значит, у модели обязана быть
   **отдельная сущность «якорь», не содержащая времени**, иначе правка неизбежно привяжется к секундам.
2. **V9.** Рендерер не должен знать бизнес-логику. Единая модель, дотянутая до рендера, тащит в него
   provenance, лицензии, политику и TTS-настройки.
3. **AC3.** Инкрементальность требует, чтобы части модели **хэшировались независимо**. Объектный граф
   с обратными ссылками (клип знает свой трек, трек знает проект) не хэшируется по кускам вообще.

Есть и четвёртая, менее очевидная проблема: `Asset` в такой модели одновременно «файл», «пиксели»,
«юридическая запись» и «место в кадре». `FACT` r3 §3.4 показывает, что юридическая часть — это
**три независимых статуса** (произведение / репродукция / запись) плюс десяток полей; смешивание их
с геометрией кадра — тот самый механизм, которым люди попадают в ошибки 3.1a/3.1b из r3.

**ALTERNATIVES.**

* **A. Единая объектная модель «как в редакторе».** Дёшево начать, знакомо. Отвергнута: см. PROBLEM.
* **B. Event sourcing / CRDT (модель = поток правок).** Красиво решает V2 и слияние веток.
  Отвергнута: для одного разработчика это цена без выгоды — конфликтов между людьми нет, а сложность
  реконструкции состояния и детерминизма воспроизведения (V8) выше, чем у файлов с чистым фолдом.
* **C. Реляционная модель в SQLite как источник истины.** Charter §6 упоминает SQLite. Отвергнута
  как источник истины: правки (V2) должны быть **человекочитаемыми и диффабельными в git**, иначе ревью
  правки невозможно; бинарный файл в git не мержится. SQLite остаётся — но только как перестраиваемый
  индекс кэша (§6, ADR-0005).
* **D (RECOMMENDED). Расслоение по ответственности: «текст → голос → время → пиксели → право».**
  Пять групп сущностей с односторонними стрелками, каждая следующая знает предыдущую и не знает следующую.

**RECOMMENDED — сущности, их вход/выход и «чего не должна знать».**

| Сущность | Ответственность | Вход → Выход | НЕ должна знать |
|---|---|---|---|
| **Project** | идентичность и глобальные параметры: `schemaVersion`, `fps`, геометрия, `sampleRate`, `seedRoot`, дефолты голоса, ссылка на `renderProfile` | `project.yaml` → настройки | рендерер, конкретного TTS-провайдера, раскладку кэша |
| **Chapter** | единица рендера/кэша/параллелизма (V4); упорядоченные сцены | сцены → глава | **абсолютное время проекта**, содержимое соседних глав |
| **Scene** | единица авторства и **scope якорей**; прозаический блок + маркеры | markdown-блок → токены + маркеры | кадры, сэмплы, ассеты по путям |
| **Anchor** | стабильный id точки текста | (scope, форма слова, порядковый номер) → id | **время** (это его определяющее свойство) |
| **AnchorBinding** | связывание якоря с физическим временем | якорь + VoiceTake → `[startSample, endSample)` | как это будет показано |
| **SpeechChunk** | единица TTS-запроса (обычно абзац) | нормализованный текст + контекст → запрос | аудио, тайминги |
| **VoiceTake** | иммутабельный результат TTS | запрос → PCM + тайминги + provenance | своё место на таймлайне |
| **Track** | типизированная дорожка: `speech \| music \| sfx \| caption \| visual \| effect` | клипы → упорядоченная дорожка | рендеринг, кодеки |
| **Clip** | размещение элемента в **анкоро-относительном** интервале | (элемент, якорь, смещение) → размещение | абсолютные секунды |
| **Asset** | content-addressed файл + вид + интринсики (w/h/длительность) | файл → `sha256` + метаданные | где используется, лицензия |
| **Provenance** | юридическая запись об активе (поля r3 §3.4) | источник → набор **утверждений** | пиксели, таймлайн |
| **Caption** | производная дорожка: токены со ссылкой на `anchorId` | привязки + стиль → токены | шрифты, перенос строк, раскладка |
| **Marker** | авторская инструкция со span'ом и целевым якорем | текст → инструкция | как она будет реализована |
| **TemplateCall** | `{templateId, templateVersion, params}` (V3) | параметры → вызов | свою визуальную реализацию |
| **Override** | типизированная правка с ключом-идентификатором, `boundTo`-отпечатком и причиной | правка → запись | структуру generated-файлов |
| **RenderProfile** | всё, что влияет на пиксели/байты, но не на раскладку | версии+настройки → отпечаток | содержание ролика |
| **PolicyReport** | generated-отчёт Policy Guard | Timeline + ruleset + дата → находки | как их чинить |
| **BuildRecord** | provenance самой сборки: входы, ключи, версии, `now`, тайминги стадий | сборка → запись | содержание ролика |

**WHY.**

* Отделение `Anchor` от `AnchorBinding` — это **исполнение V1 типами, а не дисциплиной**. Сущность,
  у которой физически нет поля времени, не может быть привязана к секундам.
* Отделение `Provenance` от `Asset` — прямое следствие r3 §3.4: `INFERENCE` схема провенанса обязана
  делать ошибку «один статус на всё» **невыразимой**, а для этого она должна быть отдельной записью
  со своими обязательными полями, а не парой строк внутри ассета.
* Отделение `TemplateCall` от его реализации — это V3. `TemplateCall` живёт в domain, реализация — в
  адаптере рендерера. Между ними — только `templateId@version` и zod-схема параметров.
* `BuildRecord` выглядит служебным, но он закрывает AC4 и разбор инцидентов: без записи «какие версии и
  какой `now`» воспроизвести старый рендер невозможно, а `now` внутри компиляции запрещён (V8).

**TRADE-OFFS.**

* Сущностей много (18). Для одного разработчика это риск бюрократии. Смягчение: **это типы, а не классы
  с поведением**; поведение живёт в трёх компиляторах (script→AST, AST+voice+overrides→Timeline,
  Timeline→RenderIR). Файлов немного, а границы между ними — то, ради чего всё затевается.
* `AnchorBinding` как отдельная таблица означает лишний lookup почти в каждом алгоритме компиляции.
  Принимаем: цена — читаемость кода, выгода — невозможность «случайно взять секунды из якоря».
* Модель ничего не знает про монтажную выразительность (переходы между главами, вложенные композиции).
  Это осознанное ограничение, вытекающее из V4; см. §9 и §13.

→ **ADR-0001** (якоря и время), **ADR-0011** (голос как артефакт), **ADR-0012** (provenance и Policy Guard).

## 3. РЕШЕНИЕ 2 — Source format и пайплайн Source → компиляция → Video IR

**CURRENT IDEA.** «Человек (или ИИ) пишет сценарий в markdown с какими-нибудь пометками, движок их
вычитывает регекспами и строит проект.» Именно так выглядит первая версия любого такого движка.

**PROBLEM.** Регекспы над markdown ломаются о V5 и V1 сразу:

* V5 требует **вырезать маркеры до отправки в TTS** и при этом сохранить соответствие
  «символ исходника ↔ символ, ушедший в TTS». Регексп-замена теряет позиции. `FACT` r1 §1.3: ElevenLabs
  отдаёт **посимвольные** тайминги, пословных нет; чтобы собрать из них слова, нужно знать границы слов
  **в той самой строке**, которая ушла в API. Без span-map это восстановление наощупь.
* V1 требует стабильных идентификаторов слов. Идентификатор нельзя выдать без детерминированной
  токенизации, а токенизация без парсера — это набор частных случаев, который расходится с TTS.
* Сообщения об ошибках. «Эффект пересекает границу главы» без `файл:строка:колонка` — бесполезное
  сообщение, а инвариант V4 обязан проверяться (r2 §8.2).

Второй слой проблемы: **какой вообще формат даёт писать человек и LLM.** Charter §1 говорит, что LLM пишет
драфты сценариев. Значит формат должен быть таким, чтобы (а) LLM попадала в него без обучения,
(б) человек правил его в любом редакторе, (в) git-diff был читаемым по словам.

**ALTERNATIVES.**

* **A. Свой DSL с собственной грамматикой.** Максимальная выразительность, точные ошибки.
  Отвергнут: грамматика + парсер + сообщения об ошибках + подсветка + форматтер + миграции синтаксиса —
  это отдельный продукт. Charter §2: один разработчик. `INFERENCE` Цена входа для LLM тоже выше:
  на выдуманный синтаксис нет корпуса, и модель будет его галлюцинировать.
* **B. Структурированный YAML/JSON-проект, который человек правит руками.** Полностью типизирован,
  тривиально валидируется zod. Отвергнут: **текст ролика перестаёт быть текстом**. Проза, разрезанная
  на массив объектов, не пишется и не читается; git-diff по правке одного слова показывает перестройку
  структуры; LLM-драфт превращается в задачу генерации схемы, а не письма.
* **C. Fountain / формат киносценария.** Есть стандарт и инструменты. Отвергнут: Fountain описывает
  *реплики персонажей и сцены съёмки*, а не «текст диктора + иллюстрации + шаблоны». Пришлось бы
  насиловать чужую семантику, и всё равно потребовались бы свои расширения.
* **D (RECOMMENDED). Markdown + YAML frontmatter + ЗАКРЫТЫЙ набор inline-маркеров, разбираемый
  честным span-aware парсером.**

**RECOMMENDED — формат.**

```markdown
---
schemaVersion: 1
chapter: intro                 # файл = одна глава (или главы объявляются внутри)
voice: { preset: narrator-ru }
style: shorts-default
---

## scene: hook

Ты думаешь, что знаешь, как выглядит Марс. [img: mars-globe] Но эта фотография
сделана не телескопом. [beat: reveal] Её сделал аппарат, который сгорел
двадцать лет назад. [pause: 400ms]

## scene: body

[tpl: lower-third | title="Mars Global Surveyor", subtitle="1997—2006"]
Он проработал [emph]девять лет[/emph] вместо запланированных двух.
```

Правила формата (все проверяются компилятором):

1. **Маркер** — это `[` + имя из закрытого списка + `:` + аргументы + `]`. Имя матчится
   `[a-z][a-z0-9-]*`. Форма `[слово: …]` **зарезервирована**: если имя не из списка — это ошибка
   компиляции «unknown marker», а не проза. Литеральная скобка в прозе экранируется: `\[`.
   `INFERENCE` Это единственное правило, которое одновременно снимает конфликт с markdown-ссылками
   `[текст](url)` и делает опечатку в имени маркера видимой сразу, а не через месяц в кадре.
2. **Точечные и парные маркеры.** Точечный (`[img:]`, `[beat:]`, `[pause:]`) привязывается к границе
   между соседними словами: `{anchor, side: 'before'|'after'}`. Парный (`[emph]…[/emph]`) задаёт диапазон
   якорей. Экстент точечных «действующих» маркеров (`[img:]`) документирован: действует до следующего
   маркера того же вида или до конца сцены.
3. **Структура — только заголовками.** `## scene: <id>` и `# chapter: <id>`. Идентификаторы **явные**,
   дубликаты — ошибка. Следствие: граница главы всегда попадает между абзацами, то есть на границу
   предложения (правило R7 из §4) — по построению, а не по проверке.
4. **Frontmatter** — только параметры, не содержание.
5. **`[tpl: id | k=v]`** — это V3 в исходнике: вызов с параметрами, не материализация.

**RECOMMENDED — уровни компиляции. Нужен ли AST/IR: доказательство.**

Проверяем каждый уровень на **необходимость**, а не на красоту. Уровень нужен, если без него какое-то
требование Charter становится невыполнимым или непроверяемым.

| Уровень | Нужен? | Доказательство |
|---|---|---|
| **ScriptAST** (span'ы, слова, маркеры) | **ДА, но не как артефакт** | Без span'ов невозможны: (а) V5 — вырезание маркеров с сохранением соответствия; (б) якоря V1 — детерминированная токенизация; (в) сообщения об ошибках с позицией; (г) проверка инварианта V4 с указанием места. Персистить его не нужно: он полностью вырождается в `Timeline` + span-map, а лишний артефакт — это лишний ключ кэша и лишняя миграция. |
| **Timeline** (сэмплы, renderer-agnostic) | **ДА** | Это единственное место, где сходятся текст, голос и правки. К нему привязан Policy Guard (r3 §5: guard работает на компиляции, не в рендере). Он **не зависит от fps и renderProfile** — а значит смена fps не трогает то, к чему привязаны overrides. |
| **RenderIR** (кадры, chapter-relative, целочисленный) | **ДА** | `FACT` r2 §8.1 — это единственная реальная страховка от двух сценариев: (а) AC2/AC3 не выполняются на CPU без GPU и нужен другой backend; (б) реализуется лицензионный риск Remotion (r2 §9.1). В обоих случаях меняется адаптер, а не движок. Плюс: IR — это то, что хэшируется в ключ кэша сегмента. |

**Контр-проверка (можно ли схлопнуть Timeline и RenderIR в один уровень?).** Нет, и причина
арифметическая, а не эстетическая: `Timeline` живёт в сэмплах и абсолютен по проекту, `RenderIR`
живёт в кадрах и **относителен началу главы**. Если объединить, в единственном артефакте окажется
абсолютное положение главы — и тогда правка длительности главы 1 меняет хэш глав 2..N,
то есть AC3 перестаёт выполняться (подробно в §6.3). Разделение уровней здесь — не слой абстракции,
а прямое условие инкрементальности.

**Уточняю V5 (частично оспариваю формулировку).** Charter пишет: «нужен **алигнер** original ↔ normalized
текста». `FACT` r1 §1.5 показывает более дешёвый и более надёжный путь: нормализовать текст **самим** и
слать `apply_text_normalization: "off"` — тогда `alignment` посимвольно совпадает с нашей строкой.
Значит, нужен не алигнер (fuzzy sequence alignment двух независимо полученных строк), а
**нормализатор-трансдьюсер**: чистая функция, которая возвращает нормализованный текст **вместе со
span-map** `original → normalized`. Разница практическая: трансдьюсер — это O(n) детерминированный код,
покрываемый табличными тестами; выравнивание последовательностей — эвристика с порогами, которую
нельзя доказать. Fuzzy-алигнер остаётся, но только как **fallback** для провайдера с
`canDisableNormalization === false` (capability из r1 §6). `UNKNOWN` — для русского языка объём работы
нормализатора (числа, падежи числительных, даты, аббревиатуры) не оценён; см. спайк S3.

**WHY.**

* Markdown+маркеры — единственный из четырёх вариантов, где **проза остаётся прозой**. Это важнее
  выразительности: контент движка — говорящий текст, а якоря V1 — это слова этого текста.
* Закрытый список имён маркеров превращает «свой DSL» в «свой словарь». Словарь растёт добавлением
  строки в реестр и zod-схемы аргументов; грамматика при этом не меняется никогда.
* `INFERENCE` LLM пишет markdown лучше, чем что-либо ещё, и промпт «вставляй `[img: <id>]` там, где
  нужна иллюстрация» короче любого описания синтаксиса.

**TRADE-OFFS.**

* Выразительность ограничена: сложная вложенная анимация в квадратных скобках не выражается.
  Осознанно: такие вещи выражаются `[tpl: …]` с параметрами (V3), а не расширением синтаксиса.
* Экранирование `\[` — небольшой налог на прозу, где реально нужны квадратные скобки.
* Парсер надо писать самому (markdown-библиотека даёт блоки, но не наши span'ы внутри инлайна).
  `INFERENCE` Это ~день работы и он неизбежен при любом варианте, кроме B.
* Слияние git-веток по одному `.md` — обычный текстовый мерж. `INFERENCE` Риск: мерж может породить
  дубликат `scene: id` — поэтому дубликаты обязаны быть ошибкой компиляции, а не «последний выигрывает».

→ **ADR-0003** (формат исходника), **ADR-0004** (уровни компиляции и IR), **ADR-0011** (нормализатор и V5).

## 4. РЕШЕНИЕ 3 — Модель таймлайна: слои времени, округление, дрейф

**CURRENT IDEA.** «Время — это секунды с плавающей точкой; где нужно — умножим на fps и округлим.»
Это состояние по умолчанию в любом JS-проекте и источник всех накопительных ошибок.

**PROBLEM.** У нас **три несовместимых представления времени**, и они конфликтуют численно:

* TTS отдаёт **секунды float** по символам (`FACT` r1 §1.3).
* Аудио физически существует в **целых сэмплах**; склейка чанков — это сложение количеств сэмплов
  (`FACT` r1 §3.3: «тайминги живут в сэмплах, не в секундах»).
* Видео существует в **целых кадрах**; Remotion оперирует `frameRange`/`durationInFrames`
  (`FACT` r2 §2.1).

Каждое преобразование между ними — источник ошибки. AC5 даёт всего **80 мс** бюджета на всю цепочку,
причём часть этого бюджета съедает сам измерительный прибор: `FACT` r1 §4.3 — средняя ошибка границы
слова у MFA ~20 мс, у WhisperX ~110 мс. `INFERENCE` Значит, на арифметику движка остаётся порядка
40–50 мс, и накопительный дрейф недопустим в принципе — он съест бюджет к середине ролика.

Три конкретных механизма дрейфа, каждый из которых убивает AC5 самостоятельно:

1. **Склейка mp3.** `FACT` r1 §3.2: encoder delay 576 + decoder delay ~529 сэмплов на голову и до
   1152 сэмплов паддинга на хвост — до **~51 мс на один стык**, накопительно. Это уже закрыто V6.
2. **Округление длительностей вместо позиций.** Если каждое слово переводить в кадры как
   `round(duration * fps)` и складывать, ошибка складывается тоже.
3. **Расхождение видео и аудио на стыке глав.** Видео существует только целыми кадрами, аудио —
   сплошное. Если длина главы в сэмплах не кратна длине кадра, конкатенация сегментов
   даёт накопительный сдвиг звука относительно картинки.

**ALTERNATIVES.**

* **A. Секунды (float) как основное время, кадры считаются на лету.** Отвергнуто: недетерминированные
  сравнения, накопительная ошибка, невозможность точного хэширования IR (§7).
* **B. Кадры как единственное время (всё квантуется сразу при импорте таймингов TTS).**
  Заманчиво просто. Отвергнуто: при 30 fps шаг квантования 33 мс, и **аудио-монтаж** (паузы, дакинг,
  склейка чанков) вынужден был бы округляться до кадров — это слышимые артефакты и потеря точности
  там, где она есть бесплатно.
* **C. Рациональные числа/тики (как timebase в ffmpeg, напр. 1/90000).** Универсально и точно.
  Отвергнуто как избыточное: у нас **уже** есть естественный тик — сэмпл. Введение второго тика
  означает два преобразования вместо одного.
* **D (RECOMMENDED). Три явных домена времени с односторонними преобразованиями и инвариантом
  делимости.**

**RECOMMENDED — три домена.**

| Домен | Единица | Кто производит | Кто потребляет |
|---|---|---|---|
| **Текстовый** (порядковый) | слово → предложение → бит → сцена → глава | парсер | автор, шаблоны, overrides |
| **Сэмплы** (физический) | целое при `sampleRate` | компилятор Timeline из VoiceTake | аудио-монтаж, Policy Guard, проверки AC5 |
| **Кадры** | целое при `fps` | компилятор RenderIR, **ровно один раз** | рендерер, ffmpeg |

**Семь правил, каждое из которых закрывает конкретный механизм дрейфа.**

* **R1. Секунды не хранятся нигде.** Ни в одном артефакте нет поля в секундах. Секунды существуют
  только (а) на границе TTS-провайдера, где немедленно конвертируются в сэмплы, и (б) на экране.
* **R2. Инвариант делимости: `fps` — целое и `sampleRate % fps == 0`.** Тогда
  `S = samplesPerFrame = sampleRate / fps` — целое, и граница кадра точно выражается в сэмплах.
  Проверяется при загрузке `project.yaml`. Допустимые пары включают 24000/30 (S=800),
  24000/60 (S=400), 44100/30 (S=1470), 44100/60 (S=735), 48000/30 (S=1600), 48000/60 (S=800).
  **Дробные fps (29.97) запрещены** — они несовместимы и с делимостью, и с AC4.
  `INFERENCE` Это ограничение бесплатно: YouTube принимает 30/60, а NTSC-совместимость нам не нужна.
  `FACT` r1 §3.2: `pcm_24000` доступен без тарифа Pro (44.1 кГц PCM/WAV требует Pro) — то есть
  дефолт 24000/30 реализуем сразу и остаётся делимым.
* **R3. Квантуются ПОЗИЦИИ, а не длительности.**
  `frame(sample) = (2·sample + S) div (2·S)` — округление к ближайшему, полуцелые вверх,
  **целочисленной арифметикой** (удвоенный знаменатель нужен, потому что `S` может быть нечётным,
  например 735). Длительность получается вычитанием: `duration = frame(end) − frame(start)`.
  Ошибка каждой границы ограничена ±½ кадра и **не накапливается**, потому что каждая позиция
  считается от нуля независимо. `INFERENCE` Проверка на переполнение: 20 минут при 48 кГц — это
  5.76·10⁷ сэмплов; `2·sample·fps` при fps=60 даёт 6.9·10⁹ < 2⁵³, то есть в `number` JS безопасно;
  формула с `S` ещё меньше. Тем не менее компилятор обязан ассертить верхнюю границу.
* **R4. Смещение чанка — это сумма реально склеенных сэмплов**, а не пересчёт из секунд
  (`FACT` r1 §3.3). `offset(k) = Σ_{i<k} numSamples(i)`, где `numSamples` берётся из PCM,
  а не из ответа API. Вставленная между чанками тишина тоже задаётся в сэмплах и входит в сумму —
  тогда пауза детерминирована и не зависит от того, что модель сделает с `<break>`
  (`FACT` r1 §2.2: SSML-паузы моделью интерпретируются, а не вставляются буквально).
* **R5. Схлопывание при квантовании чинится СЛИЯНИЕМ, не сдвигом.** Если два соседних слова попали в
  один кадр, они становятся **одним caption-токеном** (показываются вместе). Сдвиг «подвинем второе
  слово на кадр вперёд» — это ровно тот механизм, который порождает накопительный дрейф.
  `INFERENCE` При 30 fps в один кадр попадают слова короче 33 мс — это редкость даже для быстрой речи
  (речь ~3 слова/сек ⇒ ~330 мс на слово), но короткие служебные слова («и», «в», «не») туда попадают
  реально; слияние даёт естественный результат «и в» одним токеном. Порог требует замера — спайк S4.
* **R6. Граница главы кратна `S`.** После расчёта содержимого главы её длина добивается тишиной
  до ближайшего сверху кратного `S`: `lengthSamples = ceil(raw / S) · S`. Тогда
  `durationInFrames = lengthSamples / S` **точно**, а сумма сегментов точно равна длине аудио-дорожки.
  `INFERENCE` Максимальная добавка — `S − 1` сэмплов, то есть <33 мс при 30 fps: неслышимо на паузе
  между главами (глава по построению кончается на границе предложения, R7).
* **R7. Граница главы — только на границе предложения.** Обеспечивается форматом (§3, правило 3:
  главы объявляются заголовками, то есть между абзацами) и проверяется компилятором.

**Уточняю V1 (не оспариваю).** «Никогда к абсолютным секундам» относится к **речевому** таймлайну.
У ассетов с собственным внутренним временем (музыкальный трек, видео-вставка) есть внутреннее время
в сэмплах **относительно начала самого ассета** — иначе нельзя сказать «играй с 0:12 трека».
Их **размещение** на таймлайне всё равно анкоро-привязано. Формально: `Clip.placement` — анкоро-относителен,
`Clip.sourceStartSample` — внутреннее время ассета. Смешивать их запрещено типами.

**Биты.** `[beat: reveal]` — именованный псевдоним над word-якорем. Биты существуют, чтобы шаблоны и
правки ссылались на смысл («на слове „сгорел“»), а не на порядковый номер слова. Технически бит —
это `Marker`, порождающий якорь `b:reveal`, разрешающийся в тот же интервал сэмплов, что и его слово.

**WHY.** Каждое из семи правил — ответ на конкретный измеренный или задокументированный механизм
ошибки, а не на общее соображение. R2+R6 вместе дают свойство, которого нет ни в одном research-документе,
но которое требуется приёмочным вопросом №3: **видео, собранное из независимо отрендеренных глав,
совпадает с непрерывной аудио-дорожкой по построению, без подгонки**.

**TRADE-OFFS.**

* Инвариант R2 отнимает свободу выбора `sampleRate`/`fps`. `FACT` r1 §3.2: провайдер отдаёт фиксированный
  набор (`pcm_8000/16000/22050/24000/32000/44100/48000`). `22050 % 30 = 0` (S=735), `22050 % 60 ≠ 0`
  (367.5) — то есть при 22050 доступен только 30 fps. Компилятор обязан отвергать несовместимые пары
  с внятным сообщением, а не «подстраивать» их.
* R5 (слияние) означает, что подсветка «по словам» иногда подсвечивает два слова сразу. Альтернатива
  (сдвиг) даёт дрейф. Выбор в пользу точности.
* Целочисленная арифметика везде — код многословнее, чем `sample / sampleRate * fps`. Принимаем:
  это цена AC4 и AC5.
* Домен «биты» добавляет ещё один слой имён, который надо не запутать со сценами. Смягчение: биты
  живут в том же пространстве якорей с префиксом `b:`, коллизии имён — ошибка компиляции.

→ **ADR-0001** (модель времени и якоря).

## 5. Якоря: как правка переживает регенерацию голоса

Это отдельный подраздел решения 3, потому что от него зависят ответы на два из трёх приёмочных вопросов.

**PROBLEM.** Якорь должен быть стабилен относительно того, что меняется часто (тайминги, голос,
соседние сцены), и меняться, когда меняется то, к чему он привязан (само слово).

**ALTERNATIVES.**

* **A. Порядковый номер (`w0001`).** Вставка слова в начало сдвигает все последующие. Отвергнуто.
* **B. Случайный id, дописываемый форматтером в исходник (`слово[#w7f2]`).** Максимальная стабильность:
  id живёт в файле и не зависит ни от чего. Отвергнуто **как дефолт**: засоряет прозу, ломает
  читаемость драфта от LLM, требует форматтера-мутатора исходника (а значит — конфликтов при мерже).
  Остаётся как явный опт-ин для «прибитых» мест (см. TRADE-OFFS и §16).
* **C (RECOMMENDED). Контент-производный id.**
  `anchorId = "w:" + base32(blake3(scopeId ‖ 0x00 ‖ normalizedForm ‖ 0x00 ‖ occurrenceIndex))[:10]`,
  где `scopeId` — id **сцены** (явный, из исходника), `normalizedForm` — форма слова после
  нормализации V5, `occurrenceIndex` — порядковый номер этого же слова **внутри сцены**.

**WHY C.** Ключевое свойство: **регенерация TTS не меняет текст, следовательно не меняет якоря.**
Меняются секунды — а секунд в якоре нет. Это и есть механизм, которым V1 переживает V2:
правка «пауза 350 мс после слова „сгорел“» остаётся осмысленной после любого числа перегенераций,
смены голоса и смены провайдера.
Второе свойство: правка в одной сцене не трогает якоря другой сцены (scope = сцена).
Третье: правка слова «кот»→«пёс» меняет якорь только этого слова; якоря слова «и» рядом не двигаются,
потому что их `occurrenceIndex` считается по своей форме.

**TRADE-OFFS (честно, это самое слабое место документа — см. §16).**

* Правка слова **уничтожает якорь того самого слова**, ради которого правка и делалась. Правка
  становится stale и требует ревью. Это правильно семантически (слово другое — правка может быть
  бессмысленной), но раздражает на практике.
* Изменение **числа повторов** одного слова в сцене сдвигает `occurrenceIndex` у последующих
  одинаковых слов. Пример: в сцене три «Марс»; удаление первого превращает `Марс#2`→`Марс#1`,
  и правка, висевшая на втором, уезжает на третий. Это тихая ошибка — худший класс.
  **Митигация:** каждая override-запись несёт `boundTo` — отпечаток контекста (хэш соседних 3 слов);
  несовпадение делает правку stale, а не переехавшей. Тихого переезда быть не должно (§7, §16).
* Переименование сцены меняет **все** якоря сцены. Митигация: id сцен явные, переименование —
  осознанное действие; команда `vpe scene rename` переносит overrides.
* `UNKNOWN` Реальная частота «churn» якорей при живом редактировании не измерена — спайк S5.

## 6. РЕШЕНИЕ 4 — Формат проекта на диске: git, кэш, миграции, overrides

**CURRENT IDEA.** «Проект — это папка с `project.json`, куда движок пишет всё, что насчитал.»
Через месяц в этом файле оказываются вперемешку авторские решения и результаты вычислений,
и отличить одно от другого невозможно.

**PROBLEM.** Charter V2 требует разделить generated и overrides. Но «разделить» — это не про папки,
а про три конкретных вопроса, на которые нужен ответ до первой строки кода:

1. Что коммитится в git, а что перевычислимо? Ошибка в обе стороны дорогая: закоммитить
   перевычислимое — раздуть репозиторий и получить конфликты на каждом билде; не закоммитить
   невоспроизводимое — потерять его навсегда.
2. `FACT` r1 §2.3: TTS детерминизм — «best effort», **не гарантирован**. Значит аудио **невоспроизводимо**
   и обязано быть артефактом, а не результатом сборки.
3. AC6 требует, чтобы старый проект открывался новой версией. Мигрировать надо не только json,
   но и **диалект исходников** (набор маркеров меняется) и **каталог операций overrides**.

**ALTERNATIVES.**

* **A. Один большой `project.json`.** Отвергнут: смешивает слои, не мержится, инвалидирует всё при
  любой правке.
* **B. SQLite как формат проекта** (Charter §6 упоминает SQLite как предпочтение).
  **Оспариваю применение SQLite в роли формата проекта, а не сам инструмент:** V2 требует, чтобы правки
  были отдельным, обозримым слоем; ревью правки, git-diff и мерж ветки с LLM-драфтом — это текстовые
  операции. Бинарный файл их не поддерживает. SQLite остаётся в проекте, но как **перестраиваемый
  локальный индекс кэша** (`.cache/index.sqlite`), где его сильные стороны (запросы по ключам,
  транзакции, GC) применимы, а слабые (мерж) неважны, потому что файл в git не попадает.
* **C (RECOMMENDED). Файлы, разделённые по природе: authored / generated-and-committed /
  generated-and-disposable.**

**RECOMMENDED — раскладка.**

```
project.yaml                    git      schemaVersion, fps, геометрия, sampleRate, seedRoot,
                                         дефолты голоса, ссылка на renderProfile
source/NN-name.md               git      AUTHORED: проза + маркеры + frontmatter
overrides/*.yaml                git      AUTHORED: типизированные записи правок (V2)
assets/assets.lock.json         git      sha256 → provenance (r3 §3.4): три статуса, снимок лицензии, …
assets/store/ab/cd/<sha256>.*   LFS/ext  content-addressed бинарники
voice/voice.lock.json           git      chunkKey → {sha256, provider, model, voice, seed,
                                         generatedAt, billedUnits, planTier}
voice/<sha256>.flac             LFS      GENERATED-AND-COMMITTED: невоспроизводимо (r1 §2.3)
voice/<sha256>.align.json       git      тайминги в СЭМПЛАХ + span-map
fonts/…                         git      шрифты — тоже ассеты с provenance (V10, r2 §8.5)
templates/…                     git      параметры и стили, не реализация
build/                          ignored  timeline.json, ir/*.json, segments/*.ts,
                                         audio/track.flac, reports/policy.json, final.mp4
.cache/                         ignored  CAS по ключам + index.sqlite (перестраиваемый)
```

Три класса файлов и правило для каждого:

* **AUTHORED** — пишет человек или LLM. Только это правится руками. Мержится текстом.
* **GENERATED-AND-COMMITTED** — произведено машиной, но **невоспроизводимо** (голос) или дорого
  (ресайзнутые ассеты). Коммитится, руками не правится, имеет lock-файл с provenance.
* **GENERATED-AND-DISPOSABLE** — всё, что чистая функция от первых двух. Никогда не коммитится.

`INFERENCE` **Почему FLAC для голоса.** V6 требует работать в PCM, но хранить сырой PCM расточительно:
24 кГц/16 бит моно = 48 КБ/с, то есть 60-секундный Short ≈ 2.9 МБ, а 20-минутный long-form ≈ 58 МБ.
FLAC — losseless: декодирование даёт **побитово тот же PCM**, поэтому детерминизм не страдает, а объём
примерно вдвое меньше. Проверяется ассертом в тестах (`sha256(decode(flac)) == sha256(pcm)`) — дешёвая
проверка, снимающая единственное сомнение.

**schemaVersion и миграции (V7, AC6).**

* Один `schemaVersion` в `project.yaml` — он задаёт **диалект всего проекта**: синтаксис маркеров,
  схему overrides, схему lock-файлов. У каждого generated-артефакта дополнительно своя
  `timelineVersion` / `irVersion` (их миграция не нужна — они перевычисляются, но версия нужна,
  чтобы отличить «старый кэш» от «нового кода»).
* Миграция — **упорядоченная чистая функция** `vN → vN+1`, включая миграцию **текста исходников**
  (переписывание маркеров), а не только структурных файлов.
* У каждой миграции — **пара фикстур** «до/после» в тестах. Это и есть исполняемая проверка AC6:
  тест открывает фикстуру каждой исторической версии и требует, чтобы она мигрировала и собралась.
* Миграция при открытии: бэкап → запись → отчёт diff → **требование закоммитить**. Молча мигрировать
  git-tracked файлы нельзя. Миграция идемпотентна.
* `UNKNOWN` Необратимые миграции (когда новая схема не выражает старую семантику) — политика ещё не
  определена; сейчас правило простое: такие миграции запрещены, версия схемы бампается только
  расширяющими изменениями. Это ограничение стоит пересмотреть, когда оно первый раз помешает.

**Overrides (V2) — механизм.**

**Оспариваю «patch» в буквальном смысле.** V2 говорит «правки живут в отдельном overrides-слое
(patch поверх generated-артефакта)». Если понимать patch как **JSON Patch (RFC 6902) по указателям**,
это не работает: указатель `/chapters/0/clips/7` протухает от вставки одного слова, а вставка слова —
самая частая правка в этом движке. Предлагаю понимать «patch» как **типизированную запись с ключом-
идентификатором**:

```yaml
- id: ov-0007
  target: { kind: anchor, anchorId: "w:7f2ab91c3d" }
  op: speech.pauseAfter
  value: { ms: 350 }
  reason: "нужен воздух перед раскрытием"
  createdAt: "2026-08-19T12:31:00Z"
  boundTo: "ctx:9a1f…"        # отпечаток контекста, к которому привязались
```

Правила слоя overrides:

1. **Схема физически не умеет выразить абсолютные секунды.** Поля времени — только
   `{anchor, offsetMs}` либо внутреннее время ассета. V1 обеспечивается типами, а не дисциплиной.
2. **Overrides не меняют структуру, только параметры.** Добавить сцену, переставить главы, изменить
   текст — это правка исходника. `INFERENCE` Это правило и есть то, что делает слияние
   «новый драфт от LLM + мои старые правки» осмысленным: структура приходит из одного места.
3. **Дубликат пары `(target, op)` — ошибка компиляции**, а не «последний выигрывает». Тогда порядок
   применения не влияет на результат, и детерминизм фолда получается бесплатно (V8).
4. **`boundTo`** — отпечаток того, к чему привязались (контекст слова; для правок, зависящих от
   конкретного дубля — ещё и `takeId`). Несовпадение ⇒ запись помечается **stale**: не применяется
   молча и не выбрасывается, а попадает в отчёт и в `vpe overrides review`.

**Каталог операций (закрытый, версионируемый вместе со схемой):**

| Категория | Примеры op | Что с ними при регенерации TTS | Что при правке текста |
|---|---|---|---|
| Речь (вход TTS) | `speech.pronounce`, `speech.pauseAfter`, `speech.chunkBreak` | переживают: это **входы** запроса, они меняют сам запрос | переживают, если якорь цел |
| Субтитры | `caption.text`, `caption.merge`, `caption.split`, `caption.nudge` | `nudge` завязан на дубль ⇒ **stale**; остальные переживают | зависит от якоря |
| Визуал | `visual.asset`, `visual.focal`, `visual.fit` | не затронуты | привязаны к маркеру, переживают |
| Шаблоны (V3) | `template.params` | не затронуты | переживают |
| Микс | `mix.gain`, `mix.duck` | переживают (анкоро-привязаны) | переживают |
| Политика (V11) | `policy.ack` | переживают | переживают, с датой и причиной (r3 PG-F7) |

**«Eject» из V3.** Команда `vpe template eject <markerId>` заменяет `[tpl: id | params]` в **исходнике**
на развёрнутый набор примитивных маркеров и/или на локальный шаблон в `templates/`. Это правка
AUTHORED-файла, видимая в git-diff, и она необратима — ровно как требует V3 («только явный ручной eject»).

**WHY.** Разделение на три класса файлов отвечает на вопрос «что произойдёт, если удалить папку X»:
удаление `build/` и `.cache/` не теряет ничего; удаление `voice/` теряет деньги и точную копию голоса;
удаление `source/`, `overrides/`, `*.lock.json` теряет работу. Такое разделение — не косметика,
а рабочая инструкция по бэкапу.

**TRADE-OFFS.**

* Голос в git-LFS — внешняя зависимость и лимиты хостинга. `INFERENCE` На 30 роликов по 60 секунд это
  ~90 МБ FLAC — терпимо и без LFS; на long-form понадобится LFS или внешнее хранилище с lock-файлом.
  Решение отложено осознанно: формат (`voice.lock.json` + content-addressed файлы) от места хранения
  не зависит.
* Запрет структурных правок в overrides иногда неудобен («хочу поменять местами две сцены, не трогая
  текст»). Принимаем: перестановка абзацев в markdown — тривиальная текстовая операция.
* Закрытый каталог op'ов означает, что каждая новая возможность правки требует записи в каталог,
  zod-схемы и миграции. Это налог, но он же — единственное, что не даёт overrides превратиться в
  свалку произвольного JSON.

→ **ADR-0005** (формат на диске и миграции), **ADR-0006** (модель overrides).

## 7. РЕШЕНИЕ 5 — Кэш по содержимому

**CURRENT IDEA.** «Кэшируем по времени модификации файлов: если `.md` новее, чем сегмент — пересобрать.»
Классика, и она ломается на первом же откате правки: файл новее, содержимое старое, кэш промахивается;
или наоборот — `git checkout` не трогает mtime, и движок отдаёт устаревший кадр.

**PROBLEM.** AC3 требует «правка одной сцены → пересборка затронутой части ≤ 3 минут», при том что
`FACT` r2 §10.1 показывает: полный рендер даже 60-секундного ролика — это бюджет ≥2 кадров/сек, а
для long-form полный рендер измеряется часами. `INFERENCE` r2 §10.1 формулирует это жёстко:
инкрементальность — не оптимизация, а условие пригодности. Значит нужен кэш, у которого
**промах/попадание доказуемы**, а не вероятны.

Второе: TTS — не чистая функция (`FACT` r1 §2.3, детерминизм «не гарантирован») и стоит денег
(`FACT` r1 §4.1: $0.10/1k символов). Обычный кэш чистых функций для него **неприменим**:
промах ключа не должен молча приводить к сетевому вызову.

**ALTERNATIVES.**

* **A. mtime/размер.** Отвергнуто, см. CURRENT IDEA.
* **B. Один хэш всего проекта.** Тривиально корректно, бесполезно: любая правка инвалидирует всё.
* **C. Кэш на уровне файлов Remotion (`--frames`, кэш браузера).** Отвергнуто: привязывает
  инкрементальность к рендереру, то есть ровно к тому, от чего страхует `RenderIR` (r2 §8.1).
* **D (RECOMMENDED). Стадийный content-addressed кэш: у каждой стадии свой ключ из явно
  перечисленных входов, инвалидация — только по несовпадению ключа.**

**RECOMMENDED — стадии и состав ключей.**

Ключ = `blake3(канонический JSON входов ‖ stageVersion)`. Канонизация: сортированные ключи,
без незначимых пробелов, UTF-8, только целые числа (см. §8).

| Стадия | Ключ из | Выход |
|---|---|---|
| `parse` | байты файла, `parserVersion` | AST (в памяти) |
| `speechPlan` | AST сцены, `normalizerVersion`, TTS-настройки | чанки + якоря |
| `voice` ⚠ | текст чанка ⊕ stitch-контекст, `providerId`, `modelId`, `voiceId`, `seed`, опции | VoiceTake |
| `timeline` | AST, VoiceTake'и, overrides, `assets.lock`, `compilerVersion` | `timeline.json` |
| `renderIr` | глава Timeline, `fps`, геометрия, `templateRegistryVersion` | `ir/chapter-NN.json` |
| `segment` | `hash(RenderIR[chapter])`, `hash(renderProfile)` | `segments/chapter-NN.ts` |
| `audioTrack` | VoiceTake'и, музыка/sfx (sha256), настройки микса, overrides, `audioPipelineVersion` | `audio/track.flac` |
| `final` | хэши сегментов, хэш аудио, `muxProfile` | `final.mp4` |

Заметьте, чего в ключе `segment` **нет**: отдельного перечисления checksum'ов ассетов и шрифтов.
r2 §8.3 предлагает их отдельным слагаемым; у нас они уже внутри `RenderIR` (ассеты и шрифты
адресуются по `sha256` по построению), поэтому отдельное слагаемое было бы дублированием, которое
легко рассинхронизировать. `renderProfile` в ключе — обязателен, и обоснование r2 §8.3 принимается
целиком: апгрейд Remotion меняет версию Chrome, а значит потенциально субпиксельный рендер текста;
без профиля в ключе получится «валидный по кэшу, но визуально другой» сегмент — шов, который заметен
только при просмотре на телефоне.

**⚠ Стадия `voice` — мемоизация эффекта, а не чистой функции.** Правила:

1. Промах ключа **не вызывает сеть по умолчанию**. Сборка падает с сообщением
   «нет дубля для чанка X; выполните `vpe voice sync`». Сеть включается только явным `--allow-tts`.
2. Результат записывается в `voice.lock.json` и коммитится. Старые дубли **не удаляются** —
   это делает возможными A/B и мгновенный откат.
3. В ключ входит stitch-контекст (`previous_text`/`previous_request_ids`, `FACT` r1 §3.1),
   потому что от него зависит просодия, — см. цену в §7.2.

### 7.1 Ключевое свойство: chapter-relative IR

**RenderIR главы не содержит её абсолютного положения в проекте.** Абсолютные смещения живут в
assembly-манифесте, который стоит копейки пересчитать. Следствие:

> Изменение длительности главы 1 **не инвалидирует сегменты глав 2..N.**

Именно это делает AC3 достижимым: правка в начале ролика не заставляет перерисовывать хвост.
Это свойство надо защищать явно, потому что оно ломается тихо. Ломают его:

* **шаблон, зависящий от абсолютного времени** (прогресс-бар «3:45 / 10:00», сквозной счётчик глав
  «Глава 2 из 7», анимация, продолжающаяся между главами);
* **визуал, синхронизированный с музыкой** (музыка глобальна, значит её фаза в главе K зависит от
  длительностей глав до неё);
* **субтитры с контекстом соседней главы** (например, «предыдущая фраза» в кадре).

Решение: такие шаблоны обязаны декларировать `globalTimeDependency: true`. Компилятор тогда включает
`projectDuration`/`chapterOffset` в IR этой главы — и она честно становится cache-hostile, о чём
сборка сообщает. `INFERENCE` Важна не сама возможность, а то, что она **явная**: незадекларированная
зависимость от глобального времени — ошибка компиляции, а не тихая порча кэша.
Проверяется тестом: собрать проект, удлинить главу 1, убедиться, что ключи сегментов 2..N не изменились.

### 7.2 Цена stitch-контекста (арифметика на AC1)

`FACT` r1 §3.1: `previous_request_ids` — до 3 предыдущих генераций; результаты лучше при одной модели;
id живут 2 часа. `INFERENCE` На AC1 (~150 слов) чанк = абзац ⇒ примерно 6 чанков. Правка одного слова
меняет ключ своего чанка и ключи тех чанков, в контекст которых он входит, — то есть до 3 последующих.
Итого до 4 из 6 чанков перегенерируются: ~150 слов ≈ 900 символов ⇒ ≈$0.09 по цене v2
(`FACT` r1 §4.1) и десятки секунд. Приемлемо. На long-form (20 минут) правка одного слова тоже
затрагивает лишь 4 чанка — стоимость не растёт с длиной, растёт только с числом правок.
Настройка `stitch.contextDepth: 0|1|3` позволяет обменять просодию на дешевизну итераций;
дефолт — 1 (предыдущий чанк), а не 3: `INFERENCE` выигрыш просодии от 3 против 1 не измерен,
а цена инвалидации утраивается. Пересмотреть после спайка S3.

### 7.3 `stageVersion`: как не забыть его бампнуть

Ключ обязан меняться, когда меняется **код** стадии, иначе после правки компилятора кэш отдаст
результат старой логики. Варианты: (а) хэш исходников пакета, (б) хэш собранного бандла,
(в) ручная константа. Хэш исходников меняется от переименования переменной и обнуляет кэш каждый день;
хэш бандла зависит от сборщика и его версии. **RECOMMENDED: ручная константа `stageVersion` + тест,
который падает, если хэш исходников пакета изменился, а константа — нет.** Тест хранит «золотой» хэш
в файле рядом; разработчик либо бампает версию, либо обновляет золотой хэш с комментарием
«поведение не изменилось». `INFERENCE` Это перекладывает решение «изменилось ли поведение» на человека
в тот момент, когда он единственный, кто это знает.

**Инвалидация и уборка.** Инвалидации как отдельного механизма нет: несовпадение ключа = промах.
GC — LRU по времени последнего доступа с пинами на «текущий HEAD проекта».
`.cache/index.sqlite` хранит только индекс (ключ → путь → размер → last access) и перестраивается
сканированием каталога.

**WHY.** Content-addressed кэш — единственная схема, в которой «что пересчитается» можно **объяснить
словами до запуска**, а не наблюдать постфактум. Это прямо требуется приёмочным вопросом №1.

**TRADE-OFFS.**

* Явное перечисление входов каждой стадии — источник ошибок вида «забыли вход». Митигация: вход,
  не попавший в ключ, обязан быть недоступен коду стадии (передаётся только то, что хэшируется);
  плюс тест «два разных входа → два разных ключа» на каждую стадию.
* Content-addressed хранилище растёт. Для long-form с частыми правками — десятки гигабайт.
  GC обязателен, и это работа, которую придётся сделать раньше, чем хочется.
* Правило «промах voice не ходит в сеть» иногда раздражает (новая сцена — сразу ошибка).
  Принимаем: цена ошибки в обратную сторону — незаметный счёт и незаметная потеря детерминизма.

→ **ADR-0007** (кэш по содержимому), **ADR-0011** (граница TTS).

## 8. РЕШЕНИЕ 6 — Детерминизм: где живёт seed, иерархия, как тестируется (AC4)

**CURRENT IDEA.** «Заменим `Math.random()` на `random(seed)` из Remotion и объявим V8 выполненным.»
`FACT` r2 §7.4: `random(seed)` действительно детерминирован. Но это закрывает один из шести
источников недетерминизма, а остальные пять останутся и проявятся именно тогда, когда цена высока.

**PROBLEM.** AC4 требует, чтобы фикстурный проект, отрендеренный дважды, дал одинаковые кадры,
и чтобы это проверялось автоматически. Приёмочный вопрос №3 усиливает требование:
«отрендерить **сегментами** и получить AC4», то есть рендер по главам обязан совпасть с рендером
целиком. Источники расхождения, установленные research'ем:

1. `Math.random`/`Date.now` — `FACT` r2 §7.4: страница открывается несколько раз в нескольких потоках.
2. Эмодзи — `FACT` r2 §7.4: рендерятся операционной системой и различаются между ОС.
3. Системные шрифты — `INFERENCE` r2 §7.4: резолвятся ОС.
4. Версия Remotion = версия Chrome — `FACT` r2 §7.4 (файл `VERSION`), апгрейд меняет растеризацию.
5. GPU-путь — `FACT` r2 §7.4: дефолтный `angle` использует GPU «когда доступен», то есть результат
   зависит от машины.
6. Кодирование — `INFERENCE` r2 §8.7: битовая идентичность mp4 — требование сильнее нужного.

И седьмой, специфичный для сегментации: **seed, вычисленный в рендерере, зависит от того, что
рендерер знает о своём окружении.** Если seed выводится из индекса главы или из счётчика вызовов,
рендер одной главы отдельно даст другой seed, чем рендер её же в составе целого.

**ALTERNATIVES.**

* **A. Один глобальный seed на проект, всё случайное берёт из него по порядку обращения.**
  Отвергнуто: порядок обращения зависит от порядка монтирования компонентов и от конкурентности —
  ровно то, что недетерминировано в многопоточном рендере.
* **B. Seed на композицию, передаётся как prop.** Лучше, но всё ещё вычисляется в рендере и зависит
  от индексов.
* **C (RECOMMENDED). Иерархия выводимых seed'ов, материализуемых в RenderIR на этапе компиляции.**

**RECOMMENDED.**

* `seedRoot: uint32` живёт в `project.yaml` и коммитится. Один на проект.
* Seed любого узла **выводится чистой функцией от пути в модели**, а не от порядка обхода:
  `seed(node) = uint32(blake3(seedRoot ‖ chapterId ‖ sceneId ‖ layerId ‖ templateInstanceId ‖ purpose))`.
  `purpose` — строковый литерал («jitter», «grain», «shuffle»), чтобы два разных случайных
  свойства одного слоя не коррелировали.
* **Seed'ы материализуются в `RenderIR` компилятором.** Рендерер seed'ы не выводит и не знает
  `seedRoot`. Это и есть механизм, обеспечивающий сегментную эквивалентность: значение в IR одно и то же
  независимо от того, рендерится глава одна или в компании.
* **RenderIR целочисленный.** Никаких `float`: дроби — фиксированной точкой (`scaleMilli: 1250` = 1.25).
  Это убирает и класс проблем с канонизацией JSON (`0.1+0.2`, `-0`, экспоненциальная запись),
  и класс «случайно разошлись в последнем бите».
* Канонический JSON для всех хэшей: сортированные ключи, без незначимых пробелов, UTF-8 NFC,
  только целые числа.
* **Линтер (исполнение V8):** запрет `Math.random`, `Date.now`, `new Date()`, `performance.now()`,
  `toLocaleString`, `Intl.*` в пакетах compile- и render-пути. Плюс runtime-guard в entry рендера,
  который заменяет эти глобали на бросающие заглушки. `INFERENCE` r2 §8.6 прав: V8 без линтера —
  это пожелание; но линтер не ловит вызов из зависимости, поэтому нужен и runtime-guard.
* **`now` — вход сборки**, а не значение из окружения: попадает в `BuildRecord`, внутри компиляции
  недоступен. Это же требование r3 §5 к Policy Guard (дата анализа подаётся снаружи).
* `TZ=UTC`, `LC_ALL=C` в процессе рендера и компиляции.
* **Сортировки** — только с явным тотальным порядком и тай-брейком по `id`.
* **`--gl=swangle`** фиксируется в `renderProfile` (`FACT` r2 §7.1: рекомендация самого Remotion для
  машин без GPU; заодно уводит от известных утечек `angle`).
* Шрифты и **шрифт эмодзи** — файлами в проекте с checksum (`FACT` r2 §7.4 п.2, §8.5).

**Как это тестируется.**

| Тест | Что делает | Что доказывает |
|---|---|---|
| **AC4-a: двойной рендер** | отрендерить фикстуру дважды, декодировать в rawvideo, сравнить sha256 **каждого кадра** | воспроизводимость на одной машине. `INFERENCE` r2 §8.7: сравнивать кадры, а не байты mp4, иначе тест будет падать от метаданных и его отключат |
| **AC4-b: сегментная эквивалентность** | отрендерить проект целиком и по главам с конкатенацией; сравнить кадры | **что V4 реален**, а не декларация. Этого теста нет в Charter, но его требует приёмочный вопрос №3 |
| **AC4-c: shuffle-тест компилятора** | перемешать порядок элементов во входных массивах, скомпилировать, сравнить хэш IR | что в компиляторе нет зависимости от порядка и нестабильных сортировок (V8) |
| **AC4-d: тест изоляции рендера** | рендер под запретом сети; `onBrowserLog` ловит попытки | V9 как исполняемое правило (r2 §8.5) |
| **AC4-e: FLAC round-trip** | `sha256(decode(flac)) == sha256(pcm)` | что хранение голоса не портит детерминизм |

`UNKNOWN` **Порог AC4 пока не определён.** `FACT` r2 §7.4 п.7: официального утверждения о побитовой
воспроизводимости headless Chrome нет. Спайк S1 обязан ответить: побитово или с расхождениями,
влияет ли `concurrency`, влияет ли `--gl`. **До результата S1 порог в тесте не кодируется** —
иначе мы либо получим вечно красный тест, либо запишем в норму то, что не проверяли.
От этого же зависит, входит ли `concurrency` в ключ кэша: если он на пиксели не влияет, его можно
исключить и менять свободно.

**WHY.** Материализация seed'ов в IR — единственное из перечисленного, что нельзя добавить потом:
если хоть один шаблон научится выводить случайность сам, сегментная эквивалентность перестанет
выполняться, и обнаружится это не тестом, а швом в готовом ролике.

**TRADE-OFFS.**

* Целочисленный IR неудобен для авторов эффектов: `opacityPermille: 850` читается хуже, чем `0.85`.
  Митигация: конвертация в удобные единицы происходит в адаптере, а не в IR.
* Запрет `Intl`/локалей означает, что форматирование чисел и дат **на экране** придётся делать самим
  (детерминированной таблицей). Для русского это заметная работа. Принимаем: результат влияет на пиксели.
* Материализованные seed'ы раздувают IR (по числу на слой). Незначительно относительно списков токенов.
* Фиксация `swangle` — сознательный отказ от возможного ускорения GPU ради воспроизводимости
  (`INFERENCE` r2 §7.1). Цена не измерена — спайк S2.

→ **ADR-0008** (детерминизм и seed'ы).

## 9. РЕШЕНИЕ 7 — Граница рендерера и сегментация по главам

**CURRENT IDEA.** «Рендерер получает проект и рисует. Разберётся сам, где какая картинка.»
Это состояние по умолчанию у любого Remotion-проекта: в композицию передаётся `inputProps` с
доменной моделью, а компоненты по дороге ходят за ассетами и вычисляют тайминги.

**PROBLEM.** V9 запрещает в рендере сеть, TTS, поиск ассетов и бизнес-логику. Но «запрещает» —
это декларация, пока не сформулирован **контракт входа**. Без него запрет нарушается постепенно:
сначала компонент сам считает длительность, потом сам подбирает картинку, потом делает `fetch`
за шрифтом. `FACT` r2 §7.5 фиксирует техническую цену такого дрейфа: `delayRender()` имеет
таймаут 30 000 мс, а при его превышении **вкладка закрывается и кадр рендерится заново** —
то есть скрытый сетевой вызов превращается в непредсказуемое время рендера, а не в явную ошибку.

Второе: `FACT` r2 §7.1 — Remotion сам рекомендует резать длинные рендеры на части, и два его кэша
по умолчанию берут **по половине системной памяти каждый**. `INFERENCE` На рабочем ноутбуке
это конфигурация, в которой OOM — вопрос времени. То есть сегментация нужна и по V4, и по памяти.

**ALTERNATIVES.**

* **A. Передавать в композицию доменную модель как `inputProps`.** Отвергнуто: рендерер получает
  знание о проекте, IR-граница исчезает вместе со страховкой r2 §8.1.
* **B. Chunking средствами Remotion (`frameRange` + `combineChunks()`).** `FACT` r2 §7.3(a) — это
  first-party механизм, но он требует «каждый чанк рендерит одинаковое число кадров» и «одинаковые
  опции». Отвергнуто как **единица кэша**: у глав разная длина и разное содержимое, а раздельной
  инвалидации механизм не даёт вообще. Заимствуем из него правила, не зависящие от равной длины
  (кодек `h264-ts`, единый набор опций, отдельный аудио-файл).
* **C. Рендерить всё одним куском, а сегменты добавить потом.** Отвергнуто прямой цитатой
  r2 §8.8: это и есть то переписывание, которого просили избежать.
* **D (RECOMMENDED). Глава — единица рендера, кэша и процесса; вход рендерера — только `RenderIR`
  главы + `renderProfile` + карта локальных путей.**

**RECOMMENDED — контракт.**

```ts
interface SegmentRenderRequest {
  readonly ir: RenderIrChapter;                      // кадры, chapter-relative, целые числа
  readonly profile: RenderProfile;                   // всё, что влияет на пиксели/байты
  readonly assetPaths: ReadonlyMap<Sha256, string>;  // ГОТОВЫЕ локальные пути, уже ресайзнутые
  readonly fontPaths: ReadonlyMap<Sha256, string>;
  readonly outputPath: string;                       // немой .ts
  readonly workDir: string;                          // единственное место, куда можно писать
}
interface SegmentArtifact {
  readonly path: string;
  readonly sha256: Sha256;
  readonly frameCount: Frames;        // сверяется ffprobe вызывающей стороной
  readonly profileFingerprint: string;
  readonly diagnostics: readonly string[];
}
type RenderSegment = (req: SegmentRenderRequest, signal?: AbortSignal) => Promise<SegmentArtifact>;
```

**Что рендерер получает (гарантии входа).** Всё по значению или по локальному пути; ни одного URL;
время — в кадрах относительно начала главы; seed'ы материализованы; ассеты уже приведены к целевому
разрешению на этапе ingest (`FACT` r2 §7.2: декодированный битмап 4000×3000 ≈ 48 МБ RSS против ~8 МБ
у 1080×1920); шрифты — локальными файлами с checksum; субтитры — готовым списком токенов с диапазонами
кадров; имена файлов ASCII-safe по checksum (`FACT` r2 §7.2: `staticFile()` сам применяет
`encodeURIComponent`, самому кодировать нельзя — при именах по sha256 весь класс ошибок исчезает).

**Чего рендерер не получает и не делает.** Сети нет и она проверяется (AC4-d). Нет `assets.lock`,
provenance, политики, TTS-настроек, `seedRoot`, абсолютного времени проекта, соседних глав.
Не пишет вне `workDir`/`outputPath`. `delayRender` допустим **только** для загрузки шрифтов —
`INFERENCE` r2 §7.5: `delayRender` вокруг `fetch` в нашей архитектуре не тюнинг таймаута,
а баг архитектуры, и это хороший инвариант для code review.

**Разрешение противоречия V3 ↔ V9.** V3 говорит: шаблоны разворачиваются **при рендере**.
V9 говорит: в рендере нет бизнес-логики. Противоречия нет, если определить «разворачивание» точно:
это **чистая функция `(params, тайминги в кадрах) → визуальные примитивы`**, исполняемая в адаптере.
Она ничего не решает — она рисует. Всё, что требует внешних данных (какой ассет подставить, влезает ли
текст, что говорит политика), решено раньше и лежит в IR. Версия реестра шаблонов входит в
`renderProfile`, то есть в ключ кэша: смена реализации шаблона обязана перерисовать сегмент.

**Сегментация (V4) как исполняемый механизм.**

1. Компилятор `RenderIR` **валидирует** инвариант V4 и падает с указанием `файл:строка`, если эффект,
   звук или анимация пересекает границу главы (`FACT` r2 §8.2: инвариант, который никто не проверяет,
   перестаёт выполняться примерно на тридцатом ролике).
2. Каждая глава рендерится **своим процессом** — это одновременно исполнение рекомендации
   `FACT` r2 §7.1 «split up long renders into multiple parts» и ограничение последствий утечек
   памяти одной главой.
3. Главы рендерятся **немыми** (`muted`), звук — одной сплошной PCM-дорожкой (`FACT` r2 §7.3(b)+V6).
   Это делает проблему стыков аудио **несуществующей**, а не решённой.
4. `renderProfile` фиксирует явные лимиты обоих кэшей памяти, `concurrency`, `gopSize`, `colorSpace`,
   `imageFormat`, `sampleRate` (`FACT` r2 §7.1, §7.5) — не «по умолчанию», а числом.
5. Длина главы в кадрах проверяется `ffprobe` после рендера и сверяется с `durationInFrames` из IR
   (`FACT` r2 §7.3: неверная длительность даёт артефакты при конкате).

**V4 и звук: уточнение, без которого V4 читается неверно.** V4 говорит «ни один эффект, звук или
анимация не пересекает границу главы». Буквальное прочтение запрещает сквозную фоновую музыку, что
абсурдно. Правильное прочтение: **V4 — инвариант видео-домена**, потому что сегментируется именно
видео. Аудио-домен не сегментируется вообще (r2 §7.3(b)), поэтому непрерывная музыка V4 не нарушает.
Нарушает — **визуал, реагирующий на музыку**: он создаёт зависимость главы от глобального времени
(§7.1) и обязан объявлять `globalTimeDependency`.

**V4 и переходы: чего мы лишаемся.** Раз главы рендерятся независимо, кросс-фейд между главами
невозможен без перекодирования шва. Решение: **граница главы = редакторское решение «здесь жёсткая
склейка»**, а переходы живут внутри главы, между сценами. `INFERENCE` Для Shorts это не ограничение
(там доминируют жёсткие склейки); для long-form может стать ограничением, и тогда открытая дверь —
отдельный шаг сборки, перекодирующий только один GOP на шве. Сейчас не проектируется.

**Сборка.** Промежуточные сегменты — `h264-ts` (`FACT` r2 §7.3: MPEG-TS устойчив к конкатенации),
кодирование сразу с финальными параметрами, конкат `-c copy`, единственный mux с аудио, ремукс в mp4.
Второго кодирования видео нет. `UNKNOWN` `FACT` r2 §10.4: применимость `combineChunks()` к главам
**разной** длины не проверена; наш план — прямой `ffmpeg concat`, а `combineChunks()` рассматривается
как альтернатива только если concat даст артефакты. Проверяется спайком S1.

**Draft-режим (AC3).** Правило: **draft меняет только параметры растеризации, никогда — временные и
геометрические.** Технически это `--scale` (`FACT` r2 §9.2 упоминает `--scale` как средство
draft-режима), `imageFormat: jpeg`, более высокий `crf`. Следствие важное: **IR у draft и final
идентичен**, отличается только `renderProfile`, поэтому кэш IR общий, а кэш сегментов раздельный.
Draft при этом не врёт о раскладке — он врёт только о резкости.
`INFERENCE` Понижать fps в draft **нельзя**: это изменило бы квантование (§4, R3) и сделало бы
черновик непригодным для проверки синхронности субтитров.

**Рендер-воркер за интерфейсом.** `RenderSegment` — асинхронная функция; локальная реализация сегодня,
удалённая — потом (Charter §2, r2 §8.9). Ничего больше сейчас не проектируется.

**TRADE-OFFS.**

* Жёсткие склейки между главами — реальное монтажное ограничение.
* Ассеты приходится готовить заранее (ingest с ресайзом), то есть появляется ещё одна стадия и ещё
  один кэш. Зато рендер перестаёт быть местом, где решается, какой файл открыть.
* Контракт «всё по значению» делает `RenderIR` крупным: для главы с субтитрами это сотни токенов.
  `INFERENCE` Порядок величины — десятки килобайт JSON на главу; несущественно.
* Отдельный процесс на главу стоит старта Chrome. `UNKNOWN` цена не измерена — спайк S2/S3 r2 §10.3.

→ **ADR-0002** (архитектура рендеринга), **ADR-0009** (контракт рендерера и сегментация).

## 10. РЕШЕНИЕ 8 — Структура монорепо и направление зависимостей

**CURRENT IDEA.** «pnpm workspaces, пакеты по слоям, разберёмся по ходу.» Через месяц `core` импортирует
`remotion` ради одного типа, и граница из r2 §8.1 перестаёт существовать — молча.

**PROBLEM.** Ровно одна зависимость в неправильную сторону обнуляет главную страховку архитектуры.
Значит, направление стрелок должно быть **проверяемым автоматически**, а не описанным в README.

**ALTERNATIVES.**

* **A. Один пакет.** Дёшево, но границу IR не обеспечивает вообще.
* **B. Пакет на слой (12–15 штук).** Максимальная строгость, максимальная бюрократия для одного
  человека: версии, сборка, ссылки, тесты — всё умножается.
* **C (RECOMMENDED). Минимальный набор пакетов, где **каждая граница защищает конкретный риск**,
  а всё остальное живёт в модулях внутри пакета.**

Критерий существования пакета: «эту границу нарушат случайно, и это дорого». Всё, что не проходит
критерий, — модуль, а не пакет.

1. `remotion` импортируется **только** в `@vpe/renderer-remotion`.
2. `react`/JSX — только в `@vpe/renderer-remotion`.
3. `@vpe/render-ir` не импортирует ни `remotion`, ни `react`, ни `node:fs`.
4. `@vpe/model` не импортирует ничего из node-рантайма (чистые типы и арифметика).
5. Никто не импортирует `@vpe/renderer-remotion`, кроме `@vpe/cli` и `@vpe/pipeline`
   (и то — через интерфейс `RenderSegment`, а не напрямую за типами).
6. `@vpe/policy` не импортирует `@vpe/renderer-*` (r3 §5: guard — на компиляции, никогда в рендере).

`FACT` r2 §7.5 — отдельная ловушка монорепо: `public/` обязана лежать рядом с тем `package.json`,
который содержит зависимость `remotion`. Значит `public/` живёт в `@vpe/renderer-remotion`, и туда
на время рендера кладутся жёсткие ссылки на CAS-файлы с ASCII-safe именами по sha256.
Это фиксируется в ADR-0009, потому что при первой же реорганизации пакетов забудется.

**WHY.** 15 пакетов — много, и я это признаю; но каждая из шести проверок выше соответствует конкретному
сценарию, где нарушение обнаруживается поздно и дорого. Сокращать надо не количество пакетов,
а количество **правил**: правил шесть, и все автоматизируются одним тестом.

**TRADE-OFFS.**

* Накладные расходы pnpm-воркспейса на одного разработчика реальны: сборка, типы, watch.
  Митигация: единый tsconfig с project references и один общий тест-раннер.
* `@vpe/pipeline` рискует стать «богом»: он знает про все стадии. Принимаем осознанно — оркестрация
  где-то должна жить, и лучше в одном явном месте, чем размазанной.
* Разделение `templates-spec` / реализация шаблонов раздражает при добавлении шаблона (две правки
  в двух пакетах). Это цена за то, что домен не знает про React.

→ **ADR-0010** (монорепо и правила зависимостей).

Charter §5 запрещает проектировать это глубже одного абзаца. Ниже — по одной строке: какой уже
принятый шов оставляет дверь открытой. Ничего из перечисленного сейчас не проектируется и не кодируется.

| Область | Шов, оставляющий дверь открытой |
|---|---|
| Semantic Director | `Timeline` — сериализуемый renderer-agnostic артефакт; любой «режиссёр» будет его читать и порождать overrides/маркеры, то есть подключается как ещё один производитель AUTHORED-слоя, без изменений ядра. |
| Creative Memory | якоря и `BuildRecord` дают устойчивые идентификаторы и историю сборок; хранилище «что уже делали» подключается как внешний read-only вход стадии, как и канальный корпус для Policy Guard (r3 §5, PG-B1). |
| Analytics-петля | `BuildRecord` + `voice.lock` + `assets.lock` уже содержат всё, к чему можно привязать метрики публикации; петля добавляется как отдельный пакет-потребитель, ничего не переписывая. |

| Мультиканальность | проект самодостаточен (папка + lock-файлы); канал — это внешний каталог проектов, нужный только Policy Guard (r3 §1.3) как read-only вход. |

## 14. Ответы на приёмочные вопросы

### 14.1 «Правка одного слова сценария → что пересчитается, что возьмётся из кэша»

Дано: проект из трёх глав, правка одного слова в середине главы 2.

| Стадия | Что происходит | Источник |
|---|---|---|
| `parse` | ключ файла изменился → перепарсинг **этого файла**; остальные файлы из кэша | пересчёт (мс) |
| якоря | меняется якорь **только этого слова**; якоря других слов сцены целы, если не изменилось число повторов этой словоформы | — |
| overrides | правки на изменённом слове помечаются **stale** и попадают в отчёт; остальные применяются как были | — |
| `speechPlan` | меняется чанк с правкой | пересчёт (мс) |
| `voice` | перегенерируется чанк с правкой **+ до 3 соседних** (stitch-контекст, §7.2). При `contextDepth: 1` — два чанка. Остальные дубли из `voice.lock` | сеть, ~$0.02–0.09, десятки секунд |
| `timeline` | пересчитывается целиком — это чистая арифметика над готовыми артефактами | пересчёт (мс) |
| Policy Guard | перепрогон на новом Timeline (детерминирован, без сети) | пересчёт (мс) |
| `renderIr` | меняется IR **главы 2**. IR глав 1 и 3 **побайтово те же**, потому что IR chapter-relative | из кэша для 1, 3 |
| `segment` | перерендеривается **только глава 2**. Сегменты 1 и 3 — из кэша | **это и есть AC3** |
| `audioTrack` | пересобирается склейкой PCM (V6) — операция линейная и дешёвая | секунды |
| `final` | `ffmpeg concat -c copy` трёх сегментов + один mux; второго кодирования видео нет | секунды |

Что **не** пересчитывается ни при каких условиях в этом сценарии: ingest ассетов, ресайзы, шрифты,
IR и пиксели глав 1 и 3, дубли голоса остальных чанков.
Единственное, что может это сломать, — незадекларированная зависимость от глобального времени;
поэтому она запрещена компилятором, а не соглашением (§7.1).

### 14.2 «Что произойдёт при регенерации TTS со всеми ручными правками»

Регенерация — **явное действие** (`vpe voice regenerate --scene hook`), а не побочный эффект сборки.

1. Текст не меняется ⇒ **якоря не меняются** ⇒ все анкоро-привязанные правки остаются валидными
   по построению. Это главный ответ, и он структурный, а не процедурный.
2. Правки, выражающие абсолютные секунды, невозможны: схема overrides их не выражает (§6).
   То есть класс ошибок «после регенерации всё уехало на 300 мс» не существует.
3. Правки, зависящие от **конкретного дубля** (ручная подкрутка тайминга слова, `caption.nudge`),
   несут `boundTo` с `takeId`. После регенерации отпечаток не совпадает ⇒ запись помечается **stale**:
   не применяется молча и не удаляется. Сборка печатает список, `vpe overrides review` показывает
   старое/новое значение и даёт принять или переписать.
4. Правки, которые являются **входами** TTS (`speech.pronounce`, `speech.pauseAfter`,
   `speech.chunkBreak`), участвуют в формировании запроса ⇒ переживают регенерацию по определению
   и меняют её результат в нужную сторону.
5. Старые дубли **не удаляются**: `voice.lock.json` меняет ссылку, файл остаётся. Откат — правка
   одной строки lock-файла. A/B двух голосов — два коммита.
6. Смещения меняются: новый дубль имеет другое `numSamples`. Все зависимые величины пересчитываются
   от суммы реально склеенных сэмплов (правило R4), а не подгоняются. Длина главы заново добивается
   до кратного `S` (R6), поэтому кадровая сетка остаётся точной.

Итого: **переживают всё, кроме правок, привязанных к звуку конкретного дубля, — и эти помечаются,
а не теряются.**

### 14.3 «Как один и тот же проект отрендерить сегментами и получить AC4»

Четыре свойства, каждое из которых необходимо, вместе — достаточны (при подтверждении спайком S1):

1. **Seed'ы материализованы в IR** компилятором (§8). Рендерер не выводит случайность, поэтому
   значения не зависят от того, сколько глав рендерится в этом запуске.
2. **Время chapter-relative** (§7.1). Кадр N главы K не знает о существовании главы K−1.
3. **Граница главы кратна `S`** (§4, R6). Сумма длительностей сегментов в кадрах точно равна длине
   непрерывной аудио-дорожки в сэмплах, делённой на `S`. Подгонка на стыке не нужна и запрещена.
4. **`renderProfile` зафиксирован и входит в ключ** (§7): `swangle`, явные лимиты кэшей, фиксированные
   `imageFormat`/`crf`/`gopSize`/`colorSpace`, шрифты и эмодзи файлами с checksum, версия Remotion
   = версия Chrome (`FACT` r2 §7.4).

Проверяется двумя тестами: **AC4-a** (двойной рендер → равенство кадров) и **AC4-b** (рендер целиком
против рендера по главам с конкатенацией → равенство кадров). AC4-b — это тест, доказывающий, что V4
исполняется; без него V4 остаётся декларацией.

`UNKNOWN` Порог равенства (побитово или с допуском) не зафиксирован до спайка S1: `FACT` r2 §7.4 п.7 —
официального утверждения о побитовой воспроизводимости headless Chrome нет.

`imageFormat` (`png` против `jpeg`), с явными лимитами обоих кэшей памяти.
Померить пик RSS и деградацию на 20 последовательных сегментах (проверка утечек, r2 §10.3).
**Отвечает:** U2. **Решает:** fps (30 против 60 — цена ошибки двукратная), длину главы,
параметры draft-профиля, реалистичность AC2/AC3.

### S3 — «Тождество вместо выравнивания»: нормализатор и alignment (≤1 день)
20 текстов (числа, даты, деньги, проценты, URL, аббревиатуры, кавычки «»/“”, тире, многоточия,
эмодзи, NBSP) прогнать через ElevenLabs с `apply_text_normalization: off` и `auto`.
Проверить `characters.join('') === input`, поведение `<break>`, лид-ин тишину, доступность
`pcm_24000` на текущем тарифе. Написать первую версию русского нормализатора-трансдьюсера и
табличные тесты к нему.
**Отвечает:** U3, U6. **Решает:** остаётся V5 тождеством или нужен fuzzy-fallback; объём работы по русскому.

### S4 — «Прибор для 80 мс»: дрейф и контролёр AC5 (≤1 день)
Склеить 10 чанков двумя способами (PCM и mp3-байты), прогнать оба через один алигнер, сравнить
Δ последнего слова — численно подтвердить V6 на своих данных. Затем прогнать выбранного кандидата
в контролёры (ctc-forced-aligner с лицензионно-чистой моделью и/или MFA) по финальному аудио,
померить распределение |Δ|, **проверить отсутствие монотонного тренда** и wall-clock на CPU.
Заодно посчитать, сколько caption-токенов схлопывается при 30 fps (правило R5).
**Отвечает:** U4, U7. **Решает:** какой алигнер закодировать в тест AC5 и какой остаток бюджета
остаётся арифметике.

### S5 — «Правка одного слова»: инкрементальная сборка (≤1 день, после S1–S2)
На двух-главой фикстуре реализовать скелет стадийного кэша (без настоящего рендера — заглушки),
изменить одно слово и вывести список промахов и попаданий. Проверить главное утверждение §7.1:
ключи сегментов последующих глав **не изменились**. Заодно померить churn якорей на серии из
10 типовых правок (переформулировка предложения, удаление повтора, перестановка абзацев).
**Отвечает:** U5 и слабое место §5. **Решает:** остаются ли контент-производные якоря или нужен
явный опт-ин на стабильные id.

## 17. Самокритика: если можно изменить одно решение — какое

**Изменил бы решение о контент-производных идентификаторах якорей (§5).**

Почему именно его. Оно выглядит самым элегантным в документе — id выводится из содержания, ничего не
надо хранить, регенерация TTS его не трогает, — и именно поэтому опаснее остальных: элегантность
маскирует два реальных дефекта.

Первый: **правка слова уничтожает якорь того самого слова, ради которого правка делалась.** Типичный
цикл работы — «послушал, не понравилось слово, поменял слово, подкрутил паузу вокруг него» —
приводит к тому, что правка становится stale ровно в момент, когда она нужна.

Второй, более неприятный: **изменение числа повторов словоформы в сцене сдвигает `occurrenceIndex`
у последующих одинаковых слов.** Это тихая ошибка. Я закрываю её отпечатком `boundTo`, но отпечаток —
это детектор, а не решение: он превращает тихий переезд в громкий stale, что лучше, но всё равно
означает ручную работу там, где её могло не быть.

На что бы поменял: на **явные идентификаторы, дописываемые форматтером в исходник**
(`Он проработал девять[#w7f2] лет`), с контент-производными как fallback для слов, которым id ещё не
присвоен. Это уродливее в тексте и требует инструмента, который **мутирует AUTHORED-файл** (а значит —
аккуратности при мерже с драфтом от LLM), но даёт свойство, которого у контент-производной схемы нет
в принципе: **якорь переживает правку слова, к которому привязан**.

Почему я всё-таки оставил контент-производную схему как рекомендацию: она не требует инструмента,
не портит текст, который пишет и читает человек, и её дефект **измерим** — спайк S5 показывает
реальную частоту churn'а на живом редактировании. Если частота окажется высокой, переход на явные id
дешёвый: это добавление поля в модель и команды в CLI, а не смена архитектуры. Если бы решение было
необратимым, я бы выбрал явные id сразу.

Второй кандидат на пересмотр, для честности: **пятнадцать пакетов монорепо (§10)**. Я обосновал каждый
шов, но для одного разработчика это заметный налог на каждое действие. Я оставил их, потому что
сливать пакеты позже дёшево, а разделять поздно — дорого; но если через месяц окажется, что половина
границ ни разу не спасла, их надо схлопнуть без сожаления.

## Приложение A. Сигнатуры типов

Только сигнатуры: это контракт, а не реализация. Всё, что здесь целочисленное, целочисленно намеренно (§8).

```ts
// ───────────────────────── базовые скаляры ─────────────────────────
type Sha256   = string;   // 64 hex, нижний регистр
type AnchorId = string;   // "w:7f2ab91c3d" | "sc:hook" | "ch:intro" | "b:reveal" | "m:0f31aa"
type Samples  = number;   // целое ≥ 0, домен sampleRate проекта
type Frames   = number;   // целое ≥ 0, домен fps проекта
type Milli    = number;   // фикс. точка ×1000 (1.25 → 1250)
type Permille = number;   // 0..1000
type MilliDb  = number;   // −18.0 dB → −18000

// ───────────────────────── исходник, якоря, V5 ─────────────────────────
interface SourceSpan { readonly file: string; readonly offset: number; readonly length: number;
                       readonly line: number; readonly column: number }

type MarkerKind = 'img' | 'video' | 'tpl' | 'beat' | 'pause' | 'emph' | 'music' | 'sfx' | 'note';

interface ScriptMarker {
  readonly id: AnchorId;                                    // "m:<hash>"
  readonly kind: MarkerKind;
  readonly args: Readonly<Record<string, string>>;
  readonly attach: { readonly anchor: AnchorId; readonly side: 'before' | 'after' };
  readonly range: { readonly toAnchor: AnchorId } | null;   // парные [emph]…[/emph]
  readonly span: SourceSpan;
}

interface WordToken {
  readonly anchor: AnchorId;
  readonly surface: string;                                 // как в исходнике
  readonly normalized: string;                              // как ушло в TTS (V5)
  readonly span: SourceSpan;                                // позиция в ИСХОДНИКЕ
  readonly normalizedRange: { readonly start: number; readonly end: number };  // в тексте чанка
}

/** V5: не «алигнер», а трансдьюсер со span-map. Чистая функция, покрывается табличными тестами. */
interface NormalizationResult {
  readonly text: string;
  readonly map: readonly { readonly srcStart: number; readonly srcEnd: number;
                           readonly dstStart: number; readonly dstEnd: number;
                           readonly rule: string }[];
}
type Normalizer = (input: string, locale: string) => NormalizationResult;

// ───────────────────────── голос как артефакт (V6, r1) ─────────────────────────
interface VoiceTake {
  readonly takeId: Sha256;              // = sha256(PCM)
  readonly chunkKey: string;            // ключ кэша запроса
  readonly sampleRate: number;
  readonly numSamples: Samples;         // источник истины для смещения следующего чанка (правило R4)
  readonly audioRef: Sha256;            // FLAC; декод обязан дать побитово тот же PCM
  readonly units: readonly {
    readonly kind: 'char' | 'word' | 'phoneme';
    readonly text: string;
    readonly startSample: Samples; readonly endSample: Samples;
    readonly srcStart: number; readonly srcEnd: number;      // позиции в тексте запроса
  }[];
  readonly provenance: VoiceProvenance;  // provider, model, voice, seed, requestId, billedUnits,
                                         // planTierAtGeneration, generatedAt  (r1 §6 + r3 §3.4)
}

// ───────────────────────── Timeline: renderer-agnostic, время в СЭМПЛАХ ─────────────────────────
interface Timeline {
  readonly timelineVersion: number;
  readonly projectId: string;
  readonly sampleRate: number;
  readonly chapters: readonly TimelineChapter[];
  readonly bindings: ReadonlyMap<AnchorId, { readonly startSample: Samples; readonly endSample: Samples }>;
  readonly assets: ReadonlyMap<Sha256, AssetRecord>;
  readonly overridesApplied: readonly OverrideRecord[];
  readonly overridesStale: readonly { readonly record: OverrideRecord; readonly why: string }[];
}

interface TimelineChapter {
  readonly chapterId: string;
  readonly lengthSamples: Samples;         // ВСЕГДА кратно samplesPerFrame (правило R6)
  readonly scenes: readonly TimelineScene[];
  readonly clips: readonly TimelineClip[]; // время — chapter-relative, в сэмплах
  readonly globalTimeDependency: boolean;  // true ⇒ глава cache-hostile, §7.1
}

// ───────────────────────── RenderIR: кадры, chapter-relative, ЦЕЛОЧИСЛЕННЫЙ ─────────────────────────
interface RenderIrChapter {
  readonly irVersion: number;
  readonly chapterId: string;
  readonly fps: number;                                  // целое, sampleRate % fps === 0
  readonly width: number; readonly height: number;       // ЛОГИЧЕСКАЯ геометрия, не выходное разрешение
  readonly durationInFrames: Frames;                     // === lengthSamples / S, точно
  readonly layers: readonly IrLayer[];                   // отсортированы по (z, id)
  readonly fonts: readonly IrFontRef[];
  readonly assets: readonly IrAssetRef[];
  // абсолютного положения главы в проекте здесь НЕТ — это условие AC3, §7.1
}

interface IrAssetRef { readonly sha256: Sha256; readonly kind: 'image' | 'video' | 'audio';
                       readonly width?: number; readonly height?: number;
                       readonly durationSamples?: Samples }
interface IrFontRef  { readonly sha256: Sha256; readonly family: string;
                       readonly weight: number; readonly style: 'normal' | 'italic' }

interface IrLayerBase {
  readonly id: string;
  readonly from: Frames; readonly durationInFrames: Frames;
  readonly z: number;
  readonly seed: number;                     // uint32, МАТЕРИАЛИЗОВАН компилятором (§8)
  readonly effects: readonly IrEffect[];
}
interface IrImageLayer    extends IrLayerBase { readonly kind: 'image'; readonly asset: Sha256;
                                                readonly fit: 'cover' | 'contain';
                                                readonly focal: { readonly x: Permille; readonly y: Permille } }
interface IrTextLayer     extends IrLayerBase { readonly kind: 'text'; readonly styleId: string;
                                                readonly text: string }
interface IrCaptionLayer  extends IrLayerBase { readonly kind: 'caption'; readonly styleId: string;
                                                readonly tokens: readonly IrCaptionToken[] }
interface IrTemplateLayer extends IrLayerBase { readonly kind: 'template'; readonly templateId: string;
                                                readonly templateVersion: number; readonly params: IrJson }
type IrLayer = IrImageLayer | IrTextLayer | IrCaptionLayer | IrTemplateLayer;

interface IrCaptionToken { readonly anchorId: AnchorId; readonly text: string;
                           readonly from: Frames; readonly durationInFrames: Frames }
interface IrEffect       { readonly kind: string; readonly version: number;
                           readonly keyframes: readonly IrKeyframe[] }
interface IrKeyframe     { readonly frame: Frames;
                           readonly values: Readonly<Record<string, Milli>>;
                           readonly easing: string }       // id из закрытого версионируемого реестра

// ───────────────────────── AudioIR: сэмплы, глобальный, НЕ сегментируется ─────────────────────────
interface AudioIr {
  readonly irVersion: number;
  readonly sampleRate: number;
  readonly totalSamples: Samples;                          // === Σ chapter.lengthSamples
  readonly placements: readonly AudioPlacement[];          // отсортированы по (destStartSample, id)
}
interface AudioPlacement {
  readonly id: string;
  readonly source: { readonly kind: 'take';    readonly ref: Sha256 }
                 | { readonly kind: 'asset';   readonly ref: Sha256 }
                 | { readonly kind: 'silence' };
  readonly sourceStartSample: Samples;  readonly lengthSamples: Samples;
  readonly destStartSample: Samples;
  readonly gainMilliDb: MilliDb;
  readonly fadeInSamples: Samples; readonly fadeOutSamples: Samples;
  readonly duckedBy: readonly string[];                    // id других placement'ов
}

// ───────────────────────── контракт рендерера (V9) ─────────────────────────
interface SegmentRenderRequest {
  readonly ir: RenderIrChapter;
  readonly profile: RenderProfile;
  readonly assetPaths: ReadonlyMap<Sha256, string>;        // локальные, уже подготовленные (ingest)
  readonly fontPaths: ReadonlyMap<Sha256, string>;
  readonly outputPath: string;                             // немой .ts
  readonly workDir: string;                                // единственное место для записи
}
interface SegmentArtifact {
  readonly path: string; readonly sha256: Sha256;
  readonly frameCount: Frames;                             // сверяется ffprobe вызывающей стороной
  readonly profileFingerprint: string;
  readonly diagnostics: readonly string[];
}
type RenderSegment = (req: SegmentRenderRequest, signal?: AbortSignal) => Promise<SegmentArtifact>;

// ───────────────────────── overrides (V2) ─────────────────────────
type OverrideTarget =
  | { readonly kind: 'anchor';  readonly anchorId: AnchorId }
  | { readonly kind: 'marker';  readonly markerId: AnchorId }
  | { readonly kind: 'scene';   readonly sceneId: string }
  | { readonly kind: 'chapter'; readonly chapterId: string }
  | { readonly kind: 'finding'; readonly findingId: string };

interface OverrideRecord {
  readonly id: string;
  readonly target: OverrideTarget;
  readonly op: string;                  // из закрытого версионируемого каталога (§6)
  readonly value: unknown;              // валидируется zod-схемой конкретного op
  readonly reason: string;
  readonly createdAt: string;           // ISO; вводится СНАРУЖИ (V8), не Date.now()
  readonly boundTo: string | null;      // отпечаток того, к чему привязались; несовпадение ⇒ stale
}

// ───────────────────────── профиль рендера (r2 §8.4) ─────────────────────────
interface RenderProfile {
  readonly profileId: string; readonly profileVersion: number;
  readonly rendererId: 'remotion'; readonly rendererVersion: string; readonly chromeVersion: string;
  readonly gl: 'swangle';                                  // §8, детерминизм важнее скорости
  readonly scale: Milli;                                   // draft меняет ТОЛЬКО это и качество
  readonly imageFormat: 'png' | 'jpeg'; readonly jpegQuality: number;
  readonly codec: 'h264-ts'; readonly crf: number; readonly gopSize: number;
  readonly pixelFormat: string; readonly colorSpace: string;
  readonly concurrency: number;
  readonly offthreadVideoCacheBytes: number;               // явно; дефолт = половина RAM (r2 §7.1)
  readonly mediaCacheBytes: number;                        // явно; дефолт = половина RAM (r2 §7.1)
  readonly disallowParallelEncoding: boolean;
  readonly assetPipelineVersion: number;                   // ресайзер влияет на пиксели
  readonly templateRegistryVersion: number;                // V3: смена реализации ⇒ новый сегмент
  readonly fontSetHash: Sha256;
}
```
