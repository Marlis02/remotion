# Как писать сценарий чужими руками — инструкция к `vpe spec export`

**Что это.** Владелец больше не пишет сценарии руками. Одна команда выгружает правила игры
движка — грамматику прозы, каталог семи шаблонов с параметрами, числа канала и форму ответа;
выгрузка вставляется в чат с ИИ, к ней добавляется тема; ИИ возвращает два файла, которые
компилятор либо принимает, либо отвергает с адресом. Судит компилятор, а не глаза.

**Чего этот файл НЕ описывает.** Ни одного правила движка: они целиком живут в выгрузке и
берутся из кода — переписывать их сюда значило бы завести второй источник истины, который
разойдётся со схемами при первой правке. Здесь только порядок действий.

## Порядок

1. **Снять выгрузку.**

   ```
   vpe spec export                          # markdown в stdout — то, что вставляют в чат
   vpe spec export --out /tmp/spec.md       # то же в файл
   vpe spec export --json                   # та же структура машинно
   ```

2. **Вставить её в чат целиком** — от заголовка до последнего запрета. Урезанная выгрузка
   даёт урезанные правила: ИИ не знает, чего он не увидел.

3. **Добавить своё — три вещи, и все три обязательны:**
   * **тема и о чём ролик** — своими словами, столько, сколько нужно;
   * **длительность** в секундах (потолок канала — 60, он назван в выгрузке);
   * **СПИСОК ALIAS'ОВ** ассетов с одной строкой описания каждого. **Его печатает команда,
     выдумывать и переписывать руками ничего не нужно** (`ASSET-01`):

     ```
     vpe asset list --project examples/ai-test-1
     ```

     Каждый ассет выходит двумя строками — паспорт и описание:

     ```
     street · image · 3840×2835 · public-domain · 846e37e1
         «Mulberry Street, New York City», фотохром Detroit Publishing Co., ок. 1900 …
     ```

     Описание берётся из поля `note` записи ассета — того самого, которое назвали, когда
     клали файл в проект:

     ```
     vpe asset add ~/Downloads/harbour.jpg --project <кат> --alias harbour \
       --note "порт на рассвете, горизонтальный, туман" --rights own
     ```

     `--rights` — это «чьё и на каких условиях», одной строкой: **`own`** (снял сам),
     **`public-domain`** (срок охраны истёк либо служебное произведение США),
     **`cc-by-4.0`** (свободная лицензия, автора назвать обязательно — текст даётся флагом
     `--attribution`), **`all-rights-reserved`** (чужое, разрешения нет — команда примет и
     предупредит, потому что судить значение сегодня некому). Подробнее —
     [`00-PROCESS.md`](../00-PROCESS.md) §1-бис.

     **Ассета без описания в проекте быть не может:** `--note` обязателен ровно затем, чтобы
     этот список не содержал строк «alias есть, а что на нём — неизвестно».

     **Вид (`image` / `video`) в списке — не украшение.** Шаблоны ждут ассет определённого
     вида, и подстановка не того вида есть отказ компилятора с адресом записи: `still@1` и
     `parallax25@1` ждут картинку, `bed@1` — звук, ~~а видео сегодня в шаблон не ставится
     ничем~~ *(изменено: `VID-02a`, 2026-09-11)* — **видео ставится шаблоном `video@1`, и он
     единственный, кто ждёт вид `video`**.

     **Три вещи про `video@1`, которых не видно из схемы параметров и которые ИИ обязан
     знать.** Первое: **звук видео в ролик не попадает** — `audio` принимает только `"off"`,
     дорожка ролика это по-прежнему диктор и `bed@1`. Второе: **видео лежит ПОД графикой**, и
     сквозь слои НИЖЕ своего `z` шаблон пробивает прозрачное окно — значит `z` записи с видео
     обязан быть выше всего непрозрачного в сцене (в том числе выше порождённого `[img:]`,
     который стоит на `z: 0`), иначе картинка закроет видео. Слой на ТОМ ЖЕ `z` тоже закроет:
     окно пробивается строго ниже. Третье: **если видео кончилось раньше окна записи,
     держится последний кадр** — зацикливания в этой версии нет.

4. **Получить ответ** — ровно два файла: `source/NN-имя.md` и `direction/NN-имя.yaml`.
   Положить их в проект под этими именами.

5. **Судить компилятором:**

   ```
   vpe build --project examples/vertical-v1 --profile draftHalf
   ```

   Отказ называет файл, строку и правило. Отказ — это нормальный ход работы: текст отказа
   отдаётся обратно в чат, ИИ правит, шаг повторяется. Глазами смотрят ГОТОВЫЙ ролик, а не
   yaml.

## Что ИИ обязан вернуть

* **Ровно два файла** — прозу и режиссуру, с совпадающими именами. Ни `project.yaml`, ни
  `publish.yaml`, ни `aliases.yaml`: они уже написаны.
* **Прозу по-английски**, с числами словами. Это входное условие проекта (Charter V12), а не
  предпочтение.
* **Каждую запись режиссуры со своим `recordId`** — 4 случайных байта, 8 строчных hex-символов.

## Чего ИИ делать не должен

* **Выдумывать alias'ы фотографий.** Список даёт владелец пунктом 3; alias, которого нет в
  каталоге, — отказ сборки, а не пустой кадр. Списка не дали — ИИ обязан спросить, а не
  подставить правдоподобное имя.
* **Звать шаблон или кривую вне выгрузки.** Каталог и реестр easing ЗАКРЫТЫ; «похожий эффект»
  не существует.
* **Дописывать поля в `params`.** Каждая схема `.strict()`: лишнее поле — отказ с путём к нему.

## Сначала пресет, числа — только если пресета нет

*(добавлено: `TPL-01b`, 2026-09-10.)*

**Пресет — это `params`, уже стоявшие в собранном ролике и сохранённые под именем.** В карточке
каждого шаблона (раздел 2 выгрузки) под схемой параметров идёт список: имя, фраза «для чего» и
сами числа. Запись, которая берёт пресет, выглядит так:

```yaml
  template: "kenburns@1"
  preset: "drift-right"
```

**Порядок работы: сначала посмотреть список пресетов шаблона, и только если подходящего нет —
писать `params` числами.** Причина не в удобстве: числа в пресетах — из роликов, которые
собраны и просмотрены глазами, а сочинённые «правдоподобные» значения дают законный,
компилирующийся и никем не виденный кадр. Имя пресета, которого в карточке нет, — отказ
компилятора со списком доступных, а не «похожий пресет».

**Свои числа поверх пресета — можно, и накладываются они ПО ВЕРХНЕМУ УРОВНЮ КЛЮЧЕЙ.** `params`
рядом с `preset` перекрывают одноимённые ключи ЦЕЛИКОМ, глубокого слияния нет: написав `from:
{scale: 1.1}`, вы получите `from` ровно из этого поля, а не смесь с пресетным `from.x`. Чаще
всего перекрывают `asset` и `layers`: alias'ы внутри пресета принадлежат тому проекту, из
которого он снят, а картинки у вас свои.

Запись обязана нести `preset` либо `params` (можно оба). Без обоих — отказ схемы: «шаблона с
параметрами по умолчанию» движок не знает.

## Почему выгрузка не устаревает

Всё, что в ней можно проверить машиной, читается из кода при каждом запуске: параметры —
интроспекцией zod-схем шаблонов, бюджеты, роли ассетов и статус гейта — из манифестов и
записей рядом со спеками, реестр кривых — из самого реестра. Восьмой шаблон попадёт в
выгрузку сам; шаблон без описания назначения не соберётся вовсе (поле `guidance` обязательно
типом), а пустое описание краснеет юнитом поимённо
([`spec-export.test.ts`](../packages/cli/test/spec-export.test.ts)).

Авторского в выгрузке три раздела — грамматика прозы и якорей, числа канала и форма ответа, — и
у каждого утверждения там назван источник: ADR, отчёт задачи или файл профиля. Это ровно то,
чего в коде нет и быть не может.

**Снятая выгрузка для глаз приёмки** — [`docs/impl/SPEC-01/spec-export.md`](impl/SPEC-01/spec-export.md).
Она снимок, а не источник: перед работой снимайте свежую.
