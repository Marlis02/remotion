# Реестр инвариантов: правило → где записано → чем охраняется

* **Создан:** A2 (2026-08-19), по находке RT-01 m5 и процессному замечанию §5.6.
* **Зачем.** ADR-0001 объявляет принцип: «каждая строка "НЕ знает" превращается в тест зависимостей
  или тест ключа кэша, то есть модель охраняется механически». Принцип верен, но до этого файла
  проверить его выполнение было нельзя: правила рассыпаны по десяти документам, тесты — по одному,
  и они не сопоставлены. Пустая клетка в колонке «Охранник» — **видимый долг**, а не забытая строка.
* **Как поддерживать.** Новый ADR обязан либо добавить сюда строку, либо явно написать
  `decided-not-to` с причиной. Инвариант без охранника — не инвариант, а пожелание.

## Легенда статусов

| Статус | Значение |
|---|---|
| `named` | охранник назван и специфицирован; кода ещё нет (нормальное состояние до ЭТАПа 5) |
| `guarded` | тест написан и зелёный |
| `spike` | проверяется спайком, а не постоянным тестом |
| `decided-not-to` | охранника сознательно не будет; причина в клетке |

Сейчас кода нет, поэтому все механические охранники в статусе `named`. Колонка существует, чтобы
переход `named → guarded` был видимым событием, а не подразумевался.
