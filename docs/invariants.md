  [docs/spikes/sp3-closure.md](spikes/sp3-closure.md). Затронуты: **D13** (`spike → measured`),
  **D14** (`spike → measured (пара)`, охранник — гейт шаблона), **R1** (`named → measured`),
  **R11** (`spike → measured`), **M1/M2** (переписаны под выбранный рендерер), новые строки
  **R12**, **R13**, **R14**. Ни один охранник не удалён и не ослаблен; **D10** (AC4, нулевой
  порог на `render.ac4.yaml`) не изменён ни на букву.
* **Ревизия:** SP-2 (2026-08-21) — спайк выполнен, см.
  [docs/spikes/sp2-closure.md](spikes/sp2-closure.md). Затронуты: **T7** (охранник — допуск в
  ассерте и акустический детектор), **V11** (`spike → measured`), **V12** (остаётся `spike`,
  добавлен долг «выбор алигнера»), **X4** (объективная часть измерена, слуховая — за владельцем),
  новая строка **V14** (пауза из пунктуации не входит в контракт формата). В легенду добавлен
  статус `measured`. Ни один охранник не удалён и не ослаблен.
* **Зачем.** ADR-0001 объявляет принцип: «каждая строка "НЕ знает" превращается в тест зависимостей
  или тест ключа кэша, то есть модель охраняется механически». Принцип верен, но до этого файла
  проверить его выполнение было нельзя: правила рассыпаны по десяти документам, тесты — по одному,
  и они не сопоставлены. Пустая клетка в колонке «Охранник» — **видимый долг**, а не забытая строка.
* **Как поддерживать.** Новый ADR обязан либо добавить сюда строку, либо явно написать
  `decided-not-to` с причиной. Инвариант без охранника — не инвариант, а пожелание.

## Легенда статусов

| Статус | Значение |
|---|---|
| `named` | охранник назван и специфицирован; кода ещё нет (нормальное состояние до ЭТАПа 5) |
| `guarded` | тест написан и зелёный |
| `spike` | проверяется спайком, а не постоянным тестом |
| `measured` | спайк выполнен, правило подтверждено измерением; постоянный охранник назван в той же клетке (добавлено SP-2, 2026-08-21) |
| `decided-not-to` | охранника сознательно не будет; причина в клетке |

~~Сейчас кода нет, поэтому все механические охранники в статусе `named`.~~ *(изменено: `R-01`,
2026-08-22.)* **Код появился, и первые шесть охранников зелёные — §8, строки M1–M6.** ~~Остальные
механические охранники по-прежнему `named`.~~ *(изменено: `R-02`, 2026-08-22.)* **Седьмой — `P10`**
(§7); K6 и P16 получили пометки о частичном покрытии **без смены статуса** — частичное покрытие
не есть `guarded`, и это записано, чтобы счёт не рос за счёт округления вверх. Колонка существует, чтобы переход
`named → guarded` был видимым событием, а не подразумевался.
