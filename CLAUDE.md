# Правила для любой сессии в этом репозитории

## 1. Конституция

Перед любой задачей прочти `PROJECT_CHARTER.md` и соблюдай его. Процесс проекта описан в `00-PROCESS.md`. Не нарушай решения V1–V12 из Charter без явного обсуждения с владельцем. Сомневаешься — спроси, не додумывай.

## 2. Секреты

* Секреты (API-ключи, ID голосов, токены) берутся **только** из `process.env`.
* Файл `.env` **не открывать, не читать, не выводить, не логировать, не коммитить** — ни целиком, ни по частям, ни через `cat`, `grep`, `env`, `printenv` или отладочную печать объекта `process.env`.
* В отчёты, `raw/*.json`, `machine.json`, тесты и логи значения секретов не попадают. Нужен след — пиши имя переменной или имя голоса, не значение.
* Публичная форма конфигурации — `.env.example` с пустыми значениями; только его можно править.
* Если для задачи не хватает переменной — скажи, какая нужна, и жди; не подставляй заглушки.

## 3. Журнал прогресса — обязателен для любой длинной задачи

Вывод в чате теряется. Для любой задачи длиннее нескольких минут (спайки, прогоны, бенчмарки, массовые правки, всё, что делает сетевые или платные вызовы) веди **`PROGRESS.md` в корне репозитория** и пиши туда по ходу, а не в конце.

```
# PROGRESS — <задача> · старт <ISO-время>
План: <N шагов одной строкой>. Бюджет: <если есть>.
- `HH:MM` [1/N] <что начато> — ожидаю ~<время>
- `HH:MM` [1/N] готово за <время> — <результат одной строкой>; <расход накопительно>
- `HH:MM` ОШИБКА: <что> — <что делаю>
- `HH:MM` ЖДУ ВЛАДЕЛЬЦА: <что нужно решить>
**Итог:** <2–4 строки>. Детали — <файлы>.
```

* Одна строка — одно событие, только append; старые строки не редактировать.
* Перед каждым платным или долгим шагом — «начато», сразу после — «готово» с числом. Расход — накопительным итогом.
* `ЖДУ ВЛАДЕЛЬЦА` означает остановку. Не продолжать по умолчанию.
* Корневой `PROGRESS.md` в git не идёт (`.gitignore`). По завершении задачи его содержимое переносится в постоянное место (например, `docs/spikes/<имя>/results/PROGRESS.md`), корневой очищается.

## 4. Результат сессии

Результат — файлы в репозитории, не текст в чате. Утверждения помечаются FACT / PRACTICE / INFERENCE / UNKNOWN. Коммит делает владелец, если в задании не сказано иное. Но придумай название коммита.
