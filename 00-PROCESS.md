# ПРОЦЕСС: как строить движок по этапам, не теряя качество

Главная идея: **не один мега-промпт, а конвейер коротких сессий**, где
каждая сессия получает Charter + результаты предыдущих этапов, делает
ОДНУ вещь, и её результат проверяется до перехода дальше.

Почему ИИ «деградирует» и как этого избежать:
- длинный контекст → модель начинает повторяться и терять детали
  → лечится короткими сессиями с явными входными файлами;
- модель услужливо соглашается со своим же ранним текстом
  → лечится отдельной red-team сессией с чистым контекстом;
- модель заполняет форму вместо мышления
  → лечится узким scope: один этап = один вопрос.

---

## Карта этапов

```
ЭТАП 0  Репозиторий + Charter                (полдня)
ЭТАП 1  Research ×3 (промпты R1–R3)          (2–3 дня, можно параллельно)
ЭТАП 2  Core Architecture (промпт A1)         (2–4 дня, итеративно)
ЭТАП 3  Red Team Review (промпт RT1) + фиксы  (1–2 дня)
ЭТАП 4  Roadmap MVP→V2 (промпт RM1)           (1 день)
СПАЙКИ  SP-1…SP-5 (см. core.md §16)           (~4 дня) ← ГЕЙТ перед ЭТАПом 5
ЭТАП 5  Реализация MVP по модулям (промпт IMPL, много сессий)
ЭТАП 6  Каждый модуль: код-ревью (промпт REV) + тесты + фикстура
ЭТАП 7  Первое опубликованное видео = выход из MVP
дальше  Циклы: модуль → ревью → фикстура → релиз → следующий
```

## ЭТАП 0 — Репозиторий (руками, без ИИ, полдня)
1. `git init`, монорепо-скелет: `packages/`, `docs/adr/`, `docs/research/`,
   `fixtures/`.
2. Положить `PROJECT_CHARTER.md` в корень.
3. Создать `fixtures/minimal/` — эталонный мини-проект: 10 секунд,
   2 сцены, 3 картинки, 5 страниц субтитров. Он ещё не рендерится —
   это цель. Всё дальнейшее строится так, чтобы фикстура работала.

Критерий выхода: репо закоммичен, Charter прочитан тобой ещё раз.

## ЭТАП 1 — Research (промпты R1, R2, R3)
Три НЕЗАВИСИМЫЕ сессии (обязательно с доступом ИИ в интернет —
Claude с web search или Claude Code с fetch). Каждая пишет один md-файл
в `docs/research/`. Не обсуждай в них архитектуру — только факты.

Проверка этапа (тобой):
- каждое важное утверждение помечено FACT/PRACTICE/INFERENCE/UNKNOWN;
- у FACT есть ссылка на источник; открой 3–4 ссылки выборочно;
- если в документе нет ни одного UNKNOWN — это подозрительно, докопайся.

Критерий выхода: три файла в репо, ты прочитал каждый целиком.

## ЭТАП 2 — Core Architecture (промпт A1)
Одна сессия (при разрастании — продолжение с саммари). Вход: Charter +
3 research-файла. Выход: `docs/architecture/core.md` + ADR-файлы.
Проектируется ТОЛЬКО необратимое (список в промпте). Всё из anti-scope —
максимум абзац.

Проверка этапа:
- на каждое решение есть ADR с альтернативами (нет альтернатив = не думал);
- прогони чек-вопросы из конца промпта A1;
- сверь с Charter: не нарушены ли V1–V11 без явного оспаривания.

## ЭТАП 3 — Red Team (промпт RT1)
НОВАЯ сессия, чистый контекст, роль независимого ревьюера. Вход: Charter +
architecture + ADRs. Выход: `docs/reviews/red-team-01.md` (≥15 точек
отказа + overengineering audit). Затем вернись в архитектурную линию
(новая сессия с промптом A2-фиксы) и адресуй каждый пункт: исправить или
осознанно принять риск (записать в ADR).

Критерий выхода: на каждый пункт ревью есть письменная реакция
(`docs/reviews/red-team-01-response.md`: строка на каждую находку, ни одной пустой).

## Образ среды канала — три команды (`ENV-02`, 2026-09-08)

**Зачем.** `engineFingerprint` считается по версиям `Node`/`Chrome`/`ffmpeg` и двух пакетов, а
вход **R12** — пара (профиль, отпечаток). Пока среда жила на машине, смена машины делала все
записи `*.gates.json` недействующими: измерено `ENV-01` — отпечаток уехал, десять записей
переснимали руками (долг №224). Образ пришпиливает ровно те величины, которые в отпечаток
входят. Разбор — [`docs/impl/ENV-02/report.md`](docs/impl/ENV-02/report.md).

**Один раз после `git clone`** (единственный шаг, которому нужна сеть):

```bash
./scripts/vpe-docker build-image     # собрать образ: первый раз ~3.5 мин, повторно 0.2 с (кэш)
./scripts/vpe-docker prepare         # pnpm install --frozen-lockfile + pnpm -r build
```

### 1. Собрать ролик

```bash
./scripts/vpe-docker build --project examples/ai-test-1 --profile final
```

Ожидаемый вывод — как у сборки на машине: строка `проект … → профиль final`, три строки
`сегмент N/3`, затем отчёт и `final.mp4` в `examples/ai-test-1/build/`. Сеть у контейнера
**отключена** (`--network none`) — дубли голоса берутся из `voice/takes/`, в источник обращений
ноль. Живой голос требует денег и потому — отдельного флага:
`ELEVENLABS_LIVE=1 ./scripts/vpe-docker --live build … --allow-tts`.

**Вторая сборка того же проекта не рендерит ничего** (`CACHE-01`): межсборочный кэш живёт в
`<корень записи>/.cache/` — `.cache/segment/<профиль>/` для сегментов и `.cache/voice/` для
оплаченных дублей; каталог в git не идёт (`.gitignore`) и удаляется руками без потерь. На
каждый сегмент печатается строка `кэш: попадание` / `промах` / `выключен`, а числа уезжают в
`BuildRecord` (`segments[].cache` и блок `cache`). ~~`промах по композиции`~~ *(вердикт снят:
`CACHE-02`, 2026-09-11)* — `bundle.hash` теперь ВХОДИТ в ключ сегмента, поэтому правка кода
шаблона даёт другой ключ, то есть обычный промах; до этой правки она роняла сборку отказом
**K3**, и лечилось это только `rm -rf .cache`. Выключается
одним флагом на обе стадии — `--no-cache`; `vpe verify ac4` ставит его ОБОИМ своим прогонам
сама, потому что кэш во втором прогоне проверял бы кэш, а не рендерер. Порча кэша — не тихий
пересчёт, а отказ сборки с советом `rm -rf .cache/segment/<профиль>`.

**КАДРЫ СЕГМЕНТОВ ПОСЛЕ ЭНКОДА УДАЛЯЮТСЯ** *(долг №288 закрыт 2026-09-12)*. Каталог
`build/tmp/segments/*` — производное, которое после кодирования не читает никто: финал
собирается из `.mts` в `build/segments/`, кэш кладёт байты того же файла. ИЗМЕРЕНО на живом
проекте (39 с черновика): без уборки там оставалось **689 МБ** (1511 PNG), с ней — **12 КБ**
(один `concat.txt`); на десятиминутном черновике это было 12 ГБ, на двадцатиминутном финале —
около 96 ГБ. Байты ролика при этом не меняются: `final.mp4` обеих сборок побайтово один.
Оставить кадры — флаг **`--keep-frames`**: он нужен отладке («покажи мне кадр 37, который
вышел чёрным») и тем прогонам, которые каталог ЧИТАЮТ. `vpe template demo --keep-tmp`
оставляет их заодно с временным проектом.

### 1-бис. Добавить в проект свою картинку или своё видео

Своё фото или свой ролик кладёт в проект ОДНА команда — руками ни в CAS, ни в
`assets/records/`, ни в `aliases.yaml`, ни в `store.lock` больше лезть не надо (`ASSET-01`):

```bash
node packages/cli/dist/bin/vpe.js asset add work/in/demo.jpeg \
  --project work/asset-test --alias demo-photo \
  --note "проба владельца — фото с телефона, горизонтальное" \
  --rights own
```

Ожидаемый вывод — десять строк, и каждая говорит, что именно записано. Ниже — **настоящий
вывод настоящего прогона** (`ASSET-01`, 2026-09-10), а не пример по мотивам:

```
alias:      demo-photo
вид:        image (JPEG)
intrinsic:  311×162
sha256:     939d67300c8863f17919e172dbd22c20fba1bfcc1fad9865aca0bd3992697b91
в сторе:    положен (/home/marlis/.vpe/store)
запись:     создана — …/assets/records/939d6730….json
alias:      дописан — …/assets/aliases.yaml
store.lock: 13 → 14 записей
права:      work=own · reproduction=own · recording=n/a
описание:   проба владельца — фото с телефона, горизонтальное
```

**Видео добавляется ТОЙ ЖЕ командой** — вид определяется по БАЙТАМ файла, а не по расширению
имени. У видео вместо `311×162` печатается паспорт целиком:

```
вид:        video (ISO-BMFF (mp4/mov))
intrinsic:  1920×1080 · 24/1 fps · 157 кадров (6.542 с) · альфа: нет · звук: нет
```

Геометрия здесь — та, которую ВИДНО: поворот, записанный телефоном, уже применён, и снятое
вертикально видео не окажется в записи горизонтальным. Число кадров посчитано декодом, а не
взято из заголовка, — на шестисекундном ролике это стоит около секунды и платится один раз.
**Видео с переменной частотой кадров (VFR) команда не примет** и скажет, чем это лечится:
движок кладёт клипы на кадровую сетку, а у VFR «кадр номер N» не является моментом времени.

**ЧТО ВИДЕО УМЕЕТ В РОЛИКЕ — И ЧТО ЭТО СТОИТ** *(добавлено: `VID-02c`, 2026-09-12)*. Шаблон
`video@1` кладёт клип на весь кадр либо врезкой в любом из четырёх углов; **врезка держит
пропорцию файла** (`size` — доля ширины кадра, высота считается от видео), поэтому
горизонтальный клип в углу остаётся горизонтальным. Умеет: скруглить углы (`radius`),
разъехаться из угла в полный кадр и обратно (`move`), замереть на кадре (`holds`), наехать
(`zooms`), начать не с начала файла (`inPointFrame`), пойти по кругу, если файл короче сцены
(`loop`), и отдать свой звук в дорожку — ровно или ныряя под речь диктора (`audio`).

**Цена, которую надо знать заранее** (измерено на 60 кадрах 1080×1920): неподвижная врезка
добавляет к сегменту **651 мс**, скругление — ещё **+713 мс** (около +7 % стенки сегмента на
профиле `final`), **а переезд `move` — 13.8 с, то есть больше, чем сам рендер сегмента**.
Переезд — приём для одного-двух мест в ролике, а не для каждой сцены; если он нужен чаще,
сначала стоит закрыть долг №284 (дешёвая маска окна измерена, ×19.4, но пока не работает).

**Что видео НЕ умеет:** замедление (`speed`), кривую у переезда (он линеен), переезд вместе
с наездом и переезд при `fit: "contain"` — последние два отвергаются с объяснением, а не
складываются молча.

**ДЛИННЫЕ РОЛИКИ: ЧТО ЗНАТЬ ЗАРАНЕЕ** *(добавлено: `SP-VID-DUR`, 2026-09-12; числа
измерены на синтетическом проекте `work/long-10` длиной 599.7 с — 49 сцен, 17 991 кадр)*.

* **Время.** Черновик десятиминутного ролика собирается **около 20 минут** на холодную,
  **17 секунд** прогретым и **47 секунд** после правки одной сцены — промахивается ровно
  один сегмент, и это не зависит от длины ролика. Чистовой `final` на десяти минутах —
  **около двух часов** РАСЧЁТОМ (коэффициент 5.98 измерен Charter AC2), `verify ac4` —
  около четырёх, потому что он гоняет сборку дважды и оба раза без кэша.
* **Диск — вот что кончается первым.** Кадры сегментов живут в `build/tmp` до конца
  сборки и не удаляются: **12 ГБ на десять минут черновика**, около **48 ГБ** на `final`,
  около **96 ГБ** на двадцать минут `final`. Перед долгой сборкой проверьте `df -h`. Это
  долг №288 с правкой на десять строк; пока он открыт, место — часть подготовки.
* **Память НЕ кончается:** пик 279–292 МБ. Длинный РОЛИК не означает длинного СЕГМЕНТА —
  сегменты режутся по главам и сценам (на десяти минутах самый длинный 453 кадра).
* **Потолок длины — в профиле ПРОЕКТА, а не в движке:** `maxDurationFrames` в
  `profiles/compile.yaml`. Для Shorts он верен (1800 = 60 с); для длинного ролика его
  поднимают осознанно, в копии профиля.
* **Две ловушки при нарезке длинной прозы.** Якоря картинок нумеруются по встречаемости в
  ДОКУМЕНТЕ (`b:img-street-3` — третий `[img: street]` во всём файле, а не в сцене). И
  последняя сцена не должна кончаться маркером: запись, чьё окно упирается в конец
  документа, даёт пустой интервал и отказ компиляции — хвост в одну фразу это снимает.

**Что такое `--rights` простыми словами.** Это ответ на вопрос «чьё это и можно ли этим
пользоваться», одной строкой. Четыре значения покрывают почти всё:

* **`own`** — снял или нарисовал сам. Так помечено всё, что вы приносите с телефона;
* **`public-domain`** — срок охраны истёк либо это служебное произведение (снимки Библиотеки
  Конгресса в `examples/ai-test-1` — именно такие);
* **`cc-by-4.0`** — свободная лицензия, требующая назвать автора. Текст указания даётся
  флагом `--attribution "…"`, и без него `attributionRequired` останется `false`;
* **`all-rights-reserved`** — чужое, разрешения нет. **Команда это ПРИМЕТ и предупредит:**
  значение лицензии сегодня не судит никто (Policy Guard не написан, долг №210), ролик
  соберётся, и права останутся вашей заботой.

Список — подсказка, а не перечень: поле держит любую строку сознательно, потому что перечень
лицензий протух бы раньше первого ролика.

**Чего команда НЕ делает и почему.** Не переписывает занятый alias (это сменило бы картинку
во всех записях режиссуры, которые его называют, а проза не изменилась бы ни словом) и не
принимает шрифты и звук (долг №261). При любом отказе не записывается НИЧЕГО: ни байта в
сторе, ни строки в трёх файлах.

**Посмотреть, что в проекте уже есть:**

```bash
node packages/cli/dist/bin/vpe.js asset list --project examples/ai-test-1
```

Эта же выдача — **список alias'ов для ИИ-сценариста**: её вставляют в чат вместе с темой
(см. [`docs/ai-scenarist.md`](docs/ai-scenarist.md) §3).

### 1-тер. Вставить видео в ролик — три команды

**Видео в ролике ставит шаблон `video@1`** (`VID-02a`, 2026-09-11). Картинку кладёт не браузер,
а ffmpeg отдельной стадией между рендером и кодированием; браузер рисует поверх неё графику и
субтитры.

```bash
# 1. положить видео в проект — тем же `asset add`, вид определяется по БАЙТАМ
node packages/cli/dist/bin/vpe.js asset add work/in/demo.mp4 \
  --project work/asset-test --alias demo-video --rights own \
  --note "проба владельца — видео с телефона, 6.5 с"

# 2. дописать в `direction/NN-имя.yaml` запись (пресет + свой alias):
#      track: visual
#      z: 25                 ← ВЫШЕ всего непрозрачного в сцене, см. ниже
#      template: "video@1"
#      preset: "corner-tr-small"
#      params: { asset: "demo-video" }

# 3. собрать
node packages/cli/dist/bin/vpe.js build --project work/asset-test --profile draftHalf
```

В выводе сборки у сегмента с видео появляется своя строка — `видео: нижний слой 184×326 в
(330, 27), 2835 мс`; у сегментов без видео её нет вовсе, и байты у них ровно те же, что были
бы без этой задачи.

**Три вещи, которые надо знать до первой записи.**

* **`z` записи с видео обязан быть ВЫШЕ всего непрозрачного в сцене.** Видео лежит ПОД
  графикой, и шаблон пробивает сквозь слои НИЖЕ своего `z` прозрачное окно. Слой на ТОМ ЖЕ
  `z` окном не пробивается и видео закроет — это видно на первом же кадре.
* **Звук видео в ролик не попадает.** `audio` принимает единственное значение `off`; микшер
  по окнам речи придёт задачей `VID-02b`.
* **Видео кончилось раньше окна — держится последний кадр**, а не начинается заново.

Четыре пресета печатает `vpe spec export` (и коротким списком — `vpe template list`):
`fullscreen-cover`, `fullscreen-contain`, `corner-tr-small`, `hold-and-zoom`. Посмотреть, как
каждый выглядит, — `vpe template demo video@1 --profile draftHalf`.

### 1-кватер. Живой текст в кадре — одна запись

**`kineticType@1`** (`KT-01`, 2026-09-12) — слова, счётчики и формулы, появляющиеся **в такт
голосу**. Это ГРАФИКА (дорожка `visual`), а не субтитр: субтитр идёт под каждым словом ролика
и читается без звука, живой текст — одна мысль, вынесенная в кадр крупно.

```bash
# дописать в `direction/NN-имя.yaml`:
#      at:    { kind: anchor, anchor: "b:evict" }   ← БИТ, а не сцена (см. ниже)
#      until: { kind: anchor, anchor: "sc:road" }
#      track: visual
#      z: 30                 ← ВЫШЕ видео, если оно в сцене есть
#      template: "kineticType@1"
#      preset: "stack-caps-bold"
node packages/cli/dist/bin/vpe.js build --project work/ct-test-1 --profile draftHalf
```

**Времени в записи нет ни одного числа, и это главное свойство шаблона.** При
`source: "window"` (его берут четыре пресета из шести) слово появляется РОВНО на кадре, куда
алигнер поставил его начало в дубле. Автор задаёт ТОЛЬКО окно.

**Три вещи, которые надо знать до первой записи** — каждая найдена живым прогоном:

* **`z` обязан быть ВЫШЕ видео.** Под `video@1` (в канале `z: 25`) текст срезается окном видео
  и не появляется в кадре ВООБЩЕ, хотя запись исполнена и клип стоит в IR.
* **Накопление ставят на БИТ, а не на сцену.** `stack-caps-bold` на окне целой сцены накопит
  всю её речь — полсотни слов, — и блок вылезет за кадр: **кегль под длину фразы шаблон НЕ
  подбирает** (долг №293). Замена (`punch-word`) от длины окна не страдает.
* **Плашки у него нет вовсе** — она есть у субтитра; читаемость держат обводка и тень, и все
  шесть пресетов их уже несут.

Шесть пресетов печатает `vpe spec export`: `stack-caps-bold` (фраза словом за словом — приём
Баффета), `punch-word` (одно огромное слово — приём NVIDIA), `counter-money` (300 → 381),
`year-typewriter` (2008 по символу), `formula-accent` («2 + 2 = 4» с акцентом на ответе),
`caption-kinetic-clean` (нейтральный). Посмотреть все шесть подряд —
`vpe template demo kineticType@1 --profile draftHalf`.

### 1-quater. Поменять вид субтитров — ПРЕСЕТОМ, а не правкой движка

*(`CAPTION-01`, 2026-09-11.)* Вид полосы субтитров — шрифт, кегль, фон, цвета, обводка, тень,
положение — **больше не константы кода**. Меняется одной строкой в `direction/NN-имя.yaml`:

```yaml
  - recordId: "9f31b204"
    at: { kind: anchor, anchor: "sc:street" }
    until: { kind: anchor, anchor: "sc:street" }
    track: caption
    z: 30
    template: "captionEmphasis@1"
    preset: "clean-shorts"        # ← ЗДЕСЬ и меняется вид
```

Четыре пресета: **`bottom-warm`** — вид канала (тёплый акцент на непрозрачной чёрной плашке
внизу; им стоят все живые проекты), **`clean-shorts`** — без плашки, обводка, по центру,
крупно, **`translucent-bottom`** — полупрозрачная плашка внизу, **`big-center`** — самый
крупный по центру. Посмотреть все четыре подряд —
`./scripts/vpe-docker template demo captionEmphasis@1 --profile draftHalf`; кадры каждого лежат
в [`docs/impl/CAPTION-01/frames/`](docs/impl/CAPTION-01/frames/).

Нужного вида нет среди четырёх — пишутся `params` числами (тринадцать ручек, все печатает
`vpe spec export`); **ручка, которую вы не написали, берётся из умолчания канала**. Три вещи,
которые надо знать до первой правки:

* **запись ставится ПО ОДНОЙ НА СЦЕНУ**, и вид действует на весь СЕГМЕНТ: полоса в нём одна,
  две записи с разными пресетами в одном сегменте невыразимы — победит первая (долг №275);
* **сегмент, в котором такой записи нет вовсе, получает умолчание канала** — оно совпадает с
  `bottom-warm` поле в поле, и это стоит охранником;
* **без плашки ставьте обводку** (`bg: "none"` + `outline.widthPx` 3–5): белый текст на
  светлом кадре иначе пропадает. Под непрозрачной плашкой обводка не нужна.

Пятый пресет заводится копированием файла в `packages/templates-spec/src/templates/captionEmphasis@1/presets/`
— имя файла и есть имя пресета, `note` обязателен (он уходит в задание для ИИ).


Ожидаемый вывод — три признака сразу (те же, что в [`docs/gate-runbook.md`](docs/gate-runbook.md) §2):
`ГЕЙТ: PASS · профиль draftHalf · N = 3`; «различных framemd5: 1; различных sha256: 1»;

**Шаблон — это ПАПКА** (`TPL-01a`, 2026-09-09). Запрос гейта и запись живут в ней:
`packages/templates-spec/src/templates/<id>@<N>/{spec.ts, gates.json, gate-requests/}`, а

Забыть запуск нельзя молча — краснеет `tests/lints/template-registry-generated.test.ts`.
Пошаговый рецепт «как добавить следующий шаблон» — [`docs/gate-runbook.md`](docs/gate-runbook.md)
§4-ter.

**У папки есть ручки, сохранённые под именем, — ПРЕСЕТЫ** (`TPL-01b`, 2026-09-10). Посмотреть,
какие есть: `vpe spec export` — под схемой параметров каждого шаблона идёт список «имя · для
чего · числа» (короткий список имён печатает и `vpe template list`). Завести свой: положить
`packages/templates-spec/src/templates/<id>@<N>/presets/<имя>.json` вида `{"note": "для чего,
одной фразой", "params": {…}}` — имя файла и есть имя пресета (`^[a-z][a-z0-9-]*$`), `pnpm
build` не нужен. В режиссуре пишется `preset: "<имя>"` вместо `params`; свои `params` рядом
накладываются ПОВЕРХ по верхнему уровню ключей.

**И у папки есть ДЕМО — крошечный собираемый ролик** (`TPL-01c`, 2026-09-10). Решение

## Гигиена ИИ-сессий (краткая памятка)
- Прикладывай файлы, а не пересказывай их.
- Проси результат файлами, маленькими диффами.
- «Не уверен — скажи UNKNOWN» — повторяй это требование в каждом промпте.
- Заметил повторы/воду/противоречие Charter'у → стоп, новая сессия.
- Спорные места решаешь ТЫ. ИИ предлагает варианты с trade-offs,
  выбор фиксируется в ADR за твоей подписью.
- Раз в ~2 недели: сессия-аудит «прочти репо, найди дрейф от Charter
  и мёртвый код» (промпт REV в режиме аудита).
- Новый ADR обязан либо добавить строку в `docs/invariants.md` (правило → чем охраняется),
  либо явно записать `decided-not-to` с причиной. Инвариант без охранника — пожелание.
